# リガチャーの締結方式と接触形状（Phase 4-C.3、2026-08-18）

Phase 3 のリガチャーは**1 方式しかなかった** —— ビーク側のスリット＋ネジ 2 本。
[`ligature_profiles.py`](../../saxsketch/instruments/saxophone/components/ligature_profiles.py)
は逆締めを「Phase 3 では扱わない」と明記して先送りしてあった。
`plate_type`（`none`/`plain`/`rail`）は**2 つの軸を 1 つのつまみに畳んで**いて、
締結方式とリードへの当たり方を別々には選べなかった。

掃引は [`sweep_ligature.py`](sweep_ligature.py)。

## 1. 既定の「2点レール」はリードに 1 か所も当たっていなかった

4-C.2 でリードの背面が**カマボコ**（ケーンの円弧）になったのに、接触面は平面
`reed_face_y` に置かれたままだった。平らな面に対する締め代（＝締めて詰めるべき量）を
測ると:

| | 中央 x=0 | 旧レール位置 | 新しい 2 点の位置 | 全面プレートの端 |
|---|---|---|---|---|
| soprano | 0.15 | **0.83**（±4.36） | 1.12（±5.16） | **1.55**（±6.16） |
| alto | 0.15 | **0.92**（±4.56） | 1.24（±5.39） | **1.71**（±6.39） |
| tenor | 0.15 | **1.04**（±5.12） | 1.40（±6.04） | **1.88**（±7.04） |

`reed_clearance` 0.15 が設計上の締め代なので、**設計どおり当たっていたのは中央だけ**。
レールはその 5.5〜6.9 倍離れていて、剛体バンドが埋められる量ではない。全面プレートも
当たるのは冠の 1 本線だけだった。

→ 接触要素の頂点を `rp.cane_top` から起こす（`contact_top_y`）。締め代は全 x で
`reed_clearance` に揃う（実測の最大ずれ 3.6e-16 mm）。

## 2. 接触は別ソリッドではなく**内周断面の凸**

材料は「外周ロフト − 内周ロフト」なので、空洞のタブ床を上へ凸にすればそれが
そのまま接触要素になる。角柱を足す作りと比べて:

- **ソリッドが常に 1 個**。角柱だと逆締めのスリットが x=0 の要素を割った瞬間に
  宙に浮いた別ソリッドができる（`contact_count` が奇数だと必ず起きる）。
- ブーリアンが増えない。テーブルの 4.18° 傾斜にも自動で従う（断面ごとに引くので）。
- 断面図（仕様書 SVG）にも接触がそのまま出る。

要素の形は「床から立ち上がる裾 → サジッタ 0.25mm の円弧 → 裾」の 7 点。円弧の半径は
`cane_radius` と同じ式 (a²+s²)/(2s) で 2.1mm 級 —— リード背面の円弧（13.8〜15.2mm）
よりずっと小さいので、**接触は必ず 1 本の線**になる。点接触は z 方向にも同じ丸みを
かけた「テント」なので、当たるのは行の位置の**1 点**だけ（前後 2 列で総数 2n）。

床は頂点から `_CONTACT_RELIEF = 0.25` 逃がす。これはテンプレート 3 枚の `clearance`
と同じ値なので**既定の床の高さは 1 ビットも動かない**（`contact_type="none"` の
`inner_sections` は HEAD とビット一致）。

| | 山の高さ（中央→端） | タブの深さ |
|---|---|---|
| soprano | 0.25 → 1.65 | 3.00 |
| alto | 0.25 → 1.81 | 3.20 |
| tenor | 0.25 → 1.98 | 3.40 |

**点接触だけは床を 0.25mm 余分に逃がす**（z 方向の丸みぶん）。そのため
`contact_count = 1` では「床が減らす材料 > 点が足す材料」になり、体積が
`none` より小さくなる（alto で 4232.9 対 4279.7）。2 個以上なら順序どおり。

## 3. 締結方式 3 つ

- **`screw_beak`** … 現行。ビーク側にスリット、両脇に耳、X 方向にネジ穴。
- **`screw_reed`（逆締め）** … スリット・耳・穴をリード側へ。スリットは**必ず**
  タブ床を割る（床の半幅 6.70/6.95/7.65 に対しスリット 2.5/3.0/3.5）ので、
  **橋（圧力プレート）が構造部材として要る**。橋は -x 側の床へ 0.05mm 食い込ませて
  融合させ、+x 側とは 0.3mm 空ける片持ち。段差は x=0 ＝ スリットの中に置くので、
  切った後には見えない。`contact_type="none"` は `params_error` で弾く
  （橋が無いと接触面が割れたまま）。
- **`elastic`（ネジなし）** … スリットもネジ座も無い一連リング。締め代は
  **負のはめあい隙間**で表す（`clearance` の下限を −0.60 まで広げた。既定 0.25 は
  可動域の内側なので黙ったクランプは起きない）。伸びない材料では掴めないので
  `MATERIAL_LABELS` に TPU95A を足し、非弾性材料 × 弾性バンドは印刷強度カードが
  `bad` を出す（**形としては作れる**ので `params_error` にはしない —— 薄いバンドなら
  成立する余地があり、そこは設計者の判断）。

橋の厚みは `min_wall` そのもの。バンド厚に収まらない組は `params_error`:

| | バンド厚 | 必要（橋 1.6 ＋ 融合 0.05 ＋ 逃げ 0.3 ＋ 床 0.2） | 残る床 |
|---|---|---|---|
| soprano | 2.2 | 2.15 | **0.25** |
| alto | 2.4 | 2.15 | 0.45 |
| tenor | 2.6 | 2.15 | 0.65 |

ソプラノは余裕 0.05mm。`min_wall` を 0.1 上げるだけで弾かれるが、**黙って落とさず
理由を出す**のが 4-C.3 の方針そのもの。

## 4. 掃引が見つけたもの: 棚の有無で頂点数が変わっていた

`_wrap_section` はテーブル面の弦がタブより広いとき「棚」の 2 点を足す。弦の幅は z で
変わるので、**帯の中で棚が現れたり消えたりすると断面ごとの頂点数が変わる**
（弾性バンドの負の隙間 × 厚い帯で実際に起きた: 83 と 85 が混在）。ルールドロフトは
頂点数が一致していることが前提なので、これは面がねじれる。棚が無い側は円弧の刻みを
2 つ増やして帳尻を合わせる（円は同じなので位相がずれるだけ）。

**これは 4-C.3 が作った穴ではなく、前からあったもの**。ligature に掃引が無かったので
誰も踏んでいなかっただけで、`clearance` の下限を負へ広げたことで手が届く所へ来た。
pytest 側にも「1 本のロフトの中で頂点数が一定」を足してある。

## 5. 記録値（既定テンプレート、旧「2点レール」→ 新「線 × 2」）

| | 前 | 後 | 差 |
|---|---|---|---|
| soprano | 2758.4 | 2803.9 mm³ | **+45.5（+1.65%）** |
| alto | 4295.7 | 4359.8 mm³ | **+64.1（+1.49%）** |
| tenor | 5609.4 | 5694.2 mm³ | **+84.8（+1.51%）** |

旧レールは「幅 2.0 × 隙間 0.25 × 帯幅」の角柱 2 本 ＝ alto でちょうど 16.0 mm³
（HEAD の既定 4295.7 − 接触なし 4279.7 = 16.0 で一致する）。新しい線接触は
80.1 mm³ ＝ **5.0 倍**。増えたぶんは全部「リードに届くまでの高さ」で、
山の高さが端で 1.81mm あることの裏返し。

**マウスピース・リード・ネック・管体は一切動かない。** `verify_report.md` も 0 行
（`verify_base.py` はリガチャー部品を通らない）。音響も無関係。

## 6. 旧 `plate_type` の .wproj は変換して報告する

`ParamSet.apply` は**未知のキーを黙って捨てる**ので、フックが無いと「全面プレート」に
してあったプロジェクトが黙って線接触に変わる。`Component.migrate_params`（既定は恒等）
を足し、`open_project` で `apply` の**直前**に通して、変換した事実を 1 行返す
（`/api/project` の `notices` → フロントの警告トースト）。

| 旧 | 新 |
|---|---|
| `none` | `contact_type="none"` |
| `plain` | `contact_type="face"`（背面に密着） |
| `rail` | `contact_type="line"` × 2 |

## 7. 未実測 / 範囲外

- **リードの踵がタブより 0.10mm 広い**（3 サイズ共通）。タブはマウスピースの
  `reed_width`、踵はリードの `heel_width` から来る既存の作りで、どちらを正とするかを
  決める話。**適合カードに数字を出すだけ**にした。
- **TPU の推奨最小バンド厚 1.2mm は出典未記録の仮定。** 弾性バンドは締結荷重ではなく
  伸びで掴むので、他の材料と同じ根拠では決められない。決着させるのは実際に印刷して
  伸ばすこと。
- **弾性バンドの張力は計算しない。** 材料が伸びるかの判定だけ（材料定数が無い）。
- 圧力プレートを**別部品**として出すこと（実物の逆締めは別体プレートが多い）。
  いまは一体成形のまま、橋渡しで作る。
- リガチャー座の位置決め機構（`seat_offset` のまま）。

# 帯の位置決めから黙ったクランプを外す（Phase 4-C.3b、2026-08-18）

ユーザー報告:「アルトで試したらリガチャーのバンド幅が **21mm 以上だと描画が
更新されない**」。

## 1. 原因はフロントではなく `seat_range` の黙ったクランプ

`Viewer3D` は `modelVersion` ごとに `?v=` 付きで `/api/model.stl` を取り直して
いるので、**取得はしている**。返ってくるバイト列が同じだから同じ絵が出る。
`inner_sections` を 8.0〜28.0mm の 0.5 刻みでハッシュすると、**素のアルトは
16.5mm 以降が全部同じ**:

```
bw= 16.0 dbea21ad3d  <-- 変化
bw= 16.5 6e017e5522  <-- 変化
bw= 17.0 6e017e5522        （以降 28.0 まで全部同じ）
```

凍る閾値は**参照マウスピースの `heel_z × 0.23`**:

| | heel_z | 座の長さ ＝ 凍る幅 |
|---|---|---|
| soprano | 57.10 | 13.13 |
| alto | 70.30 | **16.17** |
| tenor | 79.02 | 18.17 |

報告の 21mm は heel_z ≈ 90mm のときの値（`shank_length` を 0 付近まで引くと
座が 20.68 になり、0.5 刻みのスライダは 21.0 で凍る）。**閾値が参照マウスピース
次第で動くだけで、原因は 1 か所。**

## 2. `seat_offset` はもっと死んでいた

同じクランプが帯を後ろへ引き戻すので、可動域 0.0〜15.0 のうち**生きているのは
0.0〜0.17mm**。テンプレート既定 3.0 / 4.0 / 4.5 は 3 サイズとも飽和していて、
**帯は常に最大径にぴったり後端を合わせていた**。

| オフセット | 0.0 | 2.0 | 4.0 | 8.0 | 15.0 |
|---|---|---|---|---|---|
| alto の帯 | 54.13〜70.13 | 54.30〜70.30 | 54.30〜70.30 | 54.30〜70.30 | 54.30〜70.30 |

## 3. 丸め先が物理ではなかった

`_SEAT_LENGTH_RATIO = 0.23` は「実測のリガチャー帯 ≈18mm / heel 79mm」から
作った公称値（テナー 1 本由来）で、壁ではない。**「典型的なリガチャーの幅」で座を
定義しておいて、その座より広いリガチャーを禁じていた** —— 定義が循環していた。

本当の壁は**後端だけ**。座の後端は胴の最大径（`heel_z`）で、そこから先は胴が
細くなるので頂点を跨いだ帯は掴めない。

```python
z1 = min(seat0 + lig_p["seat_offset"] + lig_p["band_width"], seat1)
return z1 - lig_p["band_width"], z1        # 前へは伸ばす。丸めない
```

- **既定 3 サイズは 15 桁までビット一致**（前クランプが効いていない側の分岐に
  入っていたため）。体積・BOM・断面 SVG・`verify_report.md` すべて不変。
- 幅 8〜28mm の 41 通りが**毎回別の形**になる。
- 上限 28mm でも 3 サイズとも成立する（実測）:

| | bw=28 の前端 | 内周半径 | タブ上限 / 要求 | 窓の後端 |
|---|---|---|---|---|
| soprano | 29.10 | 11.33 | 11.13 / 6.70 | 27.83 |
| alto | 42.30 | 13.46 | 13.26 / 6.95 | 35.75 |
| tenor | 51.02 | 14.39 | 14.19 / 7.65 | 41.90 |

  窓に掛かるのはスライダ上限の外（soprano で 29.3mm 必要）。それでも
  適合カードには判定を置いた —— マウスピースを短くすれば届く。

## 4. 消せないクランプは報告する

後端の壁は物理なので `seat_offset` の飽和は残る。**黙って飲まない**ように
`effective_seat_offset` を足し、適合カードに「要求 4.0 / 実効 0.17」の行と、
助言文（「帯の後端が最大径 z=70.3 で止まるため実効 0.17mm。前へ動かすには幅を
広げてください」）を出す。既定値は 1 つも動かさない。

適合カードの警告「バンド幅がリガチャー座に収まりません」は意味を失ったので、
**実際の破綻**（前端が窓に掛かる）へ張り替えた。座からのはみ出しは助言に
事実として出すだけで、警告にはしない。

## 5. 掃引が既定幅しか回していなかった

`sweep_ligature.py` は締結 × 当たり方 × 数を総当たりしていたが、**帯幅は既定
1 通り**だった。だから「幅を上げても形が変わらない」に届いていなかった。
幅 8/28（＋28×6線）とオフセット 0/15 の 5 ケースを足して 3 サイズ × 34 通り、
**ALL_PASS**（弾いた 3 件は逆締め×接触なし）。
