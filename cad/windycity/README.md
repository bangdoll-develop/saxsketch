# 実物準拠マウスピース ベース形状（SaxSketch 新ベース）

SaxSketch のマウスピース ベース形状を、実在のマウスピース
**WindyCity Tenor .100" Long Shank**（`WindyCity-Tenor-72-100-LS.3mf`）の実測から
起こし直した。ここにあるのは「実測 → 構成式化 → 検証」の一式。

形状定義そのものは `saxsketch/instruments/saxophone/components/profiles.py` にある
（このフォルダは実測・検証・目視確認のための道具）。

## 実測で判明した構造（旧モデルとの違い）

| | 旧 SaxSketch | 実物 |
|---|---|---|
| テーブル面 | ボア軸に平行な定数平面 `-0.40·body_dia` | **ボア軸に対し 4.18° 傾いた平面**（平面度 rms 0.035mm） |
| 外形断面 | 真円回転体（プロファイルが別物） | 真円回転体だが**プロファイルが実測と一致**。見かけの卵形はテーブルカットの結果 |
| ビーク | 3点 smoothstep 曲線 | **18.0° の直線ランプ**＋**半径 25mm の円筒面**、0.43–0.53·踵 で胴へブレンド |
| バッフル天井 | リード面基準の上昇曲線 | **ボア軸に平行な平面**が σ=0.36 まで続き、傾き一定の直線ランプ→S字でボア天井へ |
| チェンバー | 膨らみ＋スロート狭窄が既定 | **どちらも無い**。断面積が単調にボアへ開く（既定比 1.0） |
| ウィンドウ | スロット（窓）を明示的に彫る | 空洞は**1本の滑らかな管**。リード面がそれを切った所が窓 |
| 空洞の断面 | 上下同じスーパー楕円指数 | **天井は横方向にアーチ**（サグ ≈0.31mm、z によらずほぼ一定）。これがティップレールを先端曲線に沿わせている |
| ティップレール | ロフト前端の平面（軸に直角な直線） | **先端輪郭の等距離オフセット**（弧に沿って 0.90mm 一定） |
| ティップ前縁 | `tip_rail_thickness` ぶんの角（1.25mm の壁） | **リード面側から面取り**されていて、前面は 0.25mm・面取り長 0.13mm |

### 内部空洞の作り直し（Stage C-1）

FreeCAD で内部を透過すると、実物には無い**棚・縦壁・段差**が見えていた。原因は
実測の読み違いではなく、**実測から起こした法則を継ぐ所で傾きが飛んでいた**こと。

| 症状 | 原因 | 傾きの飛び |
|---|---|---|
| 内部の水平な棚 | 断面の「直立壁＋フレア」の折れ線が空洞の全長を走る | 0 → 有限 |
| 内部の縦壁（YZ x=7 の V 字スパイク） | スロット幅の細りと閉口処理が衝突し z=41 でくびれ z=44.7 で全幅へ戻る | **−0.94 → +2.09** |
| 床の段差 | 窓を閉じる床のランプ | **−0.07 → +0.71** |
| バッフルを横切る稜線 | 「直線ランプ→指数ブレンド」の継ぎ目 | **0.80 → 2.40** |
| ビークが胴へ消える所の折れ | ブレンドが終端で胴の傾きに合っていない | G1 不連続 |

そこで**スロットを作るのをやめ**、実物と同じ作られ方 — チェンバーの空洞がリード面を
突き抜けた所が窓 — に合わせた。空洞は3本の曲線だけで決まる:

- `cavity_half_width(p, z)` — 半幅 W(z)
- `cavity_roof_y(p, z)` — 天井 C(z)（バッフル）
- `cavity_floor_y(p, z)` — 床 F(z)

**F(z) が cut_top_y(z) を横切る所が窓の終端**になり、ランプも段差も要らない。
サイドレール幅は入力ではなく「リード面での弦の半分 − W(z)」という出力になる。
3本とも実測点列の PCHIP（構成上 C1）で、頭打ちも `min()` ではなく `_soft_min()`
（C∞ かつ常に min 以下）にしてあるので、全長にわたって折れが無い。

実測して初めて分かったのは、**管の径がほぼ一定**（0.865〜1.00 × ボア半径、全変化
1.15mm）だということ。旧実装が「窓が後方で細くなる」と見て幅を直接絞っていたのは
開口の話で、管そのものは絞られていない。開口が後方で狭くなるのは**床が上がるから**。

### ティップレールを先端曲線に沿わせる（Stage C-1b）

C-1 の後で FreeCAD の拡大確認をすると、**ティップレールが先端の曲線に沿っていない**
（コーナーでレールが消える）。実物と突き合わせて測ったレール幅
（窓の縁から先端輪郭への**垂直距離**）:

| | クラウン | z=2 | **コーナー z=3.5** |
|---|---|---|---|
| 実物 | 0.90 | 0.94 | 0.72 |
| C-1 のモデル | 1.20 | 0.39 | **0.02–0.09** |

実物は先端輪郭の等距離オフセット（弧の平均 0.904mm・ばらつき 0.25mm）。原因は3つで、
どれも実測で切り分けた:

| # | 原因 | 実測 |
|---|---|---|
| 1 | **ロフト前端が z 一定の平面**（蓋がリード面より上に出ていた）。窓の前縁が軸に直角な直線になる | モデルの前縁は x=±5.0 まで z=1.20 で一定。実物は 0.84→2.68 の弧 |
| 2 | **天井が横方向に平ら**。実物の天井は絶対量 ≈0.31mm の横アーチ（x=7 で、z=3〜16 を通してほぼ一定） | サグ 0.33/0.32/0.31/0.30 @ z=3/5/8/14。`nx=6` の断面は中央が平板で、h が 0.7mm しかないティップでは落差 0.07mm |
| 3 | **管がティップで太すぎた**。`_CAVITY_W` の頭（σ=0.024 で 0.980）は管ではなく胴の内側を拾っていた | z 一定で切ると実物の空洞は z=1.5 で \|x\|≲4.3、z=2.0 で ≲5.0、z=3.0 で ≲7.0 までしか無い |

直した内容:

- **断面の上半分だけ x 指数を分ける**（`_super_pts` の `nx_top`、`_TOP_ARCH`）。
  ny>1 なら上下どちらの半分も X=±1 で接線が垂直なので、指数を変えても赤道で
  **G1 のまま**繋がる。サグを断面高さ h に比例させず、実測どおり絶対量で持てる。
- **天井のティップ高さを `tip_rail_width` から決める**（`tip_roof_y` = `cut_top_y(tip_rail_width)`）。
  天井がリード面を突き抜ける z がそのままレール幅なので（先端は z=0 に立つ）、
  `table_plane_y` が「ティップが z=0 に立つ」で決まっているのと同じ立て方になる。
  `baffle_height` はバッフル区間を担当し、`_TIP_GAP_FREE_RATIO` を再校正して
  実測のテナーでは両者が一致＝天井は実測どおり一枚の平面のまま。
- **ロフト前端を窓の前縁より 0.45mm 手前へ**（`window_start_z` は「開始平面」へ降格、
  窓の前縁は `window_front_z`、実効値は `window_open_z`）。蓋がリード面より下に
  沈むので、前縁は「天井とリード面の交線」＝滑らかな弧だけで決まる。
- 天井を押し下げていた2つの拘束を実物に合わせた。外殻の肉厚はティップだけ
  `tip_rail_thickness`（実測 1.25mm、min_wall 1.8mm より薄いのが本来）を使い、
  頭打ちの `_soft_min` はレール幅に直接効くので幅 k を 0.35→0.12 に絞った。
- 床の下限拘束（`-(ro − min_wall)`）は**窓の区間では外す**。窓では胴の底が既に
  無いのにこれが効いて、z=0.85 で床がリード面より上へ押し上げられていた。
- 胴の回転体はノーズを 0.15〜0.3mm 刻みに詰めた。母線が区分直線なので、
  1.4mm 刻みだと z=2 で半径が **0.29mm 痩せ**、先端輪郭がそのぶん内側へ寄って
  レールが細く見えていた。

### ティップ前縁の面取り（Stage C-1c）

C-1b の後、FreeCAD でティップの両端に角が見えた。突き合わせると**その稜線自体は
実物にもある本物の線**（ビーク面と丸胴が出会う「肩」。z=0 の x=±3.1 から始まり
z=5.2 で x=±10.0 まで後退する）で、外形は z≥0.6 で実物と 0.03–0.15mm しか違わない。
本当の欠けは別のところにあった —— **実物のティップ前縁はリード面側から
面取りされているのに、モデルは角のまま**。

| x=0 での実測 | 実物 | C-1b のモデル |
|---|---|---|
| z=0 の前面（先端の断面） | 1.94 × **0.25** mm | 6.33 × **1.25** mm |
| リード面が設計平面へ達する z | 0.13 | **0.00** |

実物のリード面側は先端輪郭から**勾配 3.4（Δy/Δz）の一定傾斜**で z 方向 0.13–0.15mm
かけて設計平面へ降りる。x=0/1/2/3 のどこでも勾配は 3.1–3.6 で、開始 z だけが
先端輪郭に沿って動く（x=0 で 0.01、x=2 で 0.09、x=3 で 0.25）＝**先端の弧に沿った
面取り**。表面偏差としては z<0.3 で平均 0.17 / 最大 0.36mm と小さいが、
1.25mm の角ばった壁が立つぶん先端の見た目と手触りに直結する。

直した内容:

- **胴は回転体なので、z≈0 で半径を細らせるだけで面取りが弧へ自動で沿う**
  （リード面カットは固定平面なので、(x,z) の最下面は `max(cut_top, −√(r²−x²))`）。
  `outer_radius` = `outer_radius_nominal` − `tip_chamfer`·ramp。テンプレートの
  `tip_chamfer` が削り代、面取り角は仕上げの定数なのでサイズによらず
  `_TIP_CHAMFER_SLOPE` で長さを決める。
- **基準は公称半径から取る**。`table_plane_y` が `outer_radius(0)` を使ったままだと
  テーブルが 0.7mm 下がってティップ開きごと狂うので、アンカーは
  `outer_radius_nominal` に付け替えた。
- 半径を細らせるだけだと前面が 0.69mm 残る（実測 0.25mm）ので、**ビーク稜線も同じ
  区間だけ下げる**（`_TIP_FACE_DROP_RATIO`）。
- 回転体・ビーク切除の**ステーション列を `profiles.body_stations` /
  `profiles.beak_cut_stations` に一本化**した。既定の刻みは胴 0.25mm・ビーク 1.9mm で、
  長さ 0.17mm の面取りは丸ごと飛ぶ。特にビークはルールドロフトなので、断面を
  入れないと稜線の下げが**線形に均されて z=1.9 まで伸び、z=0.6 で 0.2mm** 効いていた。
  ティップ側では稜線も横断面半径も z の一次式なので、折れ目の2点
  （z=0 と z=面取り長）だけで厳密に一致する。

`tip_rail_thickness` は動かしていない。これは肉厚であると同時に
`beak_apex_y(0) = cut_top_y(0) + tip_rail_thickness` という構成条件でもあり、
`shell_limit(p,0)["top"]` がちょうどリード面に接する＝レールが成立する根拠になっている。

### ビーク切除の面一致（同時に直した潜在バグ）

ブレンド終端では `beak_apex_y == outer_radius` かつ横断面の曲率半径も胴と一致し、
切除ソリッドの下面が**胴の外周面と完全に一致**していた。面と面の一致は OCCT の
ブーリアンが最も苦手とする条件で、実際に**カットが黙って失敗**（胴がそのまま返る）
することがあった。ステーション数を 44→60 に変えるだけで成否が入れ替わる程度に
不安定で、3サイズとも `is_valid == False` だったのもこれが原因。

終端付近だけ切除ソリッドを胴の外へ逃がして、常に横断で交わるようにした。
削り残しは最大 0.45mm・z 幅 1mm ほど（許容内）。**3サイズとも `is_valid == True`**
になった。

座標系をボア軸に正すと **ティップ開き実測 2.65mm ≒ 刻印 .100"(2.54mm)**。
旧軸（PCA のまま・約1°ずれ）では 3.1mm と過大に出ていた。これが「軸の取り方が
すべての実測を汚す」ことの証拠になっている。

## 新しい構成式の要点

- テーブル平面の位置は魔法定数ではなく **「ティップが z=0 に立つ」** で決まる
  （`-r(0) = table(0) + tip_opening`）。実測と 0.01mm で一致する。
- 踵（最大径＝テーブルが消える位置）は `heel_z = (全長 − シャンク長)/(1+肩比)`。
  テナーで 79.0mm となり、代表値のリード全長 78mm と 1.0mm 差に収まる。
  **これを設計則として使ってはいけない**（Stage G）。テナーのリードは未実測の
  代表値で、実測どうしで比べられるソプラノでは符号が反転する（踵が座の後端より
  2.0〜4.9mm 後ろへ出る）。照合はこの等値では判定しない。
- ビークの傾きは `beak_height`（バイトポイントでのテーブル面からの高さ）と
  ティップ端の頂点から一意に解ける。実測 17.99°（実物 18.0°）。
- 空洞の3法則は σ = z / `bore_start_z` で正規化する。3本とも「z=zb でボア円になる」
  という共通の終端条件を持つので、遷移区間を別式で繋ぐ必要が無い
  （旧実装の smoothstep 遷移がまさにその継ぎ目だった）。床だけは 2 つの端条件へ
  合わせる必要がある（`window_end_z` で D=0、zb で F=−ボア半径）。
  **合わせ方は σ の写像であって振幅ではない。**

  > **【2026-09-05 修正】** ここには長らく「床だけは**アフィン変換で**2つの
  > 端条件へ合わせる」と書いてあった。そのアフィンの係数は
  > `a = target/(D(1) − D(s_we))`（s_we = `window_end_z`/`bore_start_z`）で、
  > **s_we → 1 で発散する**。実測テーブル `_CAVITY_D` は σ=0.838 で 0 を横切る
  > ので、s_we がそこに載っている間だけ a≈1 になる —— そして **3 サイズとも
  > たまたま載っていた**（soprano 0.8408 / tenor 0.8380 / 旧 alto 0.8382）。
  > つまり**「3 サイズで揃う」という観察に幾何コードが荷重を掛けていた**。
  > アルトへ PHROX の窓の実測を入れて s_we が 0.9078 へ動いたとたん a=3.48 に
  > なり、床が丸ごと 3.5 倍深くなって**新既定のティップが壊れた**（先端の空洞
  > 高さ 0.60 → 4.44mm。利用者が 3D ビューで発見）。いまは
  > 「M: 0→0, s_we→0.838, 1→1 の単調写像」＋「尾側だけ端条件へ寄せる滑らかな
  > 重み」で合わせる。先端は σ=0 → M(0)=0 なので **`window_length` に依らない**。
  > 詳細は `docs/print-inspection.md` §11.11。
- ティップレール幅も同じ立て方で決まる。先端は z=0 に立つので、**天井がリード面を
  突き抜ける z がそのままレール幅**。`tip_rail_width` を与えれば天井の高さが決まる
  （`tip_roof_y = cut_top_y(tip_rail_width)`）。`baffle_height` はバッフル区間の
  天井を担当し、`_TIP_GAP_FREE_RATIO` は実測のテナーで両者が一致するよう校正してある
  ので、既定値ではランプ量ゼロ＝実測どおり一枚の平面。片方だけ動かしたときだけ
  σ≲0.1 で C1 のまま繋ぐ。

## 検証結果（`verify_report.md`）

全項目合格。主な数値:

| 項目 | モデル | 実物 |
|---|---|---|
| 全長 / 幅 / 高さ | 107.50 / 30.74 / 29.34 | 107.47 / 30.75 / 29.16 |
| テーブル傾斜 | −4.26° | −4.18° |
| フェイシング面の持ち上がり | 実物との差 平均 0.024mm / 最大 0.047mm | — |
| **ティップレール幅**（弧の平均） | **0.891mm**（ばらつき 0.23mm） | 0.904mm（0.25mm） |
| **先端前面の高さ**（x≈0） | **0.24mm** | 0.30mm |
| **ウィンドウ幅**（z=6–38） | 実物との差 平均 **0.17mm** / 最大 0.29mm | — |
| ウィンドウ開口 z 範囲 | 5.1–41.6 | 5.1–41.6 |
| 材料体積 | 28.83 cc | 28.93 cc |
| 気柱体積 | 18.69 cc | 18.59 cc |
| 表面偏差（モデル→実物） | 平均 **0.22mm** / p95 0.52mm / 最大 1.64mm | — |

tenor / alto / soprano の3サイズとも**単一ソリッド・`is_valid=True`**で生成でき、
`simulate()` も通る。`build()` は 6.9s（C-1 は 5.9s）。ティップの断面と胴の母線を
詰めたぶん増えたので、断面の頂点数を 96→72 に落として戻した（ボア円での弦誤差
0.008mm、メッシュ許容 0.02mm より小さいので形状には効かない）。

ウィンドウ幅の「平均差 0.17mm」は C-1 の 0.08mm より大きく見えるが、これは測り方を
細かくしたため。`window_outline` の x 刻みが 0.2mm だと縁がグリッドをまたぐたびに
±0.2mm 量子化されて系統差に見えるので、0.05mm 刻みへ変えた。縁を直接測ると
モデルと実物の差は**片側 0.06mm**（z=6–38 の平均）。

レポートには**断面法則の連続性**（隣接区間での傾きのジャンプ）も出る。合否は
課していないが、旧実装で d(半幅)/dz が z=41 で 3.03 飛んでいた種類の不連続は
消えている。いま最大が出るのは z≈1.1 の 3.2 で、**ティップで管が一気に開く所**
（レールが先端を一周するぶん管が内側へ入るので、z=1→4 で半幅が 3.5→8.1mm と
変化する）。これは実物にもある形で、継ぎ目ではない。

### 残差として分かっていること

- 窓の直後（z=42〜45）でモデルの断面積が実物より最大 20% 大きい。窓区間の断面を
  「側壁の立った角丸長方形」として持っているのに対し、実物はその時点で既にほぼ
  楕円になっているため（形状係数の差。z=45 以降は 3% 以内、気柱体積の差は 1%）。
  実物の断面は左右対称ではあるが上下非対称（上が平ら・下が丸い卵形）で、
  スーパー楕円1族では表しきれていない。
- ソプラノは Stage A のスケーリング由来で、テーブルカットがリード踵より手前で
  消える（`test_table_reaches_reed_heel`）・ビークが 0.4L より手前で胴に溶ける
  （`test_beak_taper_spans_body`）。テンプレートの比率の問題で、今回の範囲外。
- **先端輪郭がモデルの方が 0.14〜0.28mm 内側**（z=1.2〜4）。ティップレールは
  「先端輪郭 − 窓の縁」なので、この差がそのままコーナーのレール幅の差になる
  （z=3.5 でモデル 0.57 vs 実物 0.72）。窓の縁自体は 0.02〜0.16mm しか違わないので、
  **空洞ではなく外形（ノーズの半径とフェイシング面の高さ）の残差**。
  実物の方がノーズが 0.1mm ほど太く、リード面が 0.15mm ほど高い。ここを追うと
  `_BODY_PROFILE` と `tip_opening` に触ることになり検証済みの数値が全面的に動くので、
  今回は空洞側で辻褄を合わせる（＝外形の誤差を空洞で相殺する）ことはしなかった。
- `alto` / `soprano` の `baffle_height` を 2.6 → 2.34 / 1.89 に直した。テナーと同じ
  2.6 のままだと、そのボア径では天井がリード面より下に来て**窓が z=3.4 まで開かない**
  （C-1 でも同じで、症状が見えていなかっただけ）。各サイズで
  `baffle_plateau_y == tip_roof_y` になる値にした。

## CAD 表現のプリミティブ化（Stage C-2）

`build()` の形状は全面がルールドロフトの微小パッチで、tenor で 2547 面・微小エッジ
5000本超あった。STEP を FreeCAD で開いても外周面が1クリックで選べず、外周エッジへの
フィレットも通らない ——`docs/manual-edit-workflow.md` の L1（FreeCAD でソリッド編集）が
事実上使えない状態だった。

そこで**法則（`profiles.py`）は一切変えずに、面の張り方だけ**替えた版を足した。

| 部位 | 実測が示す素性 | 置き換え先 | 実際の面 |
|---|---|---|---|
| 胴 | 真円の回転体 | C1 の折れ目で切ったスプライン母線の回転体 | REVOLUTION 3 + CYLINDER 1 |
| ビーク直線ランプ | 18° 直線＋R25 円弧 | 円弧の斜め押出 | EXTRUSION 4 |
| ビークのブレンド | 曲率半径が z で変わる | 円弧断面のルールドロフト | BSPLINE |
| テーブル | 傾いた平面 | 平面 | PLANE |
| フェイシング | テーブルに接する円弧 | スプライン（下記） | BSPLINE 1 |
| 内部空洞 | 自由曲面 | 周期スプライン断面 + `ruled=True` | BSPLINE 44 |
| ボア | 円筒 | 空洞ロフトの延長（下記） | BSPLINE |

結果は **60 面 / 微小エッジ 0 本 / 単一ソリッド / 水密**。STEP 往復も通る。

### 使い分け（`build()` と `build_cad()`）

プリミティブ表現は**ブーリアンが 4 倍以上遅い**（4.6s → 20s）。対話中は
パラメータを動かすたびに `build()` が走るので、こちらは多角形のまま据え置き、
プリミティブ版は **STEP 出力のときだけ**組む（`Component.build_cad`）。
プレビュー・シミュレーション・STL・入稿パッケージは無劣化。
`build_cad` はブーリアンが落ちたら黙って `build()` へ落とすので、出力は失われない。

### 試作で分かった3つの罠

1. **母線を1本のスプラインで通すと C1 の折れ目でうねる。** ティップ面取りの端で
   0.58mm オーバーシュートし、胴の体積が 1.3% 痩せた。刻みを 0.05mm まで詰めても
   減らない（標本化ではなく折れ目の問題）。折れ目は3箇所 —— 面取りの端・踵
   （胴→肩プロファイル）・シャンク開始。区間に分ければ 0.002mm に落ちる。
   分けたおかげで面取りが独立した1面になり、FreeCAD で選べるという副産物もついた。
2. **空洞ロフトを `ruled=False`（滑らか補間）にすると形が変わる。** 断面間で
   オーバーシュートして**気柱が 2〜3% 増える**（`cavity_volume_cc` の台形積分は
   ルールド表現なので解析値とも食い違う）。さらにロフト末端がボア円筒と円周まるごとで
   接して交わり、1回のカットに **92 秒**かかって 0.5mm² 未満のスリバー面を 29 枚吐いた。
   `ruled=True` なら形は多角形版と同一のまま面数だけ落ちる。
3. **ボアを別ソリッドの円筒にすると接線接触が残る。** 空洞の最終断面がちょうど
   ボア円なので同じ問題が出る（スリバー 35 枚）。同じ断面をもう一枚後ろに置いて
   **ロフトをそのまま延長**すれば、区間は厳密な円筒のままでブーリアンが1回減る。

### フェイシングを円筒面にしなかった理由

`facing_rise` 単体は真円だが、テーブルが 4.18° 傾いているぶん `cut_top_y` は
Y 方向にせん断されていて、厳密には楕円弧になる。円弧で最小二乗フィットすると
**0.0024mm** 残る。リードが密着する面なので近似しない（スプラインなら 1 面のまま厳密）。

### 精度は上がる（多角形版の弦誤差が消えるため）

母線を法則と直接比べると、多角形は rms 0.015 / 最大 **−0.127mm**（弦が内側を通るので
常に痩せる側）、スプラインは rms 0.0002 / 最大 **−0.002mm**。材料体積はそのぶん
+0.1% 増える。ティップレール幅の平均は 0.891 → **0.980mm** に動いた（実物 0.904）。
つまり **C-1b の校正はノーズの弦誤差を一部吸収していた** —— 弦誤差が消えたことで
今度は逆に 0.08mm 広い側へ出た。どちらも合格ライン内なので追い込みはしていない。

### フィレット（`check_step_cad.py`）

外周エッジへ掛けるフィレットは**半径 0.2mm 以下**にすること。C-1c 以降ティップの
前面は 0.25mm しかないので 0.5mm では確実に落ちる。

長さ 2mm 超の 83 本を1本ずつ試した実測は **23 本成功**。内訳は同スクリプトが面の
種類の組ごとに出す。重要なのは**胴 + フェイシング/ビーク面が 7/7 で通る**こと ——
外周の角は取れる。落ちるのは (a) 内部空洞どうしの稜線（43/47。元々編集禁止で、
C-1b で断面の上下に別の指数を入れたぶん赤道は接線連続でも曲率が不連続）、
(b) 胴の母線を区切った継ぎ目とビーク面が胴へ接する所（接線連続なので角が無く、
掛ける意味も無い）。詳細な表は `docs/manual-edit-workflow.md`。

### 掃引（`sweep_cad.py`）

面が接する条件は OCCT のブーリアンが最も苦手なので、3サイズ × 27 ケース
（チェンバー4形状・バッフル4種・フェイシング2種・主要8パラメータの min/max）を
振って確かめた。**81 ケースすべて単一ソリッド・`is_valid`**、フォールバック 0 件。

### 可動域の掃引（`sweep_limits.py`）

`sweep_cad.py` が「帯の中は通る」を確かめるのに対し、こちらは**帯の外に何が
あるか**を測る（`ParamSpec.hard_min` / `hard_max` の根拠）。帯の端から 1 段ずつ
外へ歩き、`params_error` → ステーション → OCCT ビルドの 3 段で判定する。

**「通った」と「効いた」を分けているのが要**。各点で形の指紋を取り、動いて
いなければ「壁が無い」ではなく「効いていない」と言う —— これが無いと死に帯を
壁の不在と読み違える。実際 `baffle_height` の 5.0 より上と、`window_length` の
44 より上（soprano / alto）は**壁ではなく死に帯**だと分かった。

Phase A で測った 4 本の結果は `docs/param-limits.md`。同じ壁の裏から退化が
2 つ出たが、見つけ方は別々 ——`_floor_limit` の節点衝突は**壁の位置を手で
測っていて**（掃引器を書く前）、`_chamber_weight` のほうは掃引中に
`_pchip_table` の新しいガードが名指しで捕まえた。

**Phase B-0 で、掃引器そのものの目が盲だと分かった。** 初版の指紋は空洞の
高さと z しか見ていない。だから**幅でしか効かない** `side_rail_width` /
`throat_ratio` / `chamber_ratio` と、**外形でしか効かない** `shank_dia` /
`shoulder_fullness` / `tip_chamfer` を「効いていない」と誤判定する ——
掃引器が捕まえるために作られた型に、掃引器自身が嵌まっていた。いまは
`cavity_h` / `cavity_w` / `cavity_a` / `outer_r` / `beak_y` の 5 軸を見て、
**帯の端で一番応答した軸を本命に**判定する（軸によって食い違うときはそう言う）。
外形グリッドは先端 0〜3mm だけ 0.05mm 刻み ——`tip_chamfer` の面取り長は
アルト上限でも 0.29mm しかなく、全長 60 等分では跨いで消える。

よく使う引数:

```
# 拘束を置いて測る（min() の反対側が勝っていると「効いていない」と出る）
PYTHONPATH=. python cad/windycity/sweep_limits.py chamber_to_bore_mm --with window_length=44
# choice も渡せる。baffle_curvature は curve のときしか生きていない
PYTHONPATH=. python cad/windycity/sweep_limits.py baffle_curvature --with baffle_type=curve
# 本命の軸を人が指定する（自動が鈍い軸を掴んだとき）
PYTHONPATH=. python cad/windycity/sweep_limits.py tip_chamfer --axis outer_r
```

**再測で分かったこと**: Phase A の 4 本の壁は 5 軸の掃引器でも同じ値が出た
（`tip_opening` 0.05〜5.2 / `baffle_height` −2.3 / `window_length` 4.0 /
`chamber_to_bore_mm` 0.5〜30.0）。ただし**百分率は変わった** ——
`tip_opening` の soprano は 7% ではなく 43%。旧掃引器は素の「天井 − 床」を
見ており、実際にロフトされる断面（`_contain` 後）ではなかった。
**壁は動かなかったが、根拠の数字は物差しごと差し替わった。**

**掃引が測っているのはスキーマの壁とは限らない（Phase B-2）。** バッフル 4 本は
越えられない所を決めていたのが `ParamSpec` ではなく `profiles.py` の
`min(max(...))` だった。この状態で掃引すると「帯の端から先は形が動かない」と
出るが、意味は死に帯と違う ——**形が止まるのではなく、値がコードを通らない**。
掃引器はこれを「拘束は別のところで決まっている」と言って人に返す（壁だと
言い切らない）ので、**その一言が出たらまず `profiles` 側を読む**。
外すかどうかは値ではなく**止めている理由の有無**で決めた ——`_PLATEAU_RANGE`
だけが理由を持っていたので残し、「未測定」「出所なし」「循環」の 3 つは外して
測り直した。生ログは `docs/sweeps/b2-baffle-chamber.txt`。

## 未追従（Stage B / E / F / G / H で直した）

新形状に他コンポーネントが追いついていなかったぶん。判定カードが正しく警告を出していた。

**解消済み**（Stage B = `825c6c8`、Stage E = 音響の物差し、Stage F = ソプラノ実測と
チューニング量の扱い）:

- **リガチャー**: 内周を `table_plane_y(z)` へ追従させ、タブを弦幅でクランプするのを
  やめた。実物はリード幅＝テーブル弦幅なので、0.015mm 足りずに必ず警告が出ていた。
- **ネック**: 3 サイズのネックをノギスで実測して descriptor に入れた（2026-08-09）。
  テナーは テノン 15.0 ＋ コルク 1.10×2 ＝ 17.2mm で、**実測ボア 17.0mm との差 0.2mm が
  コルクの締め代**（`reference_check.INTERFERENCE_FIT_MM`）。旧値 17.8＋0.8×2 ＝ 19.4mm は
  テノン外径が 2.8mm 太かった。「ボアはコルク込み外径以上」という向きも逆で、実物は
  少し細い（隙間があると抜ける）。
- **逆算（`measure.py`）と仕様書 SVG**: 傾斜テーブルへ追従。

- **音響の測定分解能**: Tier2 の第1共鳴が周波数格子に量子化されていた。`impedance()` が
  `linspace(50, 2000, 800)` を張り（ΔF = 2.441Hz）、ピークを格子点のまま読んでいたので、
  低音の 1 目盛りが soprano 20.9 / alto 30.9 / **tenor 41.2 セント**。テストの「±20 セント
  以内」は 3 サイズとも 1 目盛りより細かく、格子がたまたま乗ったときしか通らなかった。
  対数等間隔格子（全域 7.99 セント/格子）＋ピークの放物線補間に直した。点数が同じなので
  計算時間は変わらない。記録値 −53.6/−40.1/−43.5 → **−61.2/−27.5/−23.2**。

- **音響の基準**（Stage E）: 「Tier1 −81 / Tier2 −23 で 4 倍食い違う」の原因は Tier1 の
  校正定数ではなく、**物差しの側のバグ 2 つ**だった。

  1. **音速の食い違い**。ジオメトリの全長 `l_total = c/(2·f1)` を `C_SOUND = 343.0`
     （20℃相当）で作りながら、OpenWind へは `temperature=25.0`（音速 **347.13**）を
     渡していた。同じジオメトリを 2 エンジンで解くと 23.9 / 24.7 / 26.0 セント違い、
     うち 20.7 は音速比 347.13/343 そのもの。`TEMPERATURE_C` を唯一の出所にして解消。
  2. **延長円錐が長すぎた**。`l_ext = c/(2·f1) − x0` は**開口端の放射補正がゼロの理想
     円錐**の式。ソルバは放射を含むので、**マウスピースを外して理想円錐だけを鳴らしても
     −52.3 / −48.2 / −44.5 セント**低かった。報告していた残差はほとんどこれ。いまは同じ
     ソルバで理想円錐が f1 に鳴る長さを求めている（0.02〜0.03 セントに収束）。

  直すと **alto と tenor のマウスピースは欠損円錐の代替として ±1 セントで成立していた**。
  実測形状＋実測ネックという推定値ゼロの組が、正しく「合っている」と出る。
  容積の一行規則（`cents = −250 × 容積比`）は捨てた。テナーは実効容積が欠損円錐より
  +23% あるのに音程は +0.3 セント —— マウスピースが**代替する円錐より 161mm 短い**
  （85.5mm vs 246.8mm）ので太いぶんと短いぶんが相殺する。容積 1 個からは出せない。
  Tier1 はいま同じ共鳴管を伝達行列法で解いた第1共鳴（31〜52ms）で、Tier2 との違いは
  エンジンだけ。**`cone_half_angle_deg` は Stage B.4 で容疑から外れたまま**（テナー大端
  内径 26.0mm の掃引で、実在するネック長 200〜280mm では文献値 1.52° を挟むだけ）。

- **`cork_depth` は寸法ではなかった**（Stage F）。Stage E が残した「ソプラノの
  −31 セント」を追うと、そもそもの立て方が間違っていた。コーク挿入深さは気温・
  リード・合わせる音程で**演奏者が抜き差しするチューニングそのもの**で、それを固定値
  として持ちズレをセントで報告すると、寸法の誤差とチューニングの自由度が混ざる。

  ソプラノの実物（ヤナギサワ、刻印 4）を実測すると **全長 71.4mm**（テンプレートの
  87.52mm より 16.1mm ＝ 18% 短い）、**ボア長 38.3mm**、**最大径の位置はシャンク端から
  14.3mm**。B.1 の「テナー実測 × リード規格長比 0.8141」は**軸方向でだけ**外れていて、
  径方向は当たっていた（ボア比 13.8/17.0 = 0.8118 と 0.3% 差）。**径は軸と同じ比では
  縮まない** —— ボア径はネックのはめあいで決まり、マウスピースの長さと無関係だから。
  実際、径を軸と同じ 0.664 で縮めるとシャンクの肉厚が 0.74mm になって `min_wall` を割る。

  判定を**合う挿し込み量**（`openwind_bridge.tuning_position`）に替えると 3 サイズが揃う:

  | | 合う挿し込み | 実用域 | チューニング幅 | 実効容積 / 欠損円錐 | 感度 |
  |---|---|---|---|---|---|
  | soprano | 23.5mm | 3〜26mm | −32.4〜+3.1 セント | +25% | 1.32 セント/mm |
  | alto | 19.2mm | 3〜30mm | −10.5〜+6.2 セント | +21% | 0.48 セント/mm |
  | tenor | 20.9mm | 3〜32mm | −7.5〜+3.2 セント | +26% | 0.27 セント/mm |

  容積比は**その挿し込み量での**値。どれも実用域の内側で、しかも比が独立に
  +21〜26% で揃う。**2 つの指標が同じことを言っている。**
  ソプラノの 1.32 セント/mm がテナーの 0.27 の 5 倍という数字も、
  そのまま演奏上の情報になる。

  **この表の「実用域」は推定で、Stage I で 3 サイズとも実測に置き換わった**
  （5.7〜27.1 / 3.0〜36.4 / 3.0〜36.0。深い側はボアでもコルク帯でもなく
  押し込み限界の実測）。当時書いていた「深い側の上限はネックのコルク帯で決まる」も
  ソプラノでは成り立たない。アルトの 19.2 も実物採寸で 13.6 に動いた。下の
  「実測の受け入れ（Stage I）」を見ること。

  `simulate` の予算は 50ms（`cad/perf/bench_ui_latency.BUDGET`）で、零点を包んで詰める
  厳密解は共鳴を 10 回前後解きテナーで 335ms かかる。常用経路は現在位置とその 1mm 奥の
  2 回から**局所の傾き**で線形に推す（厳密解との差 0.002 / 0.034 / 0.029mm）。
  仕様書は `exact=True`。推定が実用域の外へ出たときだけ自動で解き直す ——
  「チューニングでは合わせられない」は強い主張で、推定の粗さ（外れた形状で最大
  3.4mm）で言ってはいけない。実測で誤警報が出ている（テナーのボアを 46mm にすると
  推定 1.61mm ＝ 域外に対し厳密解 5.05mm ＝ 域内）。

  **代償は共鳴 1 回ぶんのレイテンシ。** `simulate` は soprano 28.8 / tenor 50.0ms
  （med。Stage E は tenor 34.3）で、テナーが目安の 50ms に接している。フレーム毎に
  叩かれる `section` は 8.4ms のまま無関係。第1共鳴の探索を第1共鳴の周り ±3% の
  細格子（60 点）にすると 1 回 17ms → 1ms になるが**精度が落ちる**ので不採用
  （零点の誤差 0.03 → 1.87mm、テナーの感度 0.271 → 0.378 セント/mm。共鳴の山が
  広いので格子を細かくすると放物線あてはめの 3 点がほぼ一直線になる）。

- **`ParamSpec.validate` は範囲外を黙ってクランプする**（`core/schema.py`）。レンジの
  下限が実物より上にあると、テンプレートに実測値を書いてもモデルは別の形を作る。
  ソプラノの `shank_dia` / `shank_length` / 全長で実際に踏んだ。レンジを下げたうえで
  `test_template_values_survive_the_schema_unclamped` で構造的に防ぐ。

- **リード全長は 1 点ではない**（Stage G）。Stage F はソプラノのテーブル終端と規格
  リードの 3.5mm 食い違いに 3 候補を並べた。実測で**候補 ①「63.5 が違う」が当たった**:
  バンドーレン 3番（ケーン）**59.1** / レジェール アメリカンカット（樹脂）**62.0**。
  63.5 はちょうど 2.5 インチの丸い値で、どちらからも 1.5mm 以上外れていた。

  それ以上のことが分かる。**同じソプラノ用で 2.9mm 違う。** 許容差
  `SEAT_REACH_TOL` 1.5mm の倍あるので、「リガチャー座の後端 ＝ 規格リード全長」という
  等値照合は**ソプラノで外れたのではなく原理的に成立しない**。判定を向きのある
  拘束 2 本に割った:

  （**数字は 2026-08-15 現在**。alto 列は Stage I／第2便で 2 度動いた。下の
  「アルトを実物へ」「第2便」を参照）

  | 行 | 判定 | soprano | alto | tenor |
  |---|---|---|---|---|
  | テーブル終端 / 座の後端 | 必須（自己整合） | 60.0 / 57.1 | **73.0 / 70.3** | 81.6 / 79.0 |
  | テーブル終端 / リード全長域 | 非対称 | 60.0 / **59.1〜62.0** | **73.0 / 70.2〜71.1** | 81.6 / 78.0（判定しない） |
  | （参考）座の後端 − リード全長 | 判定しない | **−4.9〜−2.0** | **−0.8〜+0.1** | +1.0 |

  参考行が**サイズ間で符号を変える**。マウスピースとリードの両方を実測してある
  組は soprano と alto の 2 つで、ソプラノは −2〜−5mm と大きく外れ、アルトは
  ほぼ 0。**両方実測でも揃わない**ので設計則ではない。tenor の +1mm は「実測
  マウスピース × 未実測リード」の一致なので証拠としてさらに弱い（descriptor の
  `reed_std_length_source` に書いた）。B.1 の倍率 0.8141 は 63.5/78.0 で、正しい
  ケーンの 59.1 で引き直しても 0.7577 にしかならず実比 0.6642 に届かない ——
  **「全長はリード規格長から決まる」は正しいリード長を入れても成立しない。**

- **合う挿し込み量に典型値は無い**（Stage G）。実演奏の位置はマウスピース・リード・
  リガチャー・気温・アンブシュアすべてに影響される、というユーザーの指摘。そのとおりで、
  **モデルに入っているのは気温（`TEMPERATURE_C` = 25°C）と合わせる音程
  （`low_note_sounding_hz`）の 2 つだけ**。だから 23.5mm は「あなたが挿す深さ」の
  予測ではなく基準条件での値でしかなく、典型値との一致では検証できない。
  条件を `tier1_report` の `note` と仕様書のラベルに書き、
  `test_in_tune_insertion_is_a_reference_not_a_prediction` が消せないようにした。
  検証できる形にすると「**演奏者が実際に使う挿し込み量の域**（最も深い位置と
  最も浅い位置）に入るか」になる。

  **保留（測っても直さない、まず調べる）**: `cents_per_mm` が 1.325 / 0.478 / 0.271 と
  サイズ間で 3.9 倍ばらつく。管長だけで決まるとしたときの上界
  `1200·log2(L/(L−1))`（L = c/(2f₁) ＝ 836 / 1252 / 1671mm）は 2.07 / 1.38 / 1.04 で、
  比は **0.64 / 0.35 / 0.26** と単調に落ちる。判定の `TUNING_MARGIN_MM = 2.0` は
  この傾きに乗っているので、外れていれば tight / ok が動く。Stage E.2 の延長円錐の
  校正由来なのか実体なのかは測らないと分からない。

- **合成用の共鳴管が段差を落としていた**（Stage H）。時間領域リードシミュが
  「単一のレジスタに落ち着かない」（alto 実測で loose 1220 / normal 951 /
  tight 133Hz、上位成分 5 本、duration を延ばすと支配成分が移る）のを追ったら、
  リードのスケーリングではなく `_coarsen` が犯人だった。alto 既定で共鳴管を
  44 点 → 8 点に間引く際、**マウスピースのボア 7.90mm からネック小端 6.35mm への
  段差**（前の点の 0.5mm 後ろ）を `min_dx = 8mm` で捨てていた。

  | | 生の管 | 段差を落とす（旧） | 段差を残す（いま） |
  |---|---|---|---|
  | alto f1 | 138.69 Hz | **133.43 Hz（−67 セント）** | 138.58 Hz（−1.4 セント） |
  | alto n2 / n3 | 1.993 / 3.006 | 2.055 / **3.162** | 1.994 / 3.008 |
  | alto 5次のQ | 0.7 | **26.5** | — |
  | soprano f1 | 207.47 | — | 207.19（−0.13%） |
  | tenor f1 | 103.92 | — | 103.79（−0.13%） |

  「tight の 133.4Hz が共鳴から 4% ずれている」のではなく、**粗くした管の
  第1共鳴 133.43Hz そのもの**だった。共鳴列が引き伸ばされて非調和になる
  （3次が 5% シャープ）ため基音より上のレジームが安定できず、リードがモードを
  渡り歩いていた。**−67 セントは段差 1 本で全部**で、戻すと比まで 0.1% 以内に入る
  —— ティップ側の刻みは本当に効いていない（旧 docstring の「数 mm の刻み差は
  ほぼ効かない」は刻みについては正しく、落としていたのが刻みではなかった）。

  段差は**零長の不連続**にする。0.5mm のまま残すと CFL が効いて 1,183,109 ステップ
  （2 倍）。零長なら 562,050 ステップで旧と同じ。判別は間隔ではなく**傾き**
  （`|Δr/Δx| ≥ 2.0`）—— 生の管 43 セグメントで 2.0 を超えるのは段差 1 本だけ（3.1）で、
  次に急なティップ近傍の 0.86 と 3.6 倍の開きがある。3 サイズとも零長は 1 本。

  **速くはならない。** 一度「半径が跳ぶ点を無条件に残す」版を書いて 8.3 倍速く
  なったが、幾何を見ると連続した跳びが同じ x に積み上がって**ティップのテーパが
  階段に潰れていた**。速さはその歪みそのもの（メッシャーが急テーパを刻み直さなく
  なる）で、測って捨てた。

  併せて**アンブシュアを吹奏比で定義し直した**。`pulsation` だけ書き換えて
  `mass` / `section` を CLARINET のまま残していたので、静的ビーティング圧
  `p_M = ω₀²·(M/S)·y₀` が ω₀² で動く一方、吹圧は独立の定数だった。結果
  γ = 吹圧/p_M が loose **1.14** / normal 0.70 / tight **0.30**（CLARINET 既定は
  0.40）とばらけ、**名前と挙動が逆**になっていた —— 「tight」＝リード共振が最も
  高い＝最も硬い＝ γ が最も低い＝一番きれいに基音が出る。いまは
  `BLOWING_RATIO = 0.30` で揃え、吹圧は `f_reed` と `opening` から導出する。
  副産物として `tip_opening` と `facing_length` が吹圧に効くようになった
  （定数で持っていた頃は設計値を動かしても吹圧が変わらなかった）。

  3 サイズ × 3 アンブシュアの実測（f0 / 第1共鳴、セント）:

  | | loose | normal | tight |
  |---|---|---|---|
  | soprano | **−1936**（67.8Hz） | −21.5 | −11.4 |
  | alto | −13.6 | −7.3 | −4.8 |
  | tenor | −0.4 | −2.1 | −2.1 |

  **2026-09-21 追記（アルトの `reed_width` 13.4 → 16.4、実測）**: リード部品が無いとき
  流路幅はマウスピースの `reed_width` から取るので、アルトの f0 が
  137.15 / 137.58 / 137.79 → 137.70 / 137.73 / 137.85 Hz（+6.9 / +1.9 / +0.8 セント）
  動いた。3 つとも第1共鳴のまま。上の表は 13.4 の頃の値（`docs/reed-seat.md`）。

  **9 通り中 8 通りが第1共鳴。soprano の loose だけ 67.8Hz ＝ f1 の 0.327 倍**
  （207.47/3 = 69.2 に近い）で周期 3 倍化に落ちる。γ を揃えても残るので
  `_coarsen` の話ではなく、リード共振（soprano loose は f_reed 2070Hz ＝ f1 の
  10.0 倍）と非線形の組合せ。`losses`（`diffrepr`/`False`）と `order`（2/4）は
  音程に効かない（4 通りで 137.5〜137.6Hz、差 0.9 セントで FFT のビン幅以下）。

  **リード実形状の効き方も観測量が変わった。** 以前は「リード共振を変えると
  レジスタが変わる」（f0 が 5% 以上動く）で見ていたが、直すと硬さに関わらず
  第1共鳴が鳴る —— それが正しい（ビーティングリードはリード共振よりずっと低い
  管の共鳴に乗る）。効くのは音色で、倍音比（f0 の 1〜8 倍）が
  ティップ厚 0.30（f_reed 1847Hz）で 1.00/0.35/0.71/0.24/0.29/0.12、
  0.55（2154Hz）で 1.00/0.01/0.25/0.00/0.06/0.01 —— **硬いほど偶数倍音が落ちる**
  （L1 差 1.42）。なお **音色は音高より遅れて立つ**: 0.3s では両方ほぼ正弦で
  L1 差 0.006 しか出ない（音高は 0.36s で定まる）。テストは既定 duration が要る。

**残り**:

- **シャンク平行部の開始**（＝肩テーパの終わり。どれか 1 サイズ）。最大径の位置は
  3 サイズとも決まったが、`shoulder_ratio` 0.139 は**いまだにテナー 1 本の実測**を
  3 サイズで使い回している。最大径位置 1 点では `shank_length` と `shoulder_ratio`
  の組が一意にならないので（`profiles` の `_SHOULDER_RATIO`）、比のほうを実測に
  するにはもう 1 点要る。**判定は動かない** —— アルトで両方の解を試すと
  `table_cut_end_z` は 73.04 対 72.18 で、どちらでもカードは「一致」。
- **テナー基準組（WindyCity）の挿し込み限界**。いまの 36.0 は Jody Jazz Giant 6*
  で測った値で、3 サイズで唯一「テンプレートの基準マウスピースとは別の個体」。
  Jody Jazz のボアは 16.7 で WindyCity の 17.0 より細く、より手前で噛むはずなので、
  **基準の組に対しては下限**として読むことになっている。
- **alto / tenor のコルク帯**（フェルール端からコルクの奥端まで）。ソプラノだけ
  実測（33.7）が入っている。**深い側の上限は押し込み限界の実測に置き換わったので
  判定は動かない**が、推定 30.0 / 32.0 が実測の 36.4 / 36.0 より短いことは分かって
  いるので、いまの値は「実態より短いと分かっている数字」として置いてある。
- **ソプラノ × 緩めの周期 3 倍化**（上の表）。9 通りで 1 つだけ第1共鳴に乗らない。
  リード共振と非線形の組合せで、共鳴管の話ではない。`f_reed` を上げるか γ を
  下げると消えるはずだが、プリセットの意味が変わるので測ってから決める。
- **ソプラノの未実測寸法**: `body_dia` / `shank_dia` / `window_length` / `beak_height`。
  音程には効かない（`shank_length` と `shank_dia` は 0.00 セント）が、作図とリードの
  座りに効く。採寸図は `measure_soprano.py` で再生成できる。
- **alto / tenor のフェルール長**（端面からコルクまで）。3 サイズとも同じ作り
  （ユーザー確認）なので 0 のままなのは実態と違うが、**深い側は押し込み限界の実測に
  置き換わったので判定は動かない**。効くのは浅い側の下限だけ（3.0 → 5.7 相当）。
- **ソプラノのティップ開き**（紙束法）。テーブル終端の実測が ±0.12mm で追認したので
  優先度は下がった。
- 小さいもの: **採寸図が「最大径の位置」の寸法線を持たない**。`measure_*.svg` は
  シャンク端基準で `shank_length` を描くが、実際にノギスを当てるのは
  **最大径の位置**（＝ `shank_length` ＋ 肩テーパ長）で、そちらの寸法線が無い。
  図は正しいが、次に測る人が引き算しないと合わせられない。`measure_soprano.py` に
  1 行足して 3 枚とも描き直せば済む。

## 実測の受け入れ（Stage I）

### ネックのコルク帯（ソプラノ実測、2026-08-13）

差込口の端面から **2.7mm は真鍮のフェルール**（補強リング）でコルクが無く、
その先に**コルク帯 31.0mm（typical）**。マウスピースはフェルールの上を通過するので
押し込める上限は **33.7mm**。以前の 26.0（neck テンプレートの `tenon_length` を
写しただけの推定）は **7.7mm 短かった**。

| コルク帯 | 実用域 | 深い側の余裕 | 判定 |
|---|---|---|---|
| 26.0（推定） | 3〜26.0 | **2.45mm** | ok（ぎりぎり） |
| 2.7 ＋ 31.0（実測） | 5.7〜33.7 | **10.15mm** | ok |

**ソプラノが 3 サイズで唯一きわどく見えていたのは形状ではなく推定値のせいだった**
（alto 10.84 / tenor 11.14 と揃う）。`tip_opening` を可動域の端まで振っても
深い側の余裕は +5.36〜+11.00mm で、**ティップ開きはもう判定を動かさない**
（実測前は 2.15mm 以上で `tight` に落ちていた）。

**ただしこの 33.7 も上界でしかなかった。** 次節のとおり実物は 27.1mm で止まる
（深い側の余裕は 10.15 → **3.55mm**）。コルク帯の実測は「そこまでコルクが在る」
ことしか言っておらず、「そこまで入る」とは言っていない。

**そして「ティップ開きはもう判定を動かさない」も取り消しになる。** 実測の 27.1 で
掃引し直すと逆戻りする:

| `tip_opening` | 1.00 | 1.83 | 2.38 | **2.65** | **2.93** | 3.20 |
|---|---|---|---|---|---|---|
| 合う挿し込み | 22.42 | 23.34 | 24.96 | 27.07 | 30.06 | 30.38 |
| 押す側の余裕 | 4.68 | 3.76 | 2.14 | **0.03** | **−2.96** | −3.28 |
| 判定 | ok | ok | ok | tight | **届かない** | 届かない |

既定の 1.95 は余裕 3.6mm で問題ないが、**スライダの上半分は tight、2.9 以上では
合う位置に届かない**。33.7 という上界で見ていたときは全域 ok に見えていた。
**「上界で判定して安心する」ことの危うさがそのまま出た例。**

#### 副作用: soprano × straight だけ `simulate` が予算を超える

深い側が 33.7 → 27.1 に縮んだことで、**soprano/straight の速い経路（線形推定）が
実用域の外へ出るようになった**（推定 27.54 対 上限 27.10）。`tuning_position` は
そのとき**必ず厳密に解き直す**設計なので（粗い推定で「届かない」と言わないため）、
共鳴を 10 回前後解くぶん時間が増える。厳密解は 26.97 ＝ **ぎりぎり届いている**ので、
解き直しは仕事をしている —— 解き直さなければ誤って「届かない」と報告していた。

同一マシン・同一手順の A/B（中央値 ms。**このマシンは現在 Stage I 実測時より
約 1.35 倍遅い**ので、絶対値を 50ms 予算と比べてはいけない。無変更のテナーが
両側とも 65〜74ms で、Stage I 単独計測の 49.7〜50.7 に対する換算係数になる）:

| | soprano/step | **soprano/straight** | alto/step | tenor/step |
|---|---|---|---|---|
| BEFORE | 39.5 | **60.1** | 72.1 | 68.0 |
| AFTER（3 回） | 32.7 / 42.1 / 33.6 | **72.9 / 86.6 / 82.4** | 52.6 / 56.9 / 60.1 | 69.1 / 73.7 / 71.4 |

換算すると soprano/straight は **45 → 61ms 相当**で、12 通り中この 1 つだけが
予算 50ms を超える。他は横ばいかむしろ速い（アルトは胴が 6.8mm 短くなったぶん）。
**正しさと引き換えの遅さなので、直すなら「厳密解を速くする」側**（未着手）。

浅い側も 3.0 → 5.7mm に動いた。`_CORK_MIN_MM` は「コルクが噛むのに要る長さ」なので、
フェルールを足さないと「3mm 挿してある」が実際にはコルクが 0.3mm しか噛んでいない
状態を域の内側と数える。実測してあるのはソプラノだけなので、**alto / tenor の
フェルールは 0 のまま**（無い値を推定で埋めると出所が消える）。

分かったことがもう 2 つある:

- **S-902 はネックと管体が一体**（ソプラノとしては一般的）。descriptor の「ネック」は
  独立部品ではなく本体円錐の先端で、neck テンプレートの `neck_length` /
  `body_tenon_length` は印刷側の設計値であって実測ではない。
- **コルク帯は厳しい公差の掛かった部位ではない**（幅は周方向でも一定でない）。
  だから深い側の上限は**硬いしきい値ではなく柔らかい境目**として扱う。
  `tight` の助言は「余裕は n mm」ではなく「実物を止まるまで押し込んで確かめること」。
  `cork_depth`（Stage F）・リード全長（Stage G）に続く
  「一意に決まると思っていた量」の 3 つ目。

### 押し込み限界の実測（3 サイズ、2026-08-13）← モデル唯一の外部照合

ネック端面からマウスピースのシャンク端面まで、実際に押して測った。
**機械的な止まりではなく「これ以上押し込んだらまずい」という演奏者の判断**なので、
硬いしきい値ではない。**ネック単独でもマウスピース単独でもなく組の性質。**

| | 楽器 ＋ マウスピース | 実測 | それまでの推定 | ずれ |
|---|---|---|---|---|
| soprano | S-902 ＋ ヤナギサワ 4番 | **27.1** | 33.7（フェルール＋コルク） | −6.6 |
| alto | YAS-875 ＋ Wood Stone PHROX | **36.4** | 30.0（推定コルク長） | +6.4 |

### 締め代も「1 点ではない」← 4 つ目

狙い値は `テノン外径 ＋ 2×コルク厚 − 締め代 0.2`。

| マウスピース | 実測ボア | 狙い値 | 締め代 |
|---|---|---|---|
| alto Wood Stone PHROX | 15.8 | 15.80 | **+0.20** |
| alto Meyer G by Meyer 6番 | 16.4 | 15.80 | −0.40 |
| tenor WindyCity | 17.0 | 17.00 | **+0.20** |
| tenor Jody Jazz Giant 6* | 16.7 | 17.00 | +0.50 |

**基準マウスピース 2 本がどちらもちょうど +0.20** ——
`INTERFERENCE_FIT_MM` の根拠が n=1（テナーのみ）から **n=2** になった。しかも
アルトの 15.80 は**測る前にテナーの 0.2 とネック実測だけから書いてあった値**で、
実測が 15.8。狙い値を先に書いてから測って当たった唯一の量。

だが**同じアルトのネックに 0.6mm 違うボアの 2 本が載る**以上、締め代は 1 個の
定数ではない。差を吸収しているのは**コルクの厚み**（摩耗する消耗品。このアルトの
コルクは 3 サイズで唯一 1.0mm を割る 0.75 で、巻き直せば狙い値ごと動く）。
`BORE_TOL` 0.3 / `BORE_TOL_MINOR` 1.0 は**この散らばりがそのまま根拠**なので
締めない —— 締めると実在して装着できているマウスピースを「乖離」と言うことになる。

同じことは全長・最大径にも出る（alto 91.7 / 88.3、tenor 107.5 / 目測 102、
最大径 alto 29.1 / 28.0、tenor 30.8 / 30.0）。**基準は 1 サイズ 1 本**と決めて、
他は散らばりの証拠として数字だけ残す。

### テーブル終端は外部確認された（ソプラノ実測 60.2 対 モデル 60.00）

差 **0.2mm**。`table_cut_end_z` は実測を一切見ずに「テーブルは 4.18° 傾く」＋

0.4mm しか動かない（＝スケール値の `body_dia 25.0` には依存しない）。
つまりこの一致が効いているのは `table_angle` と `tip_opening`。掃引では
`tip_opening` 1.40→2.80 で 61.04→58.79 と 2.3mm 動くので、0.2mm は
**ティップ開き 0.12mm 相当** —— 未確認だったチャート値 **1.95 が ±0.12mm で追認**された。

1.8mm はみ出す。**これはモデルの粗さではなく実物の性質**だと分かった ——
実測どうしの比較で出た差。カードはこれを引き続き出す。

### アルトの全長に対する非単調性は数値ノイズではなかった

## 外形を動かせるようにした（Phase 4-C.1、2026-08-16）

実測プロファイル（`_BODY_PROFILE` 16 点 / `_SHOULDER_PROFILE` 9 点）は**定数のまま
残し**、その上に「両端 0 の歪み」を 1 個ずつ掛ける形にした。実測形は歪み 0 の
ときの形なので、**テンプレートの形は 1μm も動いていない**。

### 最大径を「頂点」として扱う

`outer_radius_nominal` は元から `heel_z` で場合分けしていた。そこを設計の骨にして、
**歪みは境を跨がない**ようにしてある:

| 歪み | 効く区間 | 頂点の半径 |
|---|---|---|
| `body_waist` | z < heel_z のみ | 動かさない（sin(πu) が u=1 で 0） |
| `shoulder_fullness` | z > heel_z のみ | 動かさない（直線も (0,1) を通る） |
| `body_dia` | 全体（相似スケール） | **これだけが動かす** |

前後の分離は**ビット一致**でテストに固定した
（`test_outer_shape_handles_do_not_cross_the_max_diameter`）。誤差ではなく
「別の区間しか触っていない」という主張なので、公差を置く意味が無い。

**崩れると何が壊れるか**: `table_plane_y` は `outer_radius_nominal(0)` から引くので、
前方が動くとテーブル平面ごと動いてティップ開きと音程が変わる。**肩を触っただけで
音程が動く**のがいちばん避けたい壊れ方で、そこを構造で止めている。

STEP 側も同じ境で切る（`body_segments`。1 本のスプラインで通すと折れ目で 0.58mm
オーバーシュートするのは Stage C-2 で実測済み）。

### 円錐シャンク（最大径からシャンク端まで一直線）

`heel_z` は導出値なので、`shank_length` を単独で動かすと**最大径ごと動いて前方まで
相似に伸縮する**。「肩の終わり」ハンドルは 2 つを連動して解く:

```
shank_length   = 全長 − z*
shoulder_ratio = (z* − heel_z) / heel_z
```

`heel_z = (L − shank)/(1 + ratio)` に入れると z* が約分されて heel_z に戻る。
実測でも端から端まで振って **ずれ 1e-7mm 台**（残るのはハンドル payload の丸めぶん）。

平行部を 0 にするのに要る肩比は soprano 0.2504 / alto 0.3044 / tenor **0.3605** で、
これが `shoulder_ratio` の上限を 0.25 → 0.45 に、`shank_length` の下限を 5.0 → 0.0 に
広げた理由。ここに `shoulder_fullness = +1` を足すと母線が厳密な直線になり
（残差 3.6e-15）、STEP は母線 2 点＝**CONICAL_SURFACE 1 枚**で出る。

**従属側を step へ丸めてはいけない。** 肩比を 0.005 刻みに丸めると最大径の位置が
0.13〜0.17mm 動く（実測）。フロントは主キーだけ丸め、丸めたあとの t から従属値を
引き直す（`SectionEditor.valuesAt`）。

### 掃引が掘り当てた既存のバグ: 最大径がシャンク径を下回れてしまう

`sweep_outer.py` を回したら **tenor / `body_dia=min(18.0)` でソリッドが 2 個**に
割れた。**Phase 4-C.1 の変更が原因ではなく元からある穴**で、`sweep_cad.py` の
`SWEEP_KEYS` に `body_dia` が入っていなかったから一度も踏まれていなかった。

3 サイズとも下限 18.0 はシャンク径（18.7 / 21.1 / 23.0）を下回る。逆転すると
`outer_radius_nominal = r_sh + (r_max − r_sh)·shape` の符号が反転して肩が
**外向きに太り**、「最大径」の位置が最大でなくなる。さらにテーブル平面は
`outer_radius_nominal(0)` から引くので、胴が細るとテーブルごと上がって
痩せた胴を斜めに抜ける。

**割れなかったソプラノとアルトのほうが偶然。** `is_valid` は True のまま返るので、
妥当性フラグや面数だけ見ていても気づけない（`len(part.solids()) == 1` を見て
初めて出た）。

直しは `params_error`（値の**組**で成立しないものを弾く既存の出口）に
「最大径 ≥ シャンク径」を足した。レンジを狭めなかったのは、これが 1 本の
パラメータの問題ではなく 2 本の関係だから。境界（等しい）は成立する側 ——
肩の段差が 0 になるだけで形は壊れないので、掃引でもそこを踏んでいる。

### 最大径の上限は判定カードにした（クランプしない）

ユーザー実測（2026-08-16、ノギス）:

| | 全長 | ボア内径 | 最大径 |
|---|---|---|---|
| Wood Stone PHROX（alto 基準機） | 91.7 | 15.8 | **29.1** |
| Meyer G by Meyer 6番（alto） | 88.3 | 16.4 | **28.0** |
| Jody Jazz Giant 6*（tenor） | 目測 102 | 16.7 | **30.0** |
| WindyCity（tenor 基準機） | 107.5 | 17.0 | **30.8** |

上限は alto **29.0** / tenor **30.0** / soprano **無し**（基準にできる市販機が未実測）。

**アルトの 29.0 は Meyer の 28.0 ではない。** 根拠は「29.1 の PHROX が Meyer 向け
リガチャーに実際に適合する」というユーザーの実使用観測で、つまりこの上限が
指しているのは**マウスピースの最大径ではなくリガチャー側の受け容量**。世間の
リガチャーが Meyer 寸法を目安に作られている、という慣例に基づく基準。

**だから `ParamSpec.max` にはできない。** 基準機自身が上限を超えている
（alto +0.1 / tenor +0.8）ので、硬い上限にすると `ParamSpec.validate` が読み込み時に
テンプレートの実測値を黙って書き換え、基準機が別の形にすり替わる。
`window_length` / `bore_dia` / `_SHOULDER_RATIO` で 3 回踏んだ穴と同じ。

判定は非対称（細い側は見ない）で 超過 ≤0.3 一致 / ≤1.0 軽微 / 超 乖離。結果は
**alto 一致（+0.1）/ tenor 軽微（+0.8）**。テナーの軽微は消さない ——
アルトと違い「超えていても市販リガチャーに入る」実績が無い。上限のほうを 30.8 へ
緩めると根拠が「自分の基準機がそうだから」になり、実物照合が循環する。
**決着させる実測は 1 つ: WindyCity に市販テナー用リガチャーが入るかどうか。**

## 寸法の図示（Phase 4-C.5）で測ったこと

3 サイズ × 主要 10 パラメータを可動域 21 点で振り、**スライダの値**と
**法則から読んだ幾何量**を比べた（`params_error` の組は除外）。

| パラメータ | 食い違う点 / 21 | 内容 |
|---|---|---|
| `window_length`（soprano） | **16 / 21** | 28.54mm で凍る（可動域 24〜44 の 76%） |
| `window_length`（alto） | **6 / 21** | 38.67mm で凍る（4-C.5 当時は 7 / 21・37.92mm） |
| `window_length`（tenor） | 0 / 21 | 全域が効く（凍る点 45.15mm は可動域の外） |
| `reed_width`（3 サイズとも） | **21 / 21** | 下記（ソリッド上に存在しない量） |
| 径・長さ・開き・ビークの 8 個 | 0 / 21 | 幾何と厳密一致 |

`window_end_z = min(front + window_length, bore_start_z − chamber_to_bore_mm)` の
後ろ側が効くと、スライダを上げても形が 1 ビットも動かない。実効値は
`window_length_effective` として既に存在していた（出す先が無かっただけ）。
**同時に docstring の数字が古いことも分かった** —— アルトは 41.1 ではなく
**37.92**、全長側は 95.0 ではなく **88.7** で、テンプレートが変わる前の値が
残っていた（この機に直した）。

### その数字はもう一度腐った（2026-09-06 に確認）

9/05 の検品で `bore_length` を実測が許す上限 48.30 へ直したので、アルトの凍る点は
**37.92 → 38.67**、全長側は **88.7 → 91.70** へ動いた。形もテストも追随したのに
**散文だけ 4-C.5 のまま**だった —— 同じ腐り方の 2 回目。原因は
`bore_start_z − chamber_to_bore_mm − window_front_z` の 3 項がどれもテンプレート
ぶら下がりなのに、その計算結果を docstring と表に**焼いて**いたこと。

対処は数字を消すことではなく**置き場所を変えること**。`window_length_effective`
の docstring からは数字を抜いて式だけ残し、値は
`test_the_window_freeze_point_is_where_the_docs_say_it_is` の `_WINDOW_FREEZE_MM`
に置いた。テンプレートが動けばそのテストが落ち、隣の `_WINDOW_FREEZE_DOCS` が
**散文を持っている 3 か所**を名指しする。

**そしてアルトは既定 38.67 がちょうどその凍る点に載っている。** 意図的で
（`bore_length` 48.30 は PHROX 実測が許す上限そのもの。`docs/print-inspection.md`）、
既定は「不足 0」と「1 目盛り上げたら 1 ビットも動かない」を同時に満たす。
利用者から見ると **ウィンドウ長のスライダは既定より上が丸ごと効かない**。

### 警告のほうが古かった（同時に直した）

止めている量を**文面に直値で書いていた**。「ボアの始まり 43.4 − **4.0mm**」の
4.0 は Phase 4-A で `chamber_to_bore_mm` になっているので、利用者がそれを 0.5 に
縮めて窓が実際に 42.2mm まで伸びても、文面は 4.0 と言い続ける。しかも直し方が
「全長を長く / ボア長を短く」だけで、**本命のつまみが挙がっていなかった** ——
`window_length` の説明文だけが「これを縮める」と言っていて、実際に読まれる警告と
食い違っていた。`min`/`max` がスキーマの外で 4 か所消費されていたのと同じ型
（代理変数は 1 か所直しても終わらない）。

**どこに出るかも非対称だった**: 3D タブだけを見ていると何も出ず、実効値は
📏 寸法（「ウィンドウ長 38.67 mm（指定 44.00）」）、警告は断面タブにしか
出なかった。これは下で塞いだ。

### 警告は右パネルの 1 か所に寄せた（2026-09-06）

**原因は場所ではなく便だった。** `cavity_warnings` が `Component.section()` の
戻り値に埋まっていて、それを読むのは `/api/section` ＝ 断面タブだけ。いっぽう
右パネルは `simulate()` の便を `GET /api/project` と `PUT /api/project/params` の
2 経路で受けており、**スライダ 1 目盛ごとに来る**。そこへ移した ——
`Component.warnings()` を registry に足し（既定 `[]`）、`AppState.simulate` が
結果に足す。**各コンポーネントの `simulate()` には書かせない**（`/api/section` が
`dimensions()` をルート側で足しているのと同じ理由。部品が増えたときに書き足し
忘れる経路を作らない）。空リストなら UI はカードごと出さないので、
**「どの部品が警告を持つか」を UI に書かずに済む**（断面タブを 404 で出し分けて
いるのと同じ約束）。

**分け方の規則**（警告は 2 種類あって、片方だけがカード向き）:

| 種類 | 例 | 出し方 |
|---|---|---|
| **状態** ＝ パラメータがそうである限り真 | 形が法則どおり出ていない／息の通り道が絞られる | 右パネルの「⚠ 注意」カード。**警告があるときだけ現れる** |
| **出来事** ＝ いま起きた | 壁で丸めた・旧プロジェクト変換・凍結後に触った・組が成立せず弾かれた | トーストのまま。常設カードに貼ると「いつの話か」が消える |

断面タブの行は**掴んでいる間だけ**残した。`/api/section?key=値` は毎フレーム
叩かれるので、**指を離す前**の値での注意が出るのはこちらだけ（右カードは確定＝
`PUT` を待つ）。確定前の行と右カードの行が食い違って見えるので、断面側には
「この位置での注意:」の見出しを付けた。

なお**アルトは既定で 1 行出ている**（天井がビーク下の肉厚で頭打ち。
`docs/print-inspection.md` の既知の状態）ので、カードは既定から見えている ——
「出ていること自体が異常の合図」にはならない。

### `reed_width` はテーブルの幅ではない

テーブルは平面カットなので、実際の平面幅は半径とカット深さから決まり **z で変わる**:

| | `reed_width` | 窓中央 | リガチャー座中央 | 最大径 |
|---|---|---|---|---|
| soprano | 12.9 | 14.26 | **13.98** | 13.74 |
| alto | 13.4 | 16.24 | **15.14** | 14.66 |
| tenor | 14.8 | 16.81 | **14.66** | 13.88 |

`reed_width` を使っているのは `window_width`（公称）とリガチャーのタブ幅だけで、
マウスピースの面を 1 つも決めていない。だから寸法線は引かず、`table_flat_width`
（座中央）を出す。**テナーだけ実幅 < `reed_width`（14.66 対 14.8）** ＝ 規格リードの
方が 0.14mm 広い。ソプラノ／アルトは逆（+1.08 / +1.74）。どちらを正とするかは
別の話なので、ここでは数字を出すだけにしてある。

### 断面へ寸法を出しても重くない

alto マウスピースの実測: `section()` **7.23 ms** に対し寸法の幾何は **0.29 ms**
（うち 0.28ms は `table_cut_end_z` の二分法 60 回。どの寸法にも要らないので呼ばない）。
`regions()` は 0.029 ms。
## 母線が単調でなくなっても OCCT は何も言わない（Phase 4-E B-4b、2026-09-07）

壁の一覧と数字は `docs/param-limits.md`、生ログは
`docs/sweeps/b4b-outer-curves.txt`。ここには形の側の話だけ書く。

**「最大径は踵」は主張であって計算結果ではない。** `heel_z` は
`(全長 − シャンク長)/(1 + 肩比)` という軸方向の式なので、形を歪める 2 本
（`body_waist` / `shoulder_fullness`）では**定義上 1 ビットも動かない**。
だから `heel_z` を見張っている限り、この 2 本が頂点を壊しても永久に
検出できない ——`sweep_outer.py` の主張 (1) が B-4b までそうだった。
**式を検算していて形を見ていない。**

そして形のほうも壊れない。`body_waist` を ±0.36、`shoulder_fullness` を
±4.0 まで振っても、3 サイズとも `params_error` は `None`・ステーションは
健全・**OCCT はソリッド 1 個**（体積も素直に増減する）。壊れるのは
**主張**だけ ——胴は最大径へ太る一方、肩はシャンクへ細る一方、という
`ligature_seat_range` / `outer_radius_nominal` が乗っている前提。

**1 つの主張なのに壊れ方が 4 通りあり、目を 1 つ作っただけでは足りなかった。**

| 目 | 見るもの | 捕まる | 見落とす |
|---|---|---|---|
| `outer_apex` | 最大半径の z | `body_waist` 上 | 他の 3 つ |
| `body_dip` | 胴が太るのをやめる点 | `body_waist` 両側 | 肩の 2 つ |
| `shoulder_dip` | 肩の最小半径 | `shoulder_fullness` 下 | 他の 3 つ |
| `shoulder_bulge` | 肩が細るのをやめる点 | `shoulder_fullness` 両側 | 胴の 2 つ |

最初は `outer_apex` と `shoulder_dip` だけで測りに行き、**肩比 +1.85〜+1.88 で
何も鳴らなかった**（肩は膨らむが最大径は超えず、シャンク径も割らない）。
単調性そのものを見る 2 つが主で、他の 2 つはその症状でしかない。

**限界値は実測プロファイル表から解く。** `r/r_max` に正規化した形の性質なので
3 サイズ共通・他のパラメータに依らず、`body_waist_limits()` /
`shoulder_fullness_limits()` が母線の微分の符号から閉じた式で出す
（±0.161380 / +0.072572 と −0.360730 / +1.863339）。**数字をスキーマへ
書き写さない** —— 写すと表を差し替えたときに片方だけ古くなる。

**肩の下側は「えぐれ」で、しかも必ずボアの上に来る。** `shoulder_fullness` を
−0.3607 より下げると肩の中ほど（s≈0.73）が `shank_radius` を下回り、
`shank_warnings` が言う肉厚（シャンク径 − ボア径）が**最薄でなくなる** ——
注意の数字そのものが甘くなる（−1.0 で 0.26〜0.34mm）。旧レンジの下端が
まさにそこだった。

**ビークは「切除できているか」を誰も見ていなかった。** ビークは切除ソリッド
なので、稜線が胴の外へ出ると**何も削らない**（上面は胴のまま）。旧コメントは
その点を「胴の全高 0.9·body_dia」と書いていたが、実測はバイトポイントでの
胴の全高 ＝ 0.723 / 0.734 / 0.746·body_dia で、**比は一定ですらない**
（バイトは全長の 1/4 で、そこの太さは踵までの比で決まる）。旧レンジの上端
0.75 倍は 3 サイズとも壁の外だった。いまは `beak_height_at_body_top` /
`beak_height_flat` が引く。

## 踵は 30% で床に当たって凍っていた（Phase 4-E B-4a、2026-09-06）

壁の一覧と数字は `docs/param-limits.md`、生ログは
`docs/sweeps/b4a-outer-axes.txt`。ここには形の側の話だけ書く。

**最大径の位置（踵）には床があった。** `heel_z` は
`(全長 − シャンク長)/(1 + 肩比)` に `max(…, 0.30·全長)` を掛けて返していて、
床に当たる点は soprano 47.0 / alto 60.4 / tenor 70.8mm（`shank_length`）と
2.036 / 1.911 / 1.791（`shoulder_ratio`）。**そこから先はどちらも形を
動かさないのに、段 1〜3 は 110mm / 2.45 まで ok を返し続ける** ——
`shank_length` は外形が丸ごと凍り、`shoulder_ratio` は踵が凍っても
肩の長さ（比 × 踵）が伸びるので母線だけ変わる。

凍り方が違うので**検出器の当たり方も違った**。`shank_length` は掃引の死に帯
（応答 0%）にそのまま引っかかるが、`shoulder_ratio` は 22〜54% を返し続けて
見えない。それでも踵が式どおり動かなくなった時点で「最大径位置に対する比」
という量の意味が壊れる（寸法図と仕様書は与えた数字を印字し続けるので、
図と形が食い違う）ので、そこを壁にした。

床の比は `profiles.HEEL_FLOOR_RATIO` に名前を付け、当たる点は
`shank_length_at_heel_floor` / `shoulder_ratio_at_heel_floor` が返す。
**0.30 をスキーマ側へ書き写さない** —— 写すと片方だけ直る代理変数になる。

**肩比 −1 で踵の分母が 0 になる。** 手前（−0.99）は段 1〜2 を素通りして
段 3 でソリッドが 2〜3 個に割れ、−1 ちょうどで素の `ZeroDivisionError`。
帯の下限 0.02 があるので UI からは届かないが、`heel_raw` が `-inf` を返して
`outer_layout_error` に理由を言わせるようにした。

**径 3 つの順序は 1 か所が持つ。** `ボア径 < シャンク径 ≤ 最大径`。総当たりで
測った通る範囲は 3 サイズとも端がぴったり相手の値になり、相手を動かすと壁も
同じだけ動く。だから帯（`min`/`max`）は絶対レンジのままにしてある ——
**相手で動く壁は静的な帯では表せない**ので、端が届かないことがあるのは
帯の欠陥ではない。届かないときに黙って丸めず理由を言うのが `hard_*` の役目。

## ボアは肉厚を守っていなかった（Phase 4-E B-3、2026-09-06）

壁の一覧と数字は `docs/param-limits.md`、生ログは
`docs/sweeps/b3-bore-window.txt`。ここには形の側の話だけ書く。

**空洞とボアで同じ法則の掛かり方が違った。** 空洞は `shell_limit` が
`ro − min_wall` に収めるのに、ボアは `mouthpiece._bore_solid` が素の円柱を
引いて引き算するだけ。だから `bore_dia` を上げるとシャンクの肉厚だけが
黙って薄くなり、**肉厚 0（シャンクが丸ごと消える）でも `params_error` は
`None`、OCCT もソリッド 1 個**を返す。soprano の実測で体積は
11776 → 6570mm3（−44%）、肉厚 −1.0mm で 4541mm3（−61%）。

つまり **「ソリッドが 1 個できる」は壁の必要条件でしかない**。掃引器の段 3 は
1 個かどうかと体積 > 100mm3 しか見ないので、この形を通す。いまは
肉厚 ≤ 0 を `outer_layout_error` が弾き、0 と `min_wall` の間は
`shank_warnings` が注意カードに出す（`min_wall` 自身がスライダなので、
そちらを壁にすると黙ったクランプになる）。

**`bore_length` の壁は長さではなく「ボアの始まり」が決めている。** 3 サイズ
とも `bore_start_z` ＝ 6.2 / 6.2 / 6.4mm で窓が 2.0mm を割り、そこが壁。
全長を縮めると壁も同じだけ下がる。`window_length` を上げても**動かない** ——
窓の後端は既に `zb − chamber_to_bore_mm` で頭打ちだから。

**掃引器の打ち切りを壁と読まないこと。** 帯の外へ歩ける距離は段数 × 刻みで、
`bore_dia` は刻み 0.05mm なので既定 40 段では 2.0mm しか出られない
（本当の壁は 3.8〜6.4mm 先）。`--steps` を足した。
