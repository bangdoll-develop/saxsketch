# SaxSketch — 管楽器設計・3Dプリント統合開発環境

サクソフォンを題材に、管楽器とアクセサリ（マウスピース／リード／リガチャー／ネック／本体）を
パラメトリック設計し、設計時の音響シミュレーションを行いながら、3Dプリント入稿データ・
部品表・仕様書までワンストップで生成するローカルWebアプリ。

現在の実装範囲（Phase 0+1）: **サクソフォン マウスピース** の完全な設計〜出力。

## 主な機能

- **パラメトリック設計**: フェイシング（ティップ開き・フェイシング長・カーブ）、バッフル
  （種別・高さ・棚の長さ・段・カーブ量）、チェンバー（スロート断面積比・形状）、ボア、
  ウィンドウ、外形など23項目。各パラメータに音・演奏性への効果を明記。バッフルは
  解説図準拠の**ストレート型／ステップ型／カーブ型**（＋ロールオーバー）を実形状として
  作り分け（既定＝実測 WindyCity のステップ型）。チェンバー断面も4形状
  （ラウンド/スクエア/馬蹄/フラットサイドウォール）を実形状として造形。仕様書に各部名称
  （ティップレール・ランプ・バレル・ウォール等）を掲載。
- **リアルタイム3Dプレビュー**: パラメータ変更 → build123d で形状再生成 → ブラウザに表示。
- **断面エディタ**: ビューアの「断面」タブで中央断面を見ながら、バッフルを**マウスで
  ドラッグして調整**。可動域はサーバ側の形状法則が返すので、形が破綻する値には
  そもそも動かせない（型ごとに有効なハンドルが変わり、型の特徴が保たれる）。
  ドラッグ中は CAD を作り直さない軽量プレビューで即応する。
- **設計時シミュレーション**
  - 音程チェック: 内容積 vs 欠損円錐体積（Benade理論）でセント偏差を推定。
  - 音色レーダー: 明るさ・パワー・抵抗感・柔軟性・エッジを Acta Acustica 2021 の
    知見に基づく回帰モデルで表示。
  - 感度ガイド: 「明るくしたいならこのパラメータを＋」を数値偏微分で常時提案。
  - ゴールシーク: 目標指標からパラメータを逆算（scipy）。差分プレビュー→承認で適用。
  - 音プレビュー: 音色指標から倍音列を合成し Web Audio で即再生。波形＋スペクトル表示、
    A/B聴き比べ。
- **プロジェクト管理**: `.wproj`（ZIP）形式で保存/読込。スキーマバージョン管理・最近使った
  ファイル対応。
- **出力**: STL / STEP / 3MF、部品表(CSV)、仕様書(HTML・断面図SVG付き・印刷推奨条件)、
  入稿パッケージ(ZIP)。オンライン3Dプリントサービスへそのまま渡せる。
- **外部ツール連携**: FreeCAD / スライサーを設定登録し「開く」ボタンで直接起動。
- **外部編集ワークフロー**: パラメータで表現できない個別調整（名入れ・フィレット・
  スカルプト）を FreeCAD / Blender で行い、アプリに再取込。凍結スナップショット・
  水密検査・領域別偏差・**パラメータ逆算**（編集がどのパラメータをどれだけ変えたか
  自動判定）・陳腐化警告つき。→ [docs/manual-edit-workflow.md](docs/manual-edit-workflow.md)

## セットアップ

### 前提ソフトウェア

| ツール | 必要バージョン | 用途 | 確認コマンド |
|---|---|---|---|
| Python | 3.11 以上（開発は 3.12 で検証） | バックエンド・CAD・音響計算 | `python --version` |
| uv | 0.11 以上 | Python仮想環境・依存管理（pip より高速） | `uv --version` |
| Node.js | 20 以上（開発は 24 で検証） | フロントエンドのビルド | `node --version` |
| npm | Node同梱 | フロント依存の取得 | `npm --version` |

uv 未導入の場合は [astral.sh/uv](https://docs.astral.sh/uv/) からインストール（Windowsは
PowerShellで `irm https://astral.sh/uv/install.ps1 | iex`）。uv を使いたくなければ
標準の `python -m venv` + `pip` でも代替可（下記「uvを使わない場合」参照）。

### 手順

プロジェクトルート（`pyproject.toml` のあるフォルダ）で順に実行する。

```powershell
# 1) Python仮想環境を作成（.venv フォルダができる）
uv venv

# 2) バックエンド依存をインストール（build123d, fastapi, scipy, trimesh など）
#    -e = 編集可能インストール（ソース変更が即反映）、[dev] = pytest等も含む
uv pip install -e ".[dev]"

# 3) フロントエンドをビルド（frontend/dist/ が生成される）
cd frontend
npm install          # 初回のみ。node_modules を取得
npm run build        # TypeScriptコンパイル + Viteビルド
cd ..
```

各ステップの意味:
- **1〜2**: `build123d`（CADカーネル OCCT）を含むため、初回は数分かかることがある。
  仮想環境 `.venv/` にすべて入り、システムのPythonは汚さない。
- **3**: サーバは `frontend/dist/` を静的配信する。**ここをビルドしないとUIが表示されない**
  （サーバ起動時にトップページが 404 になる）。フロントのソースを編集したら再度
  `npm run build` するか、後述の開発モードを使う。

### uv を使わない場合

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1        # 仮想環境を有効化（macOS/Linux は source .venv/bin/activate）
pip install -e ".[dev]"
cd frontend; npm install; npm run build; cd ..
```

## 起動

### 通常起動（ビルド済みUIを配信）

```powershell
# 仮想環境のPythonでサーバを起動
.\.venv\Scripts\python.exe -m saxsketch.server.app
```

起動すると `http://127.0.0.1:8712` で待ち受ける。**ブラウザでこのURLを開く**と
アプリが表示される（ローカル専用。外部には公開されない）。

- ポートは `8712` 固定（`saxsketch/server/app.py` の `main()` で変更可）。
- 設定ファイルは `~/.saxsketch/settings.json`（外部ツールのパス・最近使ったファイル・
  既定の出力先）。置き場所は `SAXSKETCH_HOME` で差し替えられる（テストはこれで隔離する）。
- エクスポートの既定出力先は `ドキュメント\SaxSketch\`。設定の「既定の出力先」を
  **空にしておくと環境から自動で決まる**。WSLで動かしている場合は Windows 側の
  ドキュメント（OneDrive へリダイレクトされていればそちら）を使う。サーバは Linux 側に
  居るので、`~/Documents` に置くと Windows のエクスプローラからほぼ辿れない。
- 停止は起動ターミナルで `Ctrl+C`。

初回起動時は「新規プロジェクト」ダイアログが開く。楽器=サクソフォン、サイズ=アルト、
コンポーネント=マウスピースを選んで「作成」で設計を開始できる。

### 開発モード（UIを編集しながら使う）

フロントを編集して即反映したい場合は、サーバとViteの開発サーバを**2つ同時に**起動する。

```powershell
# ターミナル1: バックエンド（APIサーバ）
.\.venv\Scripts\python.exe -m saxsketch.server.app

# ターミナル2: フロント開発サーバ（ホットリロード付き）
cd frontend
npm run dev
```

この場合はブラウザで **Viteが表示するURL（通常 `http://localhost:5173`）** を開く。
`/api` へのリクエストは `vite.config.ts` の proxy 設定で自動的に 8712 のサーバへ転送される。
`.tsx` を保存するとブラウザが自動更新される。

### 動作確認

依存が正しく入っているかは、UIを触る前にテストで確認できる。

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

12件すべて green ならジオメトリ生成・音響計算・プロジェクトI/O・APIが正常。

### つまずきやすい点

- **UIが真っ白 / トップページが404** → `frontend/dist/` が無い。`cd frontend && npm run build`
  を実行し忘れていないか確認。
- **`ModuleNotFoundError: saxsketch`** → 仮想環境のPythonで起動していない。`python` ではなく
  `.\.venv\Scripts\python.exe` を使うか、仮想環境を Activate する。
- **`build123d` のインストールが失敗** → Python が 3.11 以上か確認（`python --version`）。
  32bit Python では動かない。
- **ポート 8712 が使用中** → 別プロセスが占有している。`saxsketch/server/app.py` の
  `port=8712` を変更するか、占有プロセスを終了する。
- **エクスポートの「参照」やプロジェクト保存でダイアログが出ない** → その環境では
  OSのファイルダイアログを出せない（またはサーバが手元の画面を持っていない）。
  **代わりにパス入力欄が出る**ので、そこへ直接入力すれば動作する。
  出せるかどうかはサーバが `GET /api/capabilities` の `native_dialogs` で申告する。
- **ダイアログが出たまま操作できない / UIが固まったように見える** → 直っている。
  以前はサーバのプロセス内で tkinter を呼んでいたため、WSLで動かすと Linux 側の
  ダイアログが WSLg 越しに開き、閉じるまで `POST /api/dialog` が返らなかった。
  いまは**必ず別プロセス**で開き、時間切れ（既定 180 秒）とリクエスト切断の
  どちらでも確実に終了させる。WSL/Windows では Windows ネイティブのダイアログを出す。

## 拡張（新しい楽器の追加）

`saxsketch/instruments/<楽器id>/` を追加するだけ。コアは楽器を知らない。

- `descriptor.json` … 楽器の物理定数（調・欠損円錐体積・ネック寸法・リード規格）
- `templates/*.json` … サイズテンプレート（パラメータ初期値）
- `components/` … `Component` 派生クラス（`COMPONENTS` dict で公開）

## アーキテクチャ

- `saxsketch/core/` … スキーマエンジン・プロジェクトI/O・プラグインレジストリ
- `saxsketch/geometry/` … build123d 共通ビルダー
- `saxsketch/acoustics/` … 音程・音色・感度・ゴールシーク・倍音
- `saxsketch/export/` … モデル/BOM/仕様書/入稿パッケージ
- `saxsketch/server/` … FastAPI
- `frontend/` … React + TypeScript + Three.js（日本語UI）

## ロードマップ

- Phase 2: OpenWind 統合（マウスピースのインピーダンス表示・物理モデル音合成）
- Phase 3: リード・リガチャー（マウスピース外形と自動整合）
- Phase 4-A: 採寸ワークフロー（実物の実測をプロジェクト局所で反映・復元点つき）✔
  - 実物3mf/STLから外形寸法（全長・ボディ径・シャンク内径）を自動測定して採寸へ流し込み ✔
  - 外部編集ツール（FreeCAD）の自動起動（Windows側インストールを自動検出・WSL連携）✔
  - 外部（市販完成品など本アプリ非由来）の3mf/STL/STEPを凍結なしで読込→整列して3D表示・
    外形採寸・入稿STLに登録。差分/逆算はしない（座標系・内部形状が別物のため）。継続編集は
    FreeCADで元ファイルを開いて往復 ✔
  - 別座標系の無関係メッシュを誤取込しても領域偏差計算がハングしないよう厳密計算に上限 ✔
- Phase 4-B: ネック・キーレス管体（トーンホール設計・造形サイズ自動分割）※スライス分割で実装
  - 4-B.1 ネック（円錐ボア＋グースネック曲げ＋オクターブベント。マウスピース適合を
    descriptor 定数で自動検証。ストレート/ベント・ベント有無を選択可。採寸・FreeCAD往復・
    STL/STEP/3MF出力は既存の汎用経路を再利用）✔
    - 正直な範囲: オクターブ**キー機構は非実装**（ベント孔幾何のみ・奏者が塞ぐ/プラグ前提）。
      ボアテーパは直線円錐近似で音程は近似（採寸校正で実物へ寄せる）。長尺の自動分割は 4-B.3。
    - 前方互換: パッド座平坦化＋キー取付ボス（既定OFF）で後段のオクターブキー機構(4-B.4)を
      ネック再設計なしに載せられる。キー機構は印刷剛体パーツ＋購入品（パッド/バネ/軸）で構成予定。
  - 4-B.2 キーレス管体＋トーンホール ※さらに 3 分割
    - 4-B.2a 管体の幾何（円錐管＋ボウ＋ベル＋**ネック一体型**）✔
      - **ネックの繋ぎ方を 2 通り持つ**: `separate`（別体・既定）と `integrated`
        （ネックまで 1 部品）。後者はストレートソプラノに多い実機の作り。
        **音響はどちらでも同じ** —— 共鳴管はマウスピース→円筒ボア→欠損円錐で
        「ネック」という区間を持たないので、継ぎ目もテノンもモデルに入っていない
        （3 サイズで気柱のビット一致をテストで固定）。実利は継手が 1 つ減ること
        （印刷品でいちばん気密が出ないのが継手）。代償は**姿勢を調整できない**こと
        （実機のネックは回して銜え角を合わせる）と、壊れたら全部作り直しになること。
      - **落とし穴**: 「一体型」と「ネック省略」は別物。後者は円錐の先端側が消えて
        soprano +355 / alto +346 / tenor +289 セント上がる＝別の楽器。円錐リーチの
        カードが警告する。
      - 正直な範囲: **トーンホールは無い**（2b/2c）。**ベルのフレアは 3 サイズとも
        未実測**なので**音響へ接続していない** —— 接続すると全閉の第1共鳴が
        +38〜+106 セント動く（`cad/body/README.md` の測定）。共鳴管は校正済みの
        直線円錐のまま。曲げの音程への影響も未実装（弧長近似）。分割は 4-B.3。
      - **どの構成でも 1 パーツでは印刷できない**（弧長 502〜1378mm）。一体型に
        したから分割が要るのではなく、別体でも要る。
    - 4-B.2a' 後始末: **1 つの楽器に円錐は 1 本**にした ✔
      - ネックだけ `cone_half_angle_deg` の生値を使っており、頂点距離の値を持つ
        **アルトだけ 4.52% 食い違って**いた（別体では継ぎ目の気柱に φ0.56 の段）。
        `neck_profiles` も `volume.missing_cone` を読むようにした。まずいのは
        「アルトが急なこと」ではなく**食い違いが物理ではなくデータの有無で
        決まっていた**こと —— ソプラノに頂点距離が入った日に黙って壊れる規則だった。
        **音響の記録値は 1 つも動かない**（共鳴管はネックの幾何を読んでいない）。
      - **曲げネックの肩が段になっていなかった**（alto 5.6mm / tenor 6.4mm の
        スロープ）。ストレート経路だけが段差の位置を持っていたため、同じ
        パラメータで曲げ角 0 と 24° から違う形が出ていた。肩の定義を 1 か所に。
      - **`missing_cone_length_mm` 217.5 は出典未記録の借り物**と分かった（出所を
        追うと descriptor の一文で終わる）。代わりの半頂角 1.6° も補間なので
        **借り物 A vs 借り物 B**。落としても判定は動かない（アルトの `in_tune_mm`
        13.58→11.58mm、実用域の内側で ok のまま）と測ったうえで**値は動かさず**、
        出所の弱さだけ記録した。決着させる実測は 1 つ —— アルトのネック大端内径
        （予測 φ25.5 vs φ25.0、差 0.56mm）。詳細は `cad/body/README.md`。
    - 4-B.2b 側孔をソルバへ通す（TMM に分岐インピーダンス／OpenWind の
      `holes_valves`）。現状の `openwind_bridge` は側孔をまったく持たないので、
      穴位置を解く前にここが要る
    - 4-B.2c 穴位置を解く（運指表＋指の届く拘束＋チムニー高さで合わせる）
  - 4-B.3 造形サイズ自動分割（軸方向分割＋接合＋ビルドボリューム設定）
  - 4-B.4 オクターブキー機構（印刷剛体パーツ＋購入品BOM）
- Phase 4-C: マウスピース／リード／リガチャーの設計バラエティと寸法表示 ※5スライス
  - 4-C.1 マウスピース外形をハンドルで歪められるようにした ✔
    - **最大径は「頂点」**。外形を歪める 2 つ（`body_waist` / `shoulder_fullness`）は
      この境を跨がず、頂点の半径も動かさない（動かすのは `body_dia` だけ）。
      崩れると肩を触っただけでテーブル平面の基準とリガチャー座が動くので、
      **前後の分離はビット一致でテストに固定**してある。STEP の補間も頂点で切る。
    - **円錐シャンクが作れる**（最大径からシャンク端まで一直線）。「肩の終わり」
      ハンドルは `shank_length` と `shoulder_ratio` を**連動して**書き、
      最大径の位置を保ったまま平行部だけ 0 まで縮められる。従属側を step へ
      丸めると最大径が 0.13〜0.17mm 動くので、丸めるのは主キーだけ。
    - **最大径の上限は判定カード**（`ParamSpec.max` にしない）。上限は
      マウスピースの最大径ではなく**リガチャー側の受け容量**で、alto 29.0 /
      tenor 30.0 / soprano は基準機が未実測なので判定しない。基準機自身が
      上限を超えている（alto +0.1 / tenor +0.8）ので硬い上限にすると
      テンプレートの実測値が読み込み時に黙ってクランプされる。
  - 4-C.2 リード: カマボコ断面（ケーン円弧）と先端カーブ ✔
    - **断面はカマボコ**。上面は「削り面」と「元のケーン管の円弧」の低いほう
      （`min`）。実物の作りそのもので、円弧が勝つのはヴァンプの後ろ半分から。
      材料体積が **16〜18% 減る**。円弧は `heel_edge_thickness`（**未実測**）で
      決まり、**どの照合カードの判定にも入らない** —— 外れても判定は汚れない。
    - **断面が厚みの法則そのものになった**。旧実装は角丸長方形で近似していて、
      印刷される形が**先端断面で 15% 太かった**（BOM と剛性が読む法則と別物）。
      いまは `thickness(p, z, x)` を 19 点で直接追う（誤差 0.10%）。
    - **前縁はティップレールに沿う曲線**。`profiles.tip_contour_z` で解くと角は
      中央より 1.27〜1.57mm 後ろで、直線の前縁はそのぶん前へ張り出していた。
      円弧では輪郭に 0.1mm より近づけない（実物の輪郭は真円ではない）ので、
      適合カードは**数字を出すだけで自動追従はしない**（市販リードは規格品）。
    - **硬さモデルの荷重幅を代理変数から外した**。等分布荷重を `width(p, 0)` で
      取っていたので、前縁カーブを入れると z=0 が尖点になって荷重が 1/27 に落ち、
      硬さが上限 20.0 へ振り切れた。先端の実効幅で取る（カーブ 0 でビット一致）。
    - **ブランクは管に収まらないと弾く**（`params_error`）。幅が管を超えると円弧が
      テーブル面より下へ潜って断面が裏返る（掃引で発見）。
  - 4-C.2b リード: 先端の平面視輪郭を 1 本の曲線にした ✔（ユーザーが 3D ビューで
    「前縁から平たいヒレが出る」と報告）
    - **`if 0.0 < z < d` が z=0 を除いていた**。最先端の断面だけ前縁カーブが効かず
      全幅（11.5/11.8/13.0）のまま残り、次のステーション（5.1〜5.9）へ**後ろ向きに
      絞られて**厚さ 0.4mm の板が前へ張り出していた（輪郭の垂直ずれ 2.3〜2.7mm）。
      **既定値でも出ていた。** 掃引が見ていたソリッド数・水密・bbox・頂点数は
      全部通るので素通りした（bbox は幅が正しい側を拾う）。
    - **角の丸みが円弧の後ろに積まれていた**。輪郭が「円弧 → 平行帯 → 傾きの跳び
      （0.004→5.57）→ 2 つめの膨らみ」の 4 区間に割れ、全幅に達するのが `d` では
      なく `d + tip_corner_r` だった。適合カードが使う `front_edge_z` も純円弧
      だったので、実際に印刷される輪郭と角で 0.28〜0.56mm 食い違っていた。
    - いまは**前縁アークと側面の両方に内接する円 1 個**でフィレットする。R ≥
      先端半幅 が恒等的に成り立つので解は常に存在し、`params_error` は要らない。
      **`tip_curve_depth = 0` は幅も断面もステーションもビット単位で不変。**
    - **1 つめのバグが 2 つめを覆い隠していた**。`reed_override` の `width_mm`
      （OpenWind のリード流路幅）も `width(p, 0.0)` を読んでいて、z=0 が漏れて
      いたおかげで**たまたま正しい値**を返していた。直すと 0.5mm へ潰れて合成音が
      純正弦になる。`tip_load_width` へ差し替え（3 サイズとも旧値と厳密一致）。
    - 記録値はほぼ不変（f_reed −0.015〜−0.029% / 材料体積 ±0.00%）。

  - 4-C.4 リガチャー: 参照マウスピースの重ね表示
