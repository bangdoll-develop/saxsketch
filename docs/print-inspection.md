# 実製作品の検品 — 届いた実物を測って設計へ返す

3Dプリントに出したマウスピースが届いたとき、**何を・どう測り・何と比べるか**を
先に決めておくためのシート。初回は 2026-08-23、アルト `AltoSaxSetTrial1.wproj`。

このシートの数値は**すべて対象の `.wproj` から計算したもの**で、手写しではない
（再計算の手順は末尾「数値の再生成」）。設計を変えたら作り直すこと。

図は `cad/windycity/measure_alto.svg`（どの寸法がどこか）を併せて見る。

## 0. 大前提 — なぜ印刷品だけでは足りないか

**印刷品を測って設計値と違っても、原因がプリンタか設計かは分からない。**

アルトのテンプレートで**実測に基づくのは 3 点だけだった**（Wood Stone PHROX を
ノギスで実測、2026-08-13）:

    全長 91.7 / ボア内径 15.8 / 最大径 29.1

残りは比で引いた推定値。軸方向の `bore_length` `window_length` `tip_rail_width` は
軸比 0.8530、径方向の `shank_dia` `beak_height` `side_rail_width` `baffle_height`
`rollover_radius` `tip_rail_thickness` `tip_chamfer` は径比 0.9167 を掛けただけ
（出所はテンプレート `alto.json` の `note`）。

> **【2026-09-05】実測は 5 点になった。** 径比 0.9167 の群のうち
> **ノギスが入る 2 つ**（`shank_dia` 23.20 / `beak_height` 11.60）を PHROX で測って
> テンプレートへ入れた。**2 つとも外れ、しかも逆向き**（+10.0% / −13.0%）——
> **径比という前提そのものが壊れた**（§11.3）。残る 5 つは 0.9167 のままだが、
> **どれもノギスが入らない量で、根拠は無い**。

だから **同じ手順で PHROX も測る**。3 列にすると差が分かれる:

| 差 | 意味 |
|---|---|
| 印刷品 − 設計値 | **印刷側**の誤差（収縮補正・積層・後処理） |
| PHROX − 設計値 | **設計側**の誤差（比で引いた推定値の外れ） |
| 印刷品 − PHROX | 実物同士の差。吹き比べの結果と直接つながる |

**実測は組で入れること。** 1 点だけ入れると、実在しない不足を記録することがある
（アルトのリード全長だけ先に入れて、テナーから借りたシャンク比 28% 過大が
判定を汚しかけた。2026-08-15）。

**結果（2026-09-02 / 09-05）: この 3 列がそのまま効いた。** 印刷品は 6 項目とも
一致帯（最大 +0.28mm）、外れたのは **PHROX − 設計値**のほう ——
**比で引いた 3 量（シャンク径 +2.12 / 窓の後縁 +3.60 / ビーク高さ −1.74）だけ**が
帯を大きく超えた。§11 を見ること。
（7 項目目のティップ端→窓の後縁は印刷品では**符号が割れた** —— 2 回の読みが
−0.45 と +0.65 で、幅 1.10mm が一致帯より広い。判定は出していない。§5.3）
なお**もともとの実測 3 点は動かしていない**（再測との差が 0.1〜0.3mm で、
動かすと軸比が連れて動くため据え置き。§11.1）。増えた 2 点は別の量。

**そして `bore_length` が決着した（2026-09-05 朝）。**
PHROX の**ティップ端 → 窓の後縁** 39.4mm。予想は「40 付近なら窓は本当に長く
`bore_length` が誤り、36 付近なら測っていた量が違っただけ」で、**40 側**。
**ノギスと幾何だけで、奏者は 1 ビットも入っていない。**
テンプレートを組で更新した —— `window_length` 35.02 → **38.67** /
`bore_length` 49.05 → **48.30** / `cork_depth` 13.61 → **17.45**（§11.4）。

> **【2026-09-05 昼・修正】その更新でティップ形状が壊れた。** 新規作成した
> 既定アルトの先端で空洞高さが **0.60 → 4.44mm** に開き、ティップレールの
> 薄いくさびが消えた（利用者が 3D ビューで発見。§11.11）。**実測は正しく、
> 壊れていたのはモデルの側** —— `cavity_floor_y` が実測の床曲線を**振幅方向の
> アフィン**で端条件に合わせており、その係数が「窓の後端がボアに近づく」ほど
> 発散していた。3 サイズはたまたま特異点から離れた所に揃って載っていただけで、
> **アルトの実測がそこから外れた瞬間に露出した**。σ を写像する式へ直し、
> `cork_depth` を 17.45 → **14.38** へ引き直した。**`window_length` と
> `bore_length` の実測値は 1 つも変えていない。**

> **【2026-09-05 朝・撤回】** その決着とは別に、前便の見出しは撤回する。
> ここには「挿し込み量が **3mm** 違い、それが **`bore_length` の逆算値と
> 0.06mm で一致した**」と書いていた。**その 3mm は目視の申告で、実測は
> 6.0mm ＝ 2 倍だった**（印刷品 35.4 / PHROX 29.4、§11.7）。しかも実測者の
> 説明で、その位置が**音程の一致点ではない**ことも分かった。
> **吹奏は逆算に使えない。** 決着させたのは窓のほう。
> **申告を測定として扱ったのが誤り。**「くらい」が付いた数字は測定ではない。

## 2. 道具と分解能 — 測る前に読む

手持ちは **ノギス 0.05mm** と **チューナー＋アルト実機**、そして基準実物 PHROX。

- ノギス 1 回の読みの不確かさは **±0.05mm 級**。
  **0.1mm 未満の差は「差がある」と言ってはいけない。**
- **完璧なプリンタでも印刷品は設計値より細く出る。** STL は多角形近似だから。
  ただし**この個体は実測で 0.0055〜0.0183mm 内側**（**直径で 0.011〜0.037mm**）で、
  ノギス 1 目盛りの 1/3 以下。**ノギスで見えるずれが出たら、原因はメッシュではなく
  プリンタ側**（収縮補正・露光・後処理）と断定してよい。
  → **この「細く出る」は外れた**（実測は **7 項目とも**太い側。§11.2）。
  ただし後半の断定 —— ずれの出所はメッシュではなくプリンタ側 —— は成立している。
- 判定帯は SaxSketch の採寸カードと同じ規則を使う
  （`mouthpiece.survey_card`: 一致 `max(0.6·step, 0.05)` / 軽微 `max(2.5·step, 0.2)`）。
  **新しいしきい値は作らない。**

## 4. 測り方の落とし穴（実際に間違える 3 つ）

**① ボディ径はテーブルと平行に測る。**
最大径の位置 z=70.30 では**テーブルのカットがまだ生きている**（カットが胴から
外れるのは z=73.04）。テーブル面から反対側へノギスを当てると **27.12mm** しか
出ない。正解は横（テーブルと平行）に当てて **29.10**。
**差 1.98mm** ——間違えると「2mm 小さい」という誤報になる。

**② ウィンドウ長の起点はティップではない。**
窓の前縁はティップレールの後ろ、ティップから 0.73mm の位置。設計値 35.02 は
**窓の開口そのものの長さ**（ティップから 0.73 → 35.75）。

**③ 軸方向の基準が 2 つある。**
`facing_length` `window_length` は**ティップから**、
`bore_length` `cork_depth` `shank_length` は**シャンク端から**。
図（`measure_alto.svg`）も寸法線の向きでそれが読めるように描き分けてある。

## 5. いま測れないもの — と、それを開ける道具

**測れないのは「どう鳴るか」を決めている 3 つ**: ティップ開き・フェイシング長・
フェイシングカーブ。**隙間ゲージ（シックネスゲージ）1 本**で全部測れる。

設計カーブは算出済み。ガラス平面をテーブルに当て、ティップ側から隙間ゲージを
差し込んで**止まった位置をティップから測る**:

| 隙間 [mm] | ティップからの距離 [mm] |
|---|---|
| 0.05 | 19.66 |
| 0.10 | 18.28 |
| 0.15 | 17.22 |
| 0.20 | 16.33 |
| 0.30 | 14.83 |
| 0.50 | 12.46 |
| 0.75 | 10.09 |
| 1.00 | 8.11 |
| 1.50 | 4.78 |
| 2.00 | 1.98 |
| 2.40 | 0.00（＝ティップ開き） |

（`profiles.facing_rise` の円弧カーブを反転して算出。`facing_curve: radial`、
`facing_length` 23.0、`tip_opening` 2.4）

**隙間ゲージが無いあいだの代用**: ガラス板にテーブルを伏せて置き、ティップが
浮いた量をノギスの段差測定で読む（設計 2.40mm）。実力 ±0.1mm 程度で一致帯 0.05 には
届かないが、**0.3mm 級の異常なら捕まる**。

### 5.1 ビーク高さ — **精密なマークは要らない**（**測った。§11.3**）

> **測定済み（2026-09-05）**: 印刷品 **13.60** / PHROX **11.60**。
> **この手順はそのまま使えた** —— 印刷品が設計 13.34 に対し **+0.26**（一致帯の内）
> で出た＝手順がモデルを再現している。だから PHROX の **−1.74** は
> ランドマークの取り違えではなく**実物の差**（ウィンドウ長と違ってここは確定できる）。
> 結論は §11.3。

**測る前の動機**（そのまま残す）: `beak_height` は
**径比 0.9167 で引いた 7 つの推定値の 1 つ**で、当時はそのうち
**シャンク径だけが実測で 2.12mm 外れていた**。ビーク高さは 7 つのうち
**ノギスで測れる唯一の残り**なので、**比の当否を決める 2 点目**だった。

定義は「**バイトポイント z=22.925（=0.25 × 全長）での、テーブル平面から
ビーク稜線までの高さ**」（`profiles.beak_angle`）。

**位置決めの精度要求は緩い。** 稜線の傾きは **19.49°（tan 0.354）**:

| z の位置決め | 高さのずれ | 判定 |
|---|---|---|
| ±0.85 mm | ±0.30 | 一致帯に収まる |
| ±3.53 mm | ±1.25 | 軽微帯に収まる |

しかも z=22.925 は **`facing_length` 23.0 ＝ テーブル平坦部の始まり**とほぼ同じ位置
（差 **0.075mm**）。実物に見える landmark がある。

**手順（ノギス 1 本・傷を付けない）**:

1. ノギスを **22.9mm でロック**。固定ジョウをティップ端面に突き当てると、
   可動ジョウの内側面が z=22.9 の平面になる
2. その面に**和紙マスキングテープの縁**を合わせる。貼るのは**ビーク上面だけ**
   —— **テーブル面とティップレールには貼らない**（§8 で見る面。剥離で傷むと
   以後の測定に効く）。テープ厚 0.09mm は**縁の位置しか使わないので効かない**
3. テープの縁でノギスを当て直し、**テーブル平面 → ビーク稜線**を読む。稜線は凸なので
   **x 方向は自己中心化する**（最大を読む）
4. **当てる向きは軸に垂直**（テーブル面には 4.18° 傾く）。差は cos 4.18° で
   **0.036mm** ＝分解能以下なので、どちらでも判定は変わらない

**却下した 2 案**（同じ回り道をしないため）:

- **2 点測って傾きから逆算** —— 稜線の直線区間は z≲30 しかなく基線が 15mm。
  各点 ±1mm が 9.4% の傾き誤差になって **beak_height ±0.92mm**。1 点法より悪い
- **奥で測って位置決めを避ける** —— 感度が消える。`d高さ/d beak_height` は
  z=22.9 で 1.000、z=35 で 0.729、**z=40 以降は 0.000**（胴に合流して
  `beak_height` の情報が無い）。使えるのは z≲31 だけ

**測る価値**（テナー実測 14.55 に各比を掛けた予測）—— **この表は外れた**:

| 比の出所 | 予測 | 現行との差 | 見分け |
|---|---|---|---|
| 径比 0.9165（**現行・借り物**） | 13.34 | — | — |

### 5.2 窓の決着（**1 点測れば済む** —— 済んだ）

§11 のとおり **PHROX の窓は設計より長い**が、**窓の形が違う**（印刷品は角の立った
矩形、PHROX は角丸のスロット。§11.5）ので、同じ量を測ったか分からなかった。
決着には **ティップ端から窓の後縁までの距離**を両方で測る
（1 本の値でよい。窓の前縁は 0.73mm しかなく分解能で測れない）:

    設計値 35.75 mm（= tip_rail_width 0.73 + window_length 35.02）

PHROX が **40 付近**なら「窓は本当に長い」が確定し、`bore_length` 49.05 の
矛盾（§11）が本物になる。**36 付近**なら測っていた量が違っただけ。

**開口長（`window_length`）との違い**（実測者からの質問への回答）:

    窓の開口長          35.02 = 窓の**前縁**から後縁まで
    ティップ端→窓の後縁  35.75 = **ティップ端**から後縁まで
    差 = tip_rail_width 0.73（窓の前縁はティップから 0.73mm 後ろ）

**同じ窓を、起点だけ変えて測っている。** 起点をティップ端に置くのは、
前縁がティップレールの後ろ側の稜で、幅 0.73mm の面のどこを取るかがノギスでは
決まらないから。**ティップ端は 1 本の稜なので迷わない。**

**記入 —— 同じ量を 2 回ずつ測ってある（09-02 / 09-05）:**

| | 設計 | 09-02 | 09-05 | 平均 | 幅 | 設計との差 | 判定 |
|---|---|---|---|---|---|---|---|
| 印刷品 | 35.75 | 35.30 | 36.40 | 35.85 | **1.10** | +0.10 | **—** |
| **PHROX** | 35.75 | 39.30 | 39.40 | **39.35** | 0.10 | **+3.60** | **外れ** |

> **決着した。PHROX は 40 側。** 窓は本当に長く、**`bore_length` 49.05 は
> 幾何として成立しない**（§11.4）。**奏者が 1 ビットも入っていない測定**で決まった。
> 前便でここに書いた「吹奏の 3mm と 0.06mm で一致したので優先度が上がった」は
> 撤回済み（実測は 6.0mm。§0 / §11.4）。

**印刷品のほうは判定を出していない。** 2 回の読みの幅 1.10mm が一致帯 ±0.30 より
広く、**符号まで割れている**（−0.45 と +0.65）。**1 回の読みを想定した帯を、
幅のある量に当てると持っていない分解能で合否を言うことになる。**

### 5.3 なぜ「窓の開口長」を測らないか（と、撤回したこと）

    窓の開口長          35.02 = 窓の**前縁**から後縁まで
    ティップ端→窓の後縁 35.75 = **ティップ端**から後縁まで
    差 = tip_rail_width 0.73

**前縁はティップレールの後ろ側の稜で、幅 0.73mm の面のどこを取るかがノギスでは
決まらない。** ティップ端は 1 本の稜なので迷わない。だから測るのは後者だけで、
**`window_length` は 1 度も測っていない**（テンプレートへ入れる値は
ティップ端→窓の後縁 39.40 から `tip_rail_width` 0.73 を引いた 38.67。
**その 0.73 は設計値の流用**で、PHROX のティップレール幅は未測）。

> **【2026-09-05 朝・撤回】** ここには「**測れない `tip_rail_width` が、
> ティップ端→窓の後縁 36.40 と窓の開口長 35.30 の差 1.10 として出る**」と
> 書いていた。**その 35.30 は開口長ではなく、同じティップ端→窓の後縁だった**
> （実測者に確認）。つまり 1.10 は**別々の量の差ではなく、同じ量の再測のばらつき**。
> **測れない量は測れないままで、増えたのは「印刷品の読みには 1.10mm の幅がある」
> という事実のほう。**

**PHROX のばらつきは 0.10、印刷品は 1.10。** 印刷品の窓は角の立った矩形、
PHROX は角丸のスロット（§11.5）なので、**形から予想される向きと逆**。理由は未解明。
**次に測るときは同じ日に続けて 3 回。**

**写真は読みを裏づけるが、ランドマークは裏づけない。** `print_DSC_2001` は
ノギスをロックして横に置いた構図で、**ジョウが測定点に当たっている像ではない**。
縮小フレームでは 0.1mm も読めない。**どの 2 点を測ったかの出所は実測者の申告 1 つ**
—— 欠陥ではなく、写真という道具の分解能。**この撤回もそこから来ている。**

## 7. 吹奏テスト — **PHROX との A/B が本体**

モデルの予測:

    25°C で第1共鳴が D♭3 138.59Hz に合う挿し込み量  13.58mm
    感度                                          0.49 セント/mm
    実用域                                        3.0 〜 36.4mm

**この 0.49 は全閉最低音の値。チューニング音には使えない。**

> **【2026-09-05 訂正】** ここには「0.49 セント/mm ということは、10mm ずれても
> 5 セントにしかならない」と書いていた。**1 桁外している。**
> `openwind_bridge._assemble_resonator` はトーンホールを持たず、
> 空洞＋円筒ボア＋欠損円錐延長の 1 本しか組まない。だから 0.49 は
> **D♭3 138.59Hz（全閉）の感度**で、チューニングする音の感度ではない。
> 感度は 1/L で伸びるので **チューニング音は 3.2 倍敏感**（§11.8）。
> 10mm なら **16 セント**（モデル基準）〜 **44 セント**（1/L 則）。
> **絶対位置が弱い指標だという結論は変わらない** —— 理由が違っただけで、
> 挿し込み量を記録しない限り解釈できないことに変わりはない（§11.6 の訂正）。

しかも Tier1 の note が明記しているとおり、この値は**基準条件のもので
リード・リガチャー・アンブシュアを含まない**。

だから **同じネック・同じリード・同じリガチャー・同じ日に PHROX と交互に吹き、
差を記録する**。差ならモデルに入っていない要素の大半が相殺する。

記録するもの:

**記入 2026-09-05**（ネック Yamaha YAS-875 付属。**同じ日に交互に吹いた**）:

| 項目 | 印刷品 | PHROX |
|---|---|---|
| リード（銘柄・番手・材質） | **レジェール スタジオカット 2¼**（樹脂） | **同じ** |
| リガチャー | **ウッドストーン メイヤー用 GP** | **同じ** |
| チューナー基準（A=◯Hz） | **442** | **442** |
| 室温 | 未記録 | 未記録 |
| 音が合ったときの挿し込み量 [mm] | **35.4**（2 回の読み・09-05 朝） | **29.4**（同） |
| 低音域のずれ [cent] | 未記録 | 未記録 |
| 中音域のずれ [cent] | 未記録 | 未記録 |
| オクターブ上のずれ [cent] | 未記録 | 未記録 |
| 発音（出るか・詰まるか） | **出る**（録音あり。§11.6） | **出る**（同） |
| 抵抗感（軽い / 重い） | 未記録 | 未記録 |
| 篏合の手応え | **PHROX と同じ位置までより小さい力**（§6） | 基準 |

**A/B が実測で 1 行取れた** —— 挿し込み量の差 **6.0mm**（印刷品のほうが奥）。

> **【2026-09-05 朝・撤回】** ここには「差 **3mm**。これがモデルの `bore_length`
> 逆算と **0.06mm で一致**した」と書いていた。**3mm は前夜の目視の申告**で、
> 翌朝ノギスで測ると **6.0mm ＝ 2 倍**だった。一致は偶然（§0 / §11.4）。

**この 2 つの値は「音程が一致する位置」ではない。** 実測者の条件をそのまま残す ——

> アンブシュアが完璧に同一になることはなく、音程も完全一致したものではない。
> リードの位置・リガチャーの固定状態から周囲の体感気温、管体の温度、自身の体調から
> **この辺の位置で合わせておけば演奏時間中最も音程が安定するだろうという位置に
> 経験的に合わせている**（もちろんメーターを目視しながら）。

**つまり 6.0mm は「奏者が落ち着けた点の差」で、残差の音程差は未記録。**
逆算の入力に使うときはこの条件ごと引用する。一方で**チューナーを見ながら**
決めているので、音程と無関係でもない。

**録音は 4 本になった**（09-02 に印刷品 2 本、09-05 朝に PHROX と印刷品を 1 本ずつ）。
**PHROX 側が入ったが、4 本中 3 本がクリップして倍音比が出ない。** 数値は §11.6。

**挿し込み量の測り方**: 音が合った位置でネックのコルクに印を付け、外してから
印〜ネック小端の距離をノギスで測る。これが `cork_depth`（＝ネックがボアへ
入っている長さ）と同じ量で、上限 36.4mm もこの測り方の実測値。

### 11.2 印刷側は健全。ただし**符号が揃っている**

6 項目とも一致帯、最大 +0.28mm。**プリンタは設計を忠実に出している。**

ただし **6 つとも差がプラス**
（+0.20 / +0.00 / +0.02 / +0.10 / +0.28 / +0.26）。
第2便のビーク高さ（+0.26）も同じ側に乗った。
§2 は「完璧なプリンタでも印刷品は設計値より細く出る」（メッシュ多角形近似で
直径 0.011〜0.037mm 内側）と予想していたが、**向きが逆で、しかも一桁大きい**。

つまり**§2 の予想は外れた**（外れたこと自体を残す。予想はメッシュのぶんしか
考えていなかった）。0.1mm 級なので判定には効かないが、偶然ではない。候補は
光造形の**露光ブリード**（硬化が設計輪郭より外へ滲む）か**収縮補正の過剰**、
あるいはノギスの当て圧。**6/6 はもう偶然として扱わない。**
ただし**ビーク高さは径ではなく高さ**（テーブル面からの立ち上がり）で、
径の膨らみとは別の量。同じ向きに乗ったことは「外側へ一様に太る」で説明できる。
**次の個体でも同じ向きなら補正の話になる。**

> **【2026-09-05 朝】ここは一度 7/7 と書いて、戻した。**

> 実効容積の 1.5%。**チェンバー形状の差だけでも出る量**」と書いていた。
> 6.0mm でも容積では 0.32cc ＝ **2.9%** と小さいが、**モデルのチェンバー系の
> つまみでは作れない** —— `chamber_ratio` の既定 1.00 は**可動域の下限**で、
> モデルは PHROX のチェンバーをこれ以上小さくできない。
> **言えるのは「モデルの表現力の外」まで**で、実物のチェンバーが作れないという
> 意味ではない（可動域が狭いのかもしれない）。

**モデルは差を −2.71mm と言っている —— 符号すら逆。**

```
印刷品（実測形状） in_tune 14.05 / PHROX（実測形状） in_tune 16.76 → モデルの差 -2.71mm
実測の差 +6.00mm（印刷品 35.4 / PHROX 29.4）
```

実測は「印刷品のほうが 6.0mm **奥**」、モデルは「印刷品のほうが 2.7mm **手前**」。
**大きさが足りないのではなく、向きが合っていない。**
窓の実測を入れても向きは直らなかった（入れる前は −1.21mm）。

**音が違っても mm どうしで比べてよい。** モデルが解いているのは全閉最低音、
実測者が合わせたのはチューニング音（§11.8）。だが形状差が作るセントも
挿し込みが作るセントも**同じ 1/L で伸びる**ので、割り算した
**「何 mm 押し込めば埋まるか」は音に依らない**。セントで比べていたら
音を揃えないと意味がない。**この議論は第3便でも傷んでいない。**

**決着させたのは幾何のほうだけ。** 窓の後縁 39.40 が要求する上限
`bore_length` ≤ 48.30 は**音を 1 ビットも使っていない**。
**崩れたのは「吹奏がそれを裏づけた」という主張だけで、矛盾そのものは本物だった。**

**そして吹奏はもう逆算に使えない。** 35.4 / 29.4 は「音程が一致する位置」ではなく
**実測者が演奏中いちばん安定すると判断した位置**（§7 に原文）。
残差の音程差は記録されていない。

**`bore_length` は 48.30 へ動かした。ただし上限であって点推定ではない。**
実物の PHROX のボアがちょうど 48.30 だという証拠は無い —— **これより短い可能性は
残っている**（そのときは窓の後端とボアの始まりの余地が 4.0mm より広い）。
**「実測と両立する最大値」を採った**のは、それより小さい値に根拠が無いから。
次に効くのは §11.10 ①。

### 11.6 録音 —— **絶対音程は本当に弱い指標だった**

4 本ともリード レジェール スタジオカット 2¼ / リガチャー ウッドストーン メイヤー用 GP。

**4 本とも `--a4 442` で出し直した**（09-02 の 2 本は基準が未記録なので、
当初は 440 と仮定して +11.3 / +0.4 ¢ と書いていた。**基準は中央値を平行移動する
だけなので、下の「差」はどちらの基準でも同じ**）。

|---|---|---|---|---|
| マウスピース | 印刷品 | 印刷品 | **PHROX** | **印刷品** |

| 音数 | 95 | 48 | 114 | 105 |
| 実音の範囲 | C#3 140.8 〜 A5 871.4Hz | E3 163.9 〜 B4 497.2Hz | B♭2 117.3 〜 C6 1063.5Hz | C3 130.7 〜 C6 1024.1Hz |

**組の中の差**: 09-02 の 2 本（**同じ印刷品どうし**）が **10.8 ¢**、
09-05 の 2 本（**PHROX − 印刷品**）が **8.8 ¢**。

**A/B は録音では取れなかった。** 理由は 3 つ、どれも単独で致命:

- **4 本中 3 本がクリップ**（0.85 / 0.65 / 1.75%、いずれも `CLIP_LIMIT` 0.05% の
  13〜35 倍）。**倍音比が出ない** —— クリップが作る高次倍音とマウスピースの
  倍音は区別できないので、道具は数値を出さずに黙る
- **中央値の差 8.8 ¢ は奏者ノイズの内側。** 同じマウスピース・同じ日・5 分差の
  2 本が **10.8 ¢** 違っている（下）。**8.8 < 10.8** ——
  **マウスピースを替えた差が、替えなかった差より小さい**
- **吹いた音域が違う**（B♭2〜C6 対 C3〜C6）。同じ旋律ではない

**録音から言えるのは「両方吹けて 442 に合う」まで。**

**印刷品は吹けて、チューニングも合う。** 後の 1 本は平均律に対し中央 **+0.4 セント**
（音ごとの散らばりは絶対値中央 7.5 セント）。**2.6 オクターブ出ている**ので
レジスタも通っている。§7 の「発音」は○。

**そして絶対音程が弱い指標であることが数字で出た。** 同じマウスピース・同じリード・
同じリガチャーで **5 分差の 2 本が 10.8 ¢ 違う**（A=442 基準で +3.4 と −7.4。
当初は基準を 440 と仮定して +11.3 と +0.4 と書いていた ——
**基準を変えても差は動かない**）。

> **【2026-09-05 訂正】** ここには当初「差 10.9 セントを挿し込みで説明するには
> **22mm** 要る。抜き差ししたとは考えにくいので**この 11 セントは奏者側**」と
> 書いていた。**22mm は全閉最低音の感度 0.49 セント/mm をそのまま当てた値で、
> 録音に入っている音（E3〜B4）には使えない**（§11.8）。測り直すと:
>
> | 基準 | 10.8 ¢ に要る挿し込み |
> |---|---|
> | 1/L 則 | **2.2 〜 6.6 mm** |
> | モデルの 0.49 を 1/L で伸ばす | 6.1 〜 18.6 mm |
>
> **2mm の差し直しでも説明が付いてしまう。** 挿し込み量を記録していないので
> **奏者側と断定できない。** 言えるのは「絶対音程は、挿し込み量を記録しない限り
> 設計の指標にならない」までで、結論はむしろ強くなった。**§11.10 ④ が本命になる。**

§7 が「絶対位置は弱い指標」と書いていたのは、**理由は違ったが結論は正しかった。**

**倍音比は前の 1 本では読めない。** 0.85% の標本が振り切れていて、
**クリップが作る高次倍音とマウスピースの倍音は区別できない**。後の 1 本は 0.02% で
実質クリップ無し。ただし**モデルの合成値と直接は比べられない** ——
合成は 1 つのリード・1 つのアンブシュア・管の口での理想化で、録音には部屋・
マイク・楽器の放射が入る。**比べられるのは同条件どうしの差だけ。**

**この道具自体の再現性（実測）。** 同じ録音を、切り出し位置と解析窓を振って
測り直した:

| 条件 | 区間数 | ずれの中央 |
|---|---|---|
| そのまま | 48 | +0.42 ¢ |
| 開始を +128 / +512 / +1024 / +2000 標本ずらす | 47〜48 | +0.39 〜 +0.95 ¢ |
| 窓 2048/1024・4096/512・8192/1024 | 43〜50 | −0.63 〜 +0.67 ¢ |

**中央値の再現性は ±0.8 セント。** 揺れているのは F0 ではなく**区間の切り方**
（43〜50 個）で、中央値はそれでも 1.6 セントの幅に収まる。**同条件 2 本の
差 10.8 セントは、この再現性の 7 倍**なので本物。
**そして 09-05 の A/B 差 8.8 セントは、その 10.8 より小さい**（上）。

記録しなかったので**使えない条件**: チューナー基準（A=440 と仮定）・室温・
挿し込み量。次はこれを録音の頭で読み上げる。

### 11.7 篏合と吹奏（第2便・2026-09-05）—— **初めて音が入った**

ネックは **Yamaha YAS-875 付属**、リード **レジェール スタジオカット 2¼**、
リガチャー **ウッドストーン メイヤー用 GP**、チューナー基準 **A=442Hz**。

**篏合 —— モデルが当てた数少ない例。**

| | 予測 | 実測 |
|---|---|---|
| ネックに入るか | 締め代 0.20mm の狙い（§6） | **問題なく入った** |
| 入りやすさ | 印刷品のボアが +0.10 なので**締め代 0.10 に半減**＝入りやすい側 | **PHROX と同じ位置まで、より小さい力で済んだ** |

**§6 の予測は当たっている。** ボア径の +0.10mm という一致帯すれすれの差が、
締め代では**半減**という効きになって現れる予測で、実物の手応えがそのとおりだった。

**吹奏 —— 印刷品のほうが低い。差は実測で 6.0mm。**

同じ挿し込み位置で比べると印刷品が低く出る。442Hz に合わせるには
**PHROX より奥**まで差す必要があった。

| | 前夜（09-05 未明）の申告 | **翌朝の実測**（2 回の読み） |
|---|---|---|
| 印刷品 | — | **35.4 mm** |
| PHROX | — | **29.4 mm** |
| 差 | 「3mm くらい」 | **6.0 mm** |

**目視の申告が実測の半分だった。** 前便はこの 3mm を測定として扱い、
「窓の実測からの逆算と 0.06mm で一致」という見出しを §0・§5.2・§7・§11.3・
§11.4・§11.10・`README.md` の 8 か所に書いた。**全部撤回した**（§11.4）。
**「くらい」が付いた数字は測定ではない。**

**「同じ位置まで入る」と「6.0mm 奥まで差す必要がある」は矛盾しない。**
前者は**篏合**（そこまで入るか）、後者は**チューニング**（合った位置がどこか）。
入る余地はあったので、奥へ行くこと自体は問題にならなかった
—— ただし**余地は 1.0mm しか残っていない**（§11.9）。

奏者の言葉（そのまま残す。交絡を評価する材料になる）:

> いつもの締め方だと低く出るなぁ、これ以上締めたくないのにまだ音程低いのか、、
> 仕方ないいつもよりだいぶ奥まで差し込むけどこれで音程合わせよう

**アンブシュアで説明する筋は弱い。** ビークが **2.00mm 高い**（§11.1）ので
口の開きが変わり、それだけでも音程は下がりうる —— が、**噛む方向へ逃げていない**
（JAZZ 寄りで強く噛まないのが常態）。開いた結果ではなく、
**開きを変えないまま低かった**という報告になっている。

**それでも交絡は残る。しかも第3便で 1 つ増えた** —— 実測者の条件:

> アンブシュアが完璧に同一になることはなく、音程も完全一致したものではない。
> リードの位置・リガチャーの固定状態から周囲の体感気温、管体の温度、自身の体調から
> **この辺の位置で合わせておけば演奏時間中最も音程が安定するだろうという位置に
> 経験的に合わせている**（もちろんメーターを目視しながら）。

**6.0mm は「音程が一致する位置の差」ではなく「奏者が落ち着けた点の差」。**
残差の音程差は未記録なので、**逆算の入力にはできない**（§11.4 で撤回した理由の 2 つ目）。
一方で**チューナーを見ながら**決めているので、音程と無関係でもない。
**決着させたのは §5.2 の 1 点のほう**（PHROX のティップ端 → 窓の後縁 39.4mm）。
ノギスだけで済み、**奏者が入らない**。数値は §11.4。

**まだ空欄**: 低音域 / 中音域 / オクターブ上のずれ、抵抗感、室温、
そして**同じ挿し込み量でのセント差**（§11.10 ②）。
**2 回の読みの内訳（何と何だったか）も未記録** —— 同じ量の目視申告と実測が
2 倍違ったので、ばらつきそのものが要る。

### 11.8 モデルの感度は**全閉最低音のもの**（シートの断定を 1 桁直した）

`cents_per_mm` **0.49** は `openwind_bridge._assemble_resonator` が組む 1 本の管
—— 空洞＋円筒ボア＋欠損円錐延長 —— の第1共鳴の感度で、**トーンホールは無い**。
つまり **D♭3 138.59Hz（全閉）の値**であって、チューニング音の値ではない。

| 音 | L [mm] | 1/L 則 | モデルを 1/L で伸ばす |
|---|---|---|---|
| 全閉最低音 D♭3 138.59Hz | 1252.4 | 1.38 ¢/mm | **0.49 ¢/mm**（実測値） |
| 録音の下端 E3 163.9Hz | 1059.0 | 1.63 | 0.58 |
| チューニング音 A=440Hz | 394.5 | 4.39 | 1.56 |
| チューニング音 A=442Hz | 392.7 | 4.41 | 1.56 |
| 録音の上端 B4 497.2Hz | 349.1 | 4.96 | 1.76 |

**絶対値は決まっていない。** 同じ全閉最低音で 1/L 則が 1.38、モデルが 0.49 と
**2.8 倍食い違う**。挿し込みが縮めるのは円錐の**細い端**（体積速度が小さい）で、
1/L 則は端の位置を問わないので過大に出る —— という説明は付くが、
**どちらが実物かは未検証**。

**確かなのは比。** 感度は 1/L で伸びるので、**チューニング音は全閉最低音の 3.2 倍敏感**。
§7 が「0.49 セント/mm だから 10mm ずれても 5 セント」と書いていたのは、
**チューニング音の話に全閉最低音の数字を当てていた**（1 桁外している）。
§7 と §11.6 を直した。

**この 2.8 倍は測って埋まる。** §11.10 ② でチューニング音の実感度が直接出る ——
モデルが持っていない量なので、**モデルの外部照合になる 2 つ目**（1 つ目は
押し込み限界 36.4mm）。

> **【2026-09-05 朝】この表は「印刷した個体の設計」の値**（`cents_per_mm` 0.49）。
> **更新後のテンプレートでは 0.43** で、1/L 則 1.38 との食い違いは **3.2 倍**に
> なる（窓を実測に合わせ、`cork_depth` を引き直した結果。§11.4）。
> **`cents_per_mm` は零点での傾きではなく、いまの `cork_depth` での局所の傾き**
> なので、形を変えたら引き直すまで読んではいけない ——
> 引き直す前に読んだ 1.24 という値をここに一度書いて、撤回した（§11.9）。

### 11.9 `in_tune_mm` に絶対の相手が付いた —— **比較できる量ではなかった**

旧 §11.9 ②（現 §11.10 ③）は「差だけだと `in_tune` 13.58 との照合ができない」と書いて絶対値を
求めていた。答えが来た:

| 基準 | モデルの `in_tune` | PHROX の実演奏位置 | 差 |
|---|---|---|---|
| テンプレート素（更新後） | 17.42 mm | **29.4 mm** | **+12.0** |
| PHROX 実測形状 | 16.76 mm | 〃 | **+12.6** |

**この 15.8mm でモデルを責めることはできない。** `volume.reference_conditions` が
明記しているとおり `in_tune_mm` は基準条件の値で、モデルの胴は
**ベルが音響へ接続されていない**（`alto.json` body_note: 接続すると全閉の第1共鳴が
**+38〜+106 セント**動く）:

| 未接続のぶん | 挿し込みに直すと |
|---|---|
| 38 セント | **88mm**（素 0.43 ¢/mm）/ **90mm**（実測形状 0.42 ¢/mm） |
| 106 セント | **247mm** / **252mm** |

**どれも実用域 33.4mm より大きい。** トーンホールも無く、気温は 25°C 固定。
**免責は脚注ではなく本体だった** ——「基準条件での値」の幅が可動域を超える。

**差のほうは比較できる**（胴・ベル・気温は差で消える。mm は音に依らない
—— §11.4）。**その差でモデル −2.71mm、実測 +6.00mm。**

**副産物: `cents_per_mm` は `cork_depth` での局所の傾き。**

> **【2026-09-05 朝・訂正】** ここには一度「`cents_per_mm` は形で **2.5 倍**動く
> （素 0.49 → 実測形状 **1.24**）ので、§11.8 の 2.8 倍の食い違いは 1.1 倍まで縮む」と
> 書いた。**その 1.24 は形の値ではなく、`cork_depth` が零点から 3.8mm 離れた
> 状態で読んだ傾きだった**（ついでに窓もクランプしていた）。
> テンプレートを整合させると **0.43**（実測形状 0.42）で、1/L 則 1.38 との
> 食い違いは **3.2 倍**。§11.8 の 2.8 倍は縮むどころか少し開いた。
> **教訓は残る** —— `cents_per_mm` は零点での傾きではなく**いまの挿し込み位置での
> 傾き**なので、形を変えたら `cork_depth` を引き直すまで読んではいけない。

**実測位置は実用域のどこか**（上限 36.4 は同じ PHROX を YAS-875 に押し込んだ実測）:

| | 挿し込み | 深い側の余地 |
|---|---|---|
| PHROX | 29.4 | +7.0 mm |
| **印刷品** | **35.4** | **+1.0 mm** ← `TUNING_MARGIN_MM` 2.0 を切っている |

**ただし 36.4 は PHROX を押し込んで測った値で、印刷品自身の止まりは未測。**
印刷品はボアが +0.10mm 太く締め代が半減しているので（§6）、**同じ力ならもっと
奥まで行く可能性がある** —— `insertion_limit_source` が書いているとおり
この上限は**組の性質**で、マウスピースを替えれば動く。
**「印刷品の余裕が 1.0mm」は PHROX の止まりを借りた値。**

**`status` は `in_tune` 16.76 の位置で余裕を見るので `ok` を返す。**
判定している点と楽器が実際に使われている点が **12.6〜18.6mm 離れている**。
**コードは変えない**（`status` の規則を変えると 3 サイズ全部のカードが動く）——
実測位置での余裕は `inspection_values.py` が出す。

### 11.10 次に測るもの（順に効く）

**① ボアの終端そのもの**（`bore_length`）—— **いまの 48.30 は上限であって
点推定ではない。** 窓の実測はボアが**それ以下**だとしか言っていないので、
実物のボアが 45mm でも矛盾しない。決着させるなら:

- **細い棒を差して段差を探る**（ボア終端＝円筒からチェンバーへの立ち上がり）。
  §3 は「両ジョウとも明確な終端が見えず測れなかった」と記録している ——
  ノギスではなく**深さゲージか針金＋印**なら届くかもしれない
- 届かないなら「上限しか無い」と記録し続ける。**上限を点推定として扱わない**

**② 同じ挿し込み量でのセント差** —— **モデルの外部照合になる。**
PHROX が合う位置（29.4mm）に印刷品も差し、チューナーのずれを両方読む。
6.0mm と合わせると**チューニング音の実感度 [¢/mm]** が出る。
これはモデルが持っていない量（トーンホールが無いので全閉最低音しか解けない）で、
**1/L 則 4.4 とモデル基準 1.4 が 3.2 倍食い違っている**ところ（§11.8。
1.4 は更新後のテンプレートの 0.43 ¢/mm を 1/L で伸ばした値）。
**モデルは片方の値しか持っていないので、実測 1 点の価値が大きい。**
ついでに**全閉最低音でも読む**と、モデルが実際に解いている音での直接比較になる。

**③ 挿し込み量の 2 回の読みの内訳** —— 35.4 / 29.4 が何と何だったか。
**同じ量の目視申告（3mm）と実測（6.0mm）が 2 倍違った**ので、
ばらつきそのものが記録に要る。できれば**交互に 3 往復**（印→PH→印→PH→印→PH、
毎回抜いて合わせ直す）。**合わせ直しの再現性そのものがまだ未知**
（§11.6 の訂正 —— 録音 2 本の 11 セント差が、奏者なのか数 mm の差し直しなのか
分けられなかった）。

**③' 印刷品のティップ端→窓の後縁をもう 1 回**（同じ日に続けて 3 回）。
**2 回の読みが 1.10mm 割れていて符号まで逆**（−0.45 / +0.65）。PHROX は
0.10mm で揃っているので、**個体ではなく読み方の問題の可能性がある**（§5.3）。

**④ 録音をクリップさせずに撮り直す** —— **4 本中 3 本が振り切れている**
（0.85 / 0.65 / 1.75%）。**ピークを −6dB 以下に。**
倍音比が出ないと、録音は F0 しか出さない道具のままで A/B に使えない（§11.6）。
**録音の頭で挿し込み量・室温・A=442 を読み上げる。**
できれば**同じ旋律**を吹く（09-05 の 2 本は音域が違った）。

**⑤ リード硬さを変えた 2 本**（同一条件）—— 合成は「硬いほど偶数倍音が落ちる」と
言っている（`cad/windycity/README.md`）。**差なら比べられる**。④が先。

### 11.11 ティップが壊れた —— **「揃い」に幾何コードが荷重を掛けていた**

§11.4 の更新のあと、**新規作成した既定アルトのティップ形状が壊れた**。
利用者が 3D ビューで見つけた（`AltoSaxSetTrial1.wproj` の形は好ましく、
新既定は駄目、と写真 2 枚）。**テストも掃引も素通りしていた。**

先端の空洞高さ **0.60 → 4.44mm**。ティップレールの薄いくさびが消え、
窓の前縁コーナーが吹き飛んでいた。

**犯人は 3 つの変更のうち `window_length` 単独:**

```
旧（3 つとも旧）             h[0]= 0.60  h[5]= 1.44  hmax=16.18
window_length 38.67 のみ    h[0]= 4.44  h[5]= 9.20  hmax=22.69   ← これ
bore_length 48.30 のみ      h[0]= 0.60  h[5]= 1.28  hmax=16.06
cork_depth 17.45 のみ       h[0]= 0.60  h[5]= 1.44  hmax=16.18
```

#### 何が起きていたか

`profiles.cavity_floor_y` は実測の床曲線 `_CAVITY_D` を**振幅方向のアフィン**で
2 つの端条件（窓の終端で D=0 / ボアの始まりで F=−bore_radius）へ合わせていた:

```
a = target / (D(1) − D(s_we))          s_we = window_end_z / bore_start_z
```

`_CAVITY_D` は **σ=0.838 で 0 を横切る**（＝実測品の窓の終端）。s_we がそこに
載っている間だけ `a≈1` になる —— そして**3 サイズともたまたま載っていた**:

| | s_we | 分母 | **a** | 窓の後端→ボア |
|---|---|---|---|---|
| soprano | 0.8408 | −0.356 | 0.729 | 5.27mm |
| tenor | 0.8380 | −0.367 | 1.003 | 8.10mm |
| 旧アルト | 0.8382 | −0.367 | 0.914 | 6.90mm |
| **新アルト** | **0.9078** | **−0.098** | **3.479** | **4.00mm** |

窓を実測どおり伸ばすと s_we が 0.838 を越え、**分母が縮んで係数が 3.5 倍**。
床が丸ごと 3.5 倍深くなり、先端の落とし込み D(0)=0.100（0.79mm）が 2.73mm に化けた。

**爆発は連続していて、`window_end_z` の `zb − 4.0` が唯一の歯止めだった:**

```
間隔 10.0mm → a=0.81   6.9mm → a=0.97   4.0mm → a=3.48
      3.0mm → a=4.38   2.0mm → a=6.48   1.0mm → a=12.30
```

**これが実測で死んだ 4 つ目の「揃い」。** 前の 3 つ（径比 0.9167・ボア長の割合・
容積比）は**記述**だったが、**これは幾何コードが依存していた** —— 「3 サイズで
s_we が 0.838 に揃う」ことに、床の式が荷重を掛けていた。

#### 直し方 —— 振幅ではなく σ を写像する

窓を伸ばすことは「床が上がってくる位置が後ろへ動く」ことであって、
「空洞全体が深くなる」ことではない。

```
M: 0→0, s_we→0.838, 1→1 の単調写像（3 点 PCHIP）
g: g(0)=1, g(1)=target/D(1) の滑らかな重み（尾側だけ端条件へ寄せる）
d = D(M(σ)) · g(σ)
```

- **先端は σ=0 → M(0)=0 なので D(0) が素通り** ＝ `window_length` は先端に効かない
- **窓の終端は D(M(s_we))=0 なので g に依らず厳密**
- **割り算が消えるので特異点が無い**

| | 現行（壊） | σ 写像 |
|---|---|---|
| soprano | h[0]=0.60 hmax=13.80 cc=4.628 | 0.60 / 13.80 / 4.627 |
| tenor | 0.70 / 17.64 / 13.693 | **完全に不変** |
| 旧アルト(35.02) | 0.60 / 16.18 / 10.332 | 0.63 / 16.18 / 10.332 |
| **新アルト(38.67)** | **4.44** / 22.74 / 10.396 | **0.63** / 17.54 / 10.445 |

`window_length` を可動域 24〜44 で振っても **h[0] は 0.63 のまま動かない**。

#### 保存済みプロジェクトへの影響 —— **「無傷」ではないので数字で言う**

| | 先端 前→後 | 実効容積 前→後 |
|---|---|---|
| `AltoSaxSetTrial1.wproj`（**印刷して吹いた個体**） | 0.600 → **0.633** | 11.1013 → 11.1011（−0.00%） |
| アルトサクソフォン マウスピース | 0.600 → 0.600 | 11.1579 → 11.1590（+0.01%） |
| 〃 set | 0.600 → **0.633** | 10.8998 → 10.8995（−0.00%） |
| ソプラノサクソフォン マウスピース | 0.600 → 0.600 | 4.3147 → 4.3136（−0.03%） |

**印刷した個体は先端が +0.033mm 動く。** 容積は 3 桁目まで不変なので §11.6〜11.9 の
判定は動かない。検品シートの数字は再計算していない。

#### 息の通り道の警告を足した（利用者の要求）

「リード先端との間で息の通り道の妨げとなるべきではない。ユーザのパラメータ設定に
よって阻害される場合は警告を出すべき」。

`profiles.airway_min` を足した —— リードの接地面（`table_plane_y`）から天井までの
高さを窓の区間で見る。**リード面（`cut_top_y`）で測ってはいけない**: ティップ開きを
丸ごと数え落として入口が 0 に見える。

**判定の相手は入口（ティップ）自身なので、閾値を発明せずに済む** ——
このシートで繰り返し問題になってきた「根拠の無い丸い数字」を増やさない数少ない判定。
既定の 3 サイズは最狭部が z=0 ＝ 入口そのもので、警告は出ない。

```
baffle_height 2.38（既定） 警告なし
              3.00        z≈3.9mm で入口の 94%
              3.50        z≈3.9mm で 71%
              4.00        z≈4.3mm で 47%
              5.00（上限） z≈4.3mm で 45%
```

**助言は「バッフルを下げる」だけ。ティップ開きを広げるのは対策にならない** ——
上がるのは入口だけで奥は動かないので、比はかえって悪くなる（実測: ティップ開き
2.40 では警告なし、3.00 で 97%、3.20 で 90%）。

### 11.12 蓋の裏にもう 1 つ —— **`zb − 4.0` は幾何の壁ではなかった**

§11.11 の直後、設計許容範囲を広げる作業（`docs/param-limits.md`）の下調べで
`window_end_z` の直値 `zb − 4.0` を測ったところ、**すぐ裏に同じ型の退化が
もう 1 つ**あった。`_floor_limit` が制御点を

```
(0,0)  (s_we,0)  (min(s_we+0.06, 1), 1)  (1,1)
```

と組んでいて、**`s_we ≥ 0.94` で第 3・第 4 節点が x=1.0 で衝突**する。
`_pchip_table` は区間幅で割るので `ZeroDivisionError`。閾値は `gap ≤ 0.06·zb`
＝ **サイズで変わる**:

| | zb | 落ちる gap | 当時の壁 4.0mm からの余裕 |
|---|---|---|---|
| soprano | 33.10 | ≤ 1.99mm | 2.01mm |
| alto | 43.40 | ≤ 2.60mm | 1.40mm |
| tenor | 50.00 | ≤ 3.00mm | **1.00mm** |

**アルトの既定 `s_we` は 0.9078 ＝ 落ちるまで 0.033。** §11.11 で窓を実測へ
入れ替えたとき、たまたま踏まなかっただけだった。

つまり `zb − 4.0` は**慣習の壁の顔をして、退化を 2 つ覆っていた蓋**だった
（§11.11 の振幅アフィンと、これ）。直して蓋を外すと **3 つ目**が出た ——
`chamber_to_bore_mm` を 0 にすると `_chamber_weight` の制御点が x=1.0 で重なる
（チェンバーの長さが 0 になる）。

`_pchip_table` に**重複 x を名指しで弾くガード**を入れた。`profiles.py` には
`s_we` / `s_th` / `s_ch` から動的に組む表が **6 か所**あって、どれも同じ退化を
しうる。**3 つ目を見つけたのはこのガードそのもの。**

直しは既定形状を動かさない —— 3 サイズとも `h[0]` / `hmax` / ステーション数 /
実効容積 / `in_tune_mm` / Tier2 まで**ビット一致**を確認した。

#### ここから引き出した規則

**直値で止めている場所は、止めている理由を測るまで信用しない。**
`zb − 4.0` には「チェンバー→ボアの遷移を残す」というもっともらしい理由が
書いてあり、実際その理由自体は正しい。正しくなかったのは**その位置**で、
4.0 という数字を決めていたのは幾何ではなく**その手前で落ちるバグ**だった。

`chamber_to_bore_mm` としてパラメータに出し、壁は掃引で測った（下 0.5 /
上 30.0）。**既定 4.0 のままなら形は 1 ビットも動かない。**
