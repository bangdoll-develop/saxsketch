# 壁と帯 — 設計許容範囲をどう決めているか

Phase 4-E。**「勧める帯」と「越えられない壁」を分けて、壁の出所を書く。**

## なぜ

印刷品を吹いた利用者の見立て:

> 世の中にある素晴らしいマウスピースの設計は理論だけでは説明がつかない可能性が
> 高い。ある程度の理論に基づき設計・試作・試奏し、奏者の感覚的な評価から最終
> 設計が決定される。……そのベースの上でユーザーのアイデアによる想定（理論）外の
> 変更箇所が音質や音程によい影響を及ぼすこともあるのではないか。

理論が出したベース形状の上で「想定外の値」を試せるべき、という話。
ところが着手前の可動域には 3 つ問題があった。

1. **黙っている。** `ParamSpec.validate` は範囲外を無言でクランプし、
   フロントは差分を拾って値を戻すだけだった。利用者にはスライダが勝手に
   戻ったようにしか見えない（この repo で数えて **8 例目**の黙ったクランプ）。
2. **出所が書かれていない。** 実測由来の壁（`body_dia` の下限＝ソプラノ実測）と、
   誰も測っていない暫定値（`beak_height` の既定は自認で「幾何的な暫定値」）と、
   幾何の定義域（`shoulder_fullness` の ±1）が、コード上まったく同じ顔をしていた。
3. **本当の壁の位置を誰も測っていなかった。** これが一番大きい ——
   下の「掃引で分かったこと」がその証拠。

## 仕組み

`ParamSpec`（`saxsketch/core/schema.py`）に 4 つ増やした。

| フィールド | 意味 |
|---|---|
| `min` / `max` | **勧める帯**。UI ではトラックの網掛け。越えられる |
| `hard_min` / `hard_max` | **越えられない壁**。`None` なら帯がそのまま壁 |
| `limit_kind` | `geometry` / `manufacturing` / `convention` / `unclassified` |
| `source` | 帯の出所。**空なら「出所の記載なし」と表示する** |

規則は 2 行:

- **クランプ先は `hard_*`。無ければ `min`/`max`。**
  `hard_*` を 1 つも入れなければ**現行と完全に同じ**挙動になる。
- **`limit_kind` は説明のラベルで、硬さは決めない。** 1 本のパラメータでも
  下限が幾何・上限が慣習ということがある（`shank_length` の 0 と 30.0）ので、
  緩めるのは片側ずつ `hard_min` / `hard_max` で行う。

丸めたときは `ParamSet.adjustments` に**値・単位・壁の種別・出所**を積み、
`PUT /api/project/params` の `adjustments` で画面まで届く:

> ⚠ 最小肉厚 0.2 → 1.2 mm に丸めました（製造の制約の下限、出所: 3D プリントの
> 強度下限（レジン 2mm 以上推奨））

## 掃引器

`cad/windycity/sweep_limits.py`。帯の端から外へ 1 段ずつ歩き、3 段で判定する:

1. `comp.params_error(p)` が `None`
2. `profiles.cavity_stations(p)` が例外を出さず、枚数と先端高さが退化しない
3. **OCCT ビルドがソリッド 1 個**（`is_valid` は当てにしない。体積も見る）

1〜2 は速いので端から端まで、3 は境界の周りだけ（1 点 4.5〜7 秒）。

**「通った」と「効いた」は別物。** 各点で形の指紋を取り、**動いていなければ
そう言う**。これが無いと死に帯を「壁が無い」と読み違える —— 実際
`chamber_to_bore_mm` は既定の `window_length` では**負にしても何も起きない**
（`min()` の反対側が勝つ）ので、最初の掃引は「−18mm まで通る」という嘘の
結論を出していた。

指紋と応答は 5 軸（`cavity_h` / `cavity_w` / `cavity_a` / `outer_r` / `beak_y`）で
見る。**初版は空洞の高さと z しか見ておらず、それ自体が誤判定の元だった** ——
下の「掃引器そのものが 3 軸で盲だった」を参照。

## 掃引で分かったこと（Phase A・2026-09-05）

### 広げた 4 本

「入れた壁」は `hard_min`/`hard_max` に実際に書いた値で、**測った位置そのもの
とは限らない** —— 落ちる点ちょうどではなくスライダの 1 段手前で止めたり
（`chamber_to_bore_mm` の下は落ちる点が 0 で、入れたのは 0.5）、応答が死ぬ手前で
止めたり（`baffle_height`）する。差がある行は「何が壁か」に書いてある。

| パラメータ | 帯 | 入れた壁 | 何が壁か |
|---|---|---|---|
| `tip_opening` | 1.0–3.2mm | **0.05 – 5.2** | 下は 0 でちょうど落ちる（`ZeroDivisionError`）。上は 5.2 まで確認して打ち切り＝**それより外は未測定**。応答は tenor 101% / alto 82% で一定、**soprano だけ 7%** ＝ 死に帯の線引き 5% のすぐ上（膝が無いので広げたが、ぎりぎり） |
| `baffle_height` | 0.0–5.0mm | **−2.3 – （広げない）** | 上は **5.0 から先が死に帯**（天井が外殻で頭打ち）。負は天井を基準より上げる向き。ソリッドは −4.0 でも通るが **alto はそこで応答 4%**（soprano 23% / tenor 37%）。効くのは −2.3 までなので、縛るサイズに合わせた |
| `window_length` | 24.0–44.0mm | **4.0 – （広げない）** | 上は**帯の内側で既に死んでいる** —— 凍る点は soprano **28.54** / alto **38.67** / tenor 45.15mm で、生きているのは帯の 23% / 73% / 100%（2026-09-06 実測。値は `_WINDOW_FREEZE_MM` が持つ）。壁ではなく `chamber_to_bore_mm` の影で、**アルトは既定 38.67 がちょうど凍る点**なので既定より上は 1 目盛りも効かない |
| `chamber_to_bore_mm`（新設） | 2.0–10.0mm | **0.5 – 30.0** | 下は **3 サイズともぴったり 0**。上は 30.0 まで確認、その先は `cavity_layout_error` |

「広げない」と書いた 2 つは**壁が無いのに広げなかった**のではない ——
**壁ではなく死に帯**だったので、広げても嘘のつまみが増えるだけ。

### 「ソリッドが通る」だけでは決められなかった

`baffle_height` は当初 **−4.0** で入れた（3 サイズともソリッド 1 個）。
その後**固定グリッド**（ステーション数に依らない σ 等分）で空洞の平均高さの
応答を測ったら、**alto はそこで帯の端の 4%** しか動いていなかった。
効くのは **−2.3mm まで**。soprano 23% / tenor 37% はまだ生きているが、
**縛るサイズに合わせて −2.3 にした**。

線引きは「帯の端での傾きの 5% を割ったら死に帯」。この基準で 4 本すべてを
測り直した結果:

| | 帯の端の傾きに対する、壁での傾き | 判定 |
|---|---|---|
| `tip_opening` 上 | tenor 101% ／ alto 82% ／ soprano **7%** | 生きている（**ぎりぎり**。膝は無い） |
| `window_length` 下 | soprano 139% ／ alto 114% ／ tenor 110% | 生きている |
| `chamber_to_bore_mm` 上 | soprano 140% ／ alto 108% ／ tenor 101% | 生きている |
| `baffle_height` 下 | soprano 23% ／ tenor 37% ／ **alto 4%** | **死に帯 → −2.3 で止めた** |

（`chamber_to_bore_mm` の下側はこの表に入れていない。窓を上限まで伸ばして
拘束を効かせても **tenor では最初から効かない**ので、3 サイズを並べた比較に
ならない ——`zb` が大きいぶん窓の長さのほうが先に頭打ちになる。）

**「ソリッドが 1 個できる」は壁の条件であって、つまみが効く条件ではない。**
掃引器の形の指紋はステーション数が変わると跳ねるので、この判定には固定
グリッドを使う。判定と「効くのはどこまでか」の探索は掃引器に入れてあるので、
Phase B では同じ 1 コマンドで出る。

判定を足したら**もう 1 つ穴が見つかった**: `tip_opening` を 0 に寄せると天井と
床がどちらも発散して傾きが 1e18 になるのに、**`cavity_stations` は通る** ——
段 1〜2 を抜けたからといって量が測れているとは限らない。掃引器の側で
非有限と桁外れを弾くようにした（`MAX_SANE_SLOPE`）。

### `zb − 4.0` は幾何の壁ではなく、バグを覆う蓋だった

`window_end_z` の直値 4.0 は「チェンバー→ボアの遷移を残す」慣習に見えていたが、
**すぐ裏に退化が 2 つ並んでいた**。

1 つ目は `5fb0bf4` で直した `cavity_floor_y` の振幅アフィン（`a = target/(D(1) −
D(s_we))` が s_we → 1 で発散。`docs/print-inspection.md` §11.11）。

2 つ目は `_floor_limit`。制御点を `(0,0) (s_we,0) (min(s_we+0.06,1),1) (1,1)` と
組んでいたので、**`s_we ≥ 0.94` で第 3・第 4 節点が x=1.0 で衝突**して
`_pchip_table` が `ZeroDivisionError`。閾値は `gap ≤ 0.06·zb` ＝ サイズで変わる:

| | zb | 落ちる gap | 当時の壁 4.0mm からの余裕 |
|---|---|---|---|
| soprano | 33.10 | ≤ 1.99mm | 2.01mm |
| alto | 43.40 | ≤ 2.60mm | 1.40mm |
| tenor | 50.00 | ≤ 3.00mm | **1.00mm** |

**アルトの既定 `s_we` は 0.9078 ＝ 落ちるまで 0.033。** 直しは 2 つ ——
ランプが必ず収まるよう `s_we` を頭打ちにし、ランプの終わりが 1.0 に達したら
末尾の節点を置かない。既定 3 サイズの `s_we` は 0.8408 / 0.9078 / 0.8380 なので
頭打ちは効かず、**3 サイズとも形状・音響がビット一致**（`h[0]` / `hmax` /
ステーション数 / 実効容積 / `in_tune_mm` / Tier2 まで）。

### 蓋を外したら 3 つ目が出た

`chamber_to_bore_mm` を 0 まで下げると、今度は `_chamber_weight` の制御点が
x=1.0 で重なる（`s_we = s_th = 1` ＝ チェンバーの長さが 0）。**同じ型の 3 つ目。**

そこで `_pchip_table` に**重複 x を名指しで弾くガード**を入れた。
`profiles.py` には `s_we` / `s_th` / `s_ch` から動的に組む表が **6 か所**あり、
どれも設計値の組み合わせ次第で退化しうる。`ZeroDivisionError` がリスト内包の
奥から出るのではなく、どの表のどの点が重なったかを言う:

```
ValueError: PCHIP の制御点 x が単調増加ではありません:
pts[1]=(1.0, 0.0) と pts[2]=(1.0, 1.0) で x が 1.0 → 1.0（幅 0.0）。表全体: [...]
```

**このガードが 3 つ目を見つけた。** 併せて `cavity_layout_error` にも
「遷移は長さを持たなければならない」を書いて、例外ではなく理由で弾くようにした。

## 広げると壊れる下流が 4 つあった

`min`/`max` は**スキーマ以外の 4 か所でも消費されていた**。どれも「帯 ＝ 越え
られない値」を前提にしていたので、壁を広げた時点で意味が変わる。

| 場所 | 帯のままだと | どうしたか |
|---|---|---|
| 断面タブのハンドル（`baffle_handles`） | スライダは壁まで動くのにハンドルは帯で止まる ＝ **同じパラメータが 2 つの UI で違うところまでしか動かない** | スキーマの可動域を渡すようにした。`baffle_handles` は 0.0/5.0 などを直に書いていて、`_handle_ranges` のコメント自身が警告していた二重化 |
| 感度表（`brightness.sensitivity`） | 帯の外にいる利用者では 1 段が「+0.05」ではなく「−0.8」になり、**感度の符号ごと壊れる** | 止める先を `ParamSpec.bounds()` に |
| ゴールシーク（`goalseek`） | 利用者が帯の外に置いた値を**黙って帯の中へ引き戻す** | 探索は帯の中のまま（理論側の提案が慣習の外へ出るのは筋が違う）。ただし**現在値が外にあるならそこを含める** |
| 採寸フォーム（`survey_targets`） | 実物の実測が帯の外だと**測った値が別物にすり替わる**（`body_dia` の下限を下げた経緯そのもの） | 壁で受ける |

### Tier2 は広げない。ただし黙らせない

音色レーダー（`brightness.tone_metrics`）の正規化域は帯とほぼ同じ数値だが、
**意味が違う** —— こちらは回帰を当てた範囲で、外挿する根拠が無い。だから
広げず、**指標は帯の端で頭打ちになる**。

問題は「スライダを動かしてもレーダーが動かない」がこの repo で何度も踏んで
いる型（効いていないのに気づけない）だということ。そこで有効範囲を
`_MODEL_RANGE` として括り出し、**外に出ている入力を `note` に並べる**:

> …**ティップ開き 4mm（有効範囲 1〜3.2mm） がモデルの有効範囲の外にあります。**
> この指標はそこで頭打ちになっていて、動かしても変わりません（回帰を当てた
> 範囲の外なので外挿していません）。形そのものは変わっているので、断面タブと
> 寸法を見てください。

## 分類の結果（マウスピース 33 個）

| 種別 | 数 | 例 |
|---|---|---|
| `convention` | 28 | ほとんど。市販品や実測品がその辺りにあるというだけ |
| `geometry` | 3 | `tip_chamfer`（0 ＝ 面取りなし）、`baffle_curvature` / `shoulder_fullness`（±1 が定義域） |
| `manufacturing` | 2 | `min_wall`、`material` |
| `unclassified` | 0 | 残していない |

**分類したのはマウスピースだけ。** リード・リガチャー・ネック・管体は
`unclassified` のままで、挙動も現行どおり（`hard_*` が無いので帯がそのまま壁）。

**出所が空のものが 6 個ある**（`tip_opening` / `facing_curve` / `baffle_type` /
`rollover_radius` / `chamber_shape` / `material`）。UI には「出所の記載なし」と
出る。**空欄を埋めるために出所を発明しない** —— 記載が無いことも情報。

B-1 で 4 個（`facing_length` / `tip_rail_width` / `tip_rail_thickness` /
`side_rail_width`）に出所が付いたが、**書いたのは壁の出所であって帯の出所では
ない** —— どれも「帯の出所は記載なし。壁は掃引で測った」と書いてある。

## 掃引器そのものが 3 軸で盲だった（Phase B-0・2026-09-06）

残り 25 本に掃引器を回す前に、**測れるのかを先に測った**。アルト既定から
±2 段振って何が動くかを見ると、器械の側が見えていない軸が 3 つあった。

| 動く軸 | 初版の指紋に映るか | 該当パラメータ |
|---|---|---|
| 空洞の高さ・ステーション数・z | ○ | 15 本 |
| 空洞の**幅・断面積** | **×** | `side_rail_width` / `throat_ratio` / `chamber_ratio` |
| **外形**（胴・シャンク・ビーク・先端の面取り） | **×** | `shank_dia` / `shoulder_fullness` / `tip_chamfer` |
| 選択肢に依存して初めて生きる | **×** | `baffle_curvature`（`baffle_type=curve` のみ）/ `rollover_radius`（`rollover` のみ） |

そのまま回していたら、この 8 本は全部「**形が動かない ＝ この向きでは効いて
いない**」という嘘の結論になる。**掃引器が捕まえるために作られた型に、掃引器
自身が嵌まっていた。** `side_rail_width` は `w`・断面積・体積が確かに動くのに
指紋は不動、`tip_chamfer` は外形を動かすのに全長 60 等分のグリッドでは
先端 0.29mm の面取りを跨いで消える。

直したのは 3 つ:

- **指紋を 5 軸に**（`cavity_h` / `cavity_w` / `cavity_a` / `outer_r` / `beak_y`）。
  空洞側はステーション列を**固定 z グリッドへ内挿**して載せ替える ——
  枚数が変わるだけで平均が跳ねるのを避けるため。外形側は**先端 0〜3mm だけ
  0.05mm 刻み**。物差しの目盛りが対象より粗いと、無いのと同じ。
- **本命の軸は掃引器が選ぶ**。人が「このパラメータはこの軸」という表を
  保守すると、また抜ける（初版の 1 軸がまさにそれ）。帯の端で一番応答した
  軸を本命にし、**軸によって食い違うときはそう言って人に返す**。
- **`--with` が choice を受ける**。これが無いと `baffle_curvature` と
  `rollover_radius` は永久に測れない（既定の `baffle_type` は `step`）。

軸を選ぶときの正規化は**平均ではなく絶対値の平均**にした。`beak_y` は 0 を
跨ぐので平均がほぼ 0 になり、平均で割ると相対変化が跳ね上がって**どの
パラメータでもこの軸が勝ってしまう**（実測: `tip_opening` で beak_y 6.9e-3 vs
cavity_h 3.8e-3）。**軸選びが零点の置き方で決まるのは、測っていることに
ならない。** 逆に「応答している軸すべての最大」を採る案は捨てた ——
傾きが 1e-4 しか無い軸の比（`chamber_to_bore_mm` の cavity_w で 5396%）が
本命を覆い隠す。桁の違う軸は最初から外す（`AXIS_KEEP`）。

### 掃引で決められない 3 本

- **`cork_depth`** —— `total_cc` は 1 ビットも動かず `effective_cc` だけ動く。
  幾何ではなくチューニング量だと**測定で裏が取れた**（そう書いてはあった）。
- **`reed_width`** —— `window_width` は線形に応答するのに面が 1 つも動かない。
  `table_flat_width` の docstring が自認済み:「`reed_width` はソリッドの上に
  存在しない —— 窓幅の公称値とリガチャーのタブ幅に使われるだけ」。
  壁を決めるのはリガチャー/リードとの噛み合わせであって、掃引ではない。
- **`min_wall`** —— 印刷の壁（Phase A から変わらず）。

### ついでに出た 4 つ目の退化と、検証の穴

`tip_opening` を下へ歩くと **0 ちょうどで素の `ZeroDivisionError`** が上がる。
radial のフェイシングは `y(0)=tip` となる円弧半径を `(fl² + tip²) / (2·tip)` で
解くので、`tip_opening = 0` で発散する。`params_error` は `None` を返していた
ので、**理由なしに落ちる**。`cavity_layout_error` と `facing_rise` の両方で
断るようにした ——`_pchip_table` の節点衝突・`cavity_floor_y` の特異点・
`_chamber_weight` に続いて**同じ型の 4 つ目**。

もう 1 つ、掃引器自身のバグ: 死に帯を見つけて壁を内側へ引き戻したあと、
**段 3（OCCT ビルド）は引き戻す前の点をビルドしていた**。`baffle_height` の
−2.3 は一度もビルドで確かめられておらず、確かめていたのは −4.0 のほう。
**検証している場所が結論と違うのは、検証していないのと同じ。**

### Phase A の 4 本を測り直した

物差しを替えたので、Phase A の値がその物差しでも出るかを確かめた。
**壁は 4 本とも同じ値**（`tip_opening` 0.05〜5.2 / `baffle_height` −2.3 /
`window_length` 4.0 / `chamber_to_bore_mm` 0.5〜30.0）。

ただし**百分率は変わった**。`tip_opening` の soprano は 7% ではなく **43%** ——
旧掃引器は素の「天井 − 床」を見ており、`_contain` で外殻に収めたあとの
実際にロフトされる断面ではなかった。Phase A に「soprano だけ鈍っていて

- **軸によって答えが割れることが実際にあった。** `side_rail_width` の下側は

## B-2 バッフル ＋ チェンバー（2026-09-06）

### このスライスで分かった一番大きいこと —— 壁の半分はスキーマに無かった

6 本のうち 4 本は、越えられない所を決めていたのが `ParamSpec` ではなく
`profiles.py` の `min(max(...))` だった。**そのまま掃引すると 4 本とも

「形が止まる」のではなく「値がコードを通らない」。

| 本 | 掛け金の場所 | 値 | 止めている理由 | どうしたか |
|---|---|---|---|---|
| `baffle_plateau` | `baffle_plateau()` | 型ごと `_PLATEAU_RANGE` | **書いてある**（長い棚を許せばそれはもうストレートではなくステップ） | **残す** |
| `baffle_step_rise` | `_v_step` | `0.85` | 無い（`src` は「上限は未測定」） | 外す |
| `baffle_curvature` | `_v_curve` | `±1.0` | **循環**（「定義域そのもの」と書いてあるだけ） | 外す |
| `rollover_radius` | `_v_rollover` | `w ≤ 0.9` | **`src` が空** ＝ UI に「出所の記載なし」と出ていた | 上だけ外す |

Phase A の型 ——**直値の壁は、止めている理由を測るまで信用しない** —— を
そのまま当てた。**外す／残すを決めたのは値ではなく理由の有無**で、
`_PLATEAU_RANGE` だけが理由を持っていた。

### 同じ数字がコードの中にもう 1 部あった（代理変数の 5 例目）

`baffle_step_rise` の 0.85 は **3 か所**にあった —— スキーマの `max`、
`_v_step` のクランプ、`brightness._baffle_bonus` の正規化 `/0.85`。
`throat_ratio` の帯 0.60〜1.35 も `brightness._MODEL_RANGE` にもう 1 部ある。

**`brightness` 側は直さない。** あちらは回帰を当てた範囲であって幾何の壁では
なく、数値が同じでも意味が違う（Phase A で Tier2 を広げなかったのと同じ）。
壁の外で明るさが動かなくなるのは正しい振る舞い —— `_norm` が [0,1] に
丸めるので頭打ちになる。**テストに「わざと頭打ち」と書いて固定した**。
書かないと、次に読む人が「片方だけ直し忘れ」として直す。

### 測った壁

| `baffle_curvature` | −1〜1 | **−1.7** | **3.0** | 下は死に帯の縁（n が大きくなると `1−(1−t)^n` が飽和する。soprano −1.7 / alto −1.9 / tenor −1.7 ＝ 縛る soprano・tenor）。上は打ち切りで応答 16〜17% |

| `chamber_ratio` | 1.00〜3.00 | **0.05** | **5.0** | 下は `_chamber_weight` の `max(比, 0.05)`。`√比 − 1` を取るので比 0 以下は意味を持たない ＝ **残すガード**。上は打ち切りで応答 soprano 22% / alto 64% / tenor 37% |

**「打ち切り」は「壁を見つけた」ではない。** 40 段外へ歩いて落ちなかった
だけで、その先は未測定 ——spec の `src` にもそう書いた。

### `rollover_radius` は掛け金ではなく式が壁を作っていた

`_v_rollover` は肩の丸みを σ 尺度の `w = 半径 / span` へ直して使う
（`span = (1 − 棚) × ボア開始 z`）。フィレットは
`f(u) = u²/(2w)` (u<w) / `u − w/2` (u≥w) を `f(t)/f(1)` で正規化した形。

- **上**: `w ≥ 1` になると `t ≤ 1 < w` が常に成り立って `f(t)/f(1) = t²` に
  落ち、**w が式から消える**。掃引が見つけた縁は soprano 21.0 / alto 27.5 /
  tenor 31.5 で、それぞれの span 21.2 / 27.8 / 32.0mm の 1 段手前 ——
  **サイズごとに違う壁を、掃引が独立に当てた**。外した 0.9 のクランプは
  この飽和のすぐ内側にいただけだった
- **下**: `w ≥ 0.02` のガードは**残した**。`u²/(2w)` が `w→0` で発散する ——
  `_pchip_table` の節点衝突・`cavity_floor_y` の特異点・`_chamber_weight`・
  `facing_rise` の円弧半径に続く、**割り算が潰れる同じ型の 5 つ目**

帯が 3〜20mm 固定なのに壁がサイズで 21〜31.5mm と違うのは、この量が
**ボア開始位置に比例する**から。帯のほうがサイズを見ていない。

### `baffle_plateau` のスライダは大半が死んでいる（黙ったクランプの 7 例目）

帯 0.02〜0.75 は 4 型を覆う**和集合**で、どの型のものでもない。実効範囲は
`_PLATEAU_RANGE` が型ごとに決める:

| 型 | 実効範囲 | スライダの死んでいる割合 |
|---|---|---|
| step / rollover | 0.10〜0.70 | 下 11% ＋ 上 7% ＝ **18%** |
| straight / curve | 0.02〜0.12 | 上 **86%** |

3 サイズとも同じ（比なのでサイズに依らない）。断面タブのハンドルは
`_PLATEAU_RANGE` を読むので正しく、**食い違っているのはスライダのほう**。
`window_length` がソプラノで 76%、`seat_offset` が 98.9% だったのと同じ型で、
これで 7 例目 ——**掃引はこれを「拘束は別のところで決まっている」と言って
人に返した**（壁だと言い切らなかったのが正しい）。

直すにはスライダの可動域をバッフル型で切り替える必要があり、`ParamSpec` は
いま静的なのでこのスライスには入れていない。**報告しただけでは直っていない。**

### `throat_ratio` は B-0 の直しが無ければ測れなかった

空洞の**途中**を相似に絞るだけなので、初版の掃引器が見ていた 5 つの
スカラー（枚数・先端高さ・最大高さ・窓の後端・ボアの始まり）は
**1 ビットも動かない**。本命の軸は `cavity_a` で、応答は帯の端の 117〜118%。

同じ節の `chamber_ratio` のほうは最大高さが動くので旧指紋でも見えていた。
**同じ節のパラメータでも、見える／見えないは 1 本ずつ別に決まる。**

生ログは `docs/sweeps/b3-bore-window.txt`。

### 測った壁

| パラメータ | 帯 | 入れた壁 | 何が壁か |
|---|---|---|---|
| `bore_dia` | 実測 ±1.0mm（12.8–14.8 / 14.8–16.8 / 16.0–18.0） | **実測 −11.0 – シャンク径 −0.05**（2.8–18.62 / 4.8–23.15 / 6.0–22.95） | 上は**シャンクが残る限界**（`bore_dia` < `shank_dia`）。下は帯の端から 10mm まで通した ＝ その先は未測定 |
| `bore_length` | 実測の 0.5〜1.25 倍（19–48 / 24–60 / 29–72） | **1.0 – 全長 −6.5**（1–64.9 / 1–85.2 / 1–101.0） | 上は窓が 2.0mm を割る手前（3 サイズとも **zb 6.2〜6.4mm**）。下はボアが長さを失う手前 |

### 打ち切りは壁ではない（掃引器に `--steps` を足した）

帯の外へ歩く距離は **段数 × 刻み**で決まる。既定 40 段は、刻みが 0.5〜1.0 の
B-1/B-2 では 20〜40mm 歩けたが、**`bore_dia` は刻み 0.05mm なので 2.0mm しか
出られない**。3 サイズとも「40 段まで通った（打ち切り）」で終わり、その数字を
壁として書いていたら、本当の壁の **3.8〜6.4mm 手前**で止めるところだった。

`--steps` を足して 200 段（10mm）で歩き直した。段 1〜2 は速いので伸ばしても
数秒、段 3 は境界の周りだけなので増えない。**打ち切りの文面も「帯の端から
何 mm 外まで見たか」を書くように直した** ——「40 段」だけでは、読んだ人が
距離に翻訳できない。

### 壁が「数字」ではなく「関係」だった 2 本

| | 止めているもの | 相手が動くと |
|---|---|---|
| `bore_dia` 上 | `bore_dia` < `shank_dia` | シャンク径を細くすると壁も下がる |
| `bore_length` 上 | 窓が `_MIN_WINDOW_SPAN_MM` 残ること | **全長**を縮めると壁も同じだけ下がる |

`bore_length` の壁は 3 サイズとも **zb（ボアの始まり）＝ 6.2 / 6.2 / 6.4mm**
で揃った。長さではなく**始まりの位置**が決めているので、全長を帯の下限に
すると壁は 65.2 → 47.3 / 85.5 → 62.8 / 101.1 → 74.2mm へ動く（zb は動かない）。

**相手を間違えかけた。** 計画では「`window_length` を上げれば壁が動く」と
書いていたが、**動かなかった** —— 窓の後端は既に `zb − chamber_to_bore_mm` で
頭打ちなので、この向きでは窓長は相手にならない。Phase A で
`window_length` の死に帯を作っていたのと同じ頭打ちが、ここでは
**壁を全長だけの関数にしている**。

どちらも `hard_*` に入っているのは**安い掛け金**（テンプレート値から作った
静的な数字）で、成立条件は `outer_layout_error` / `cavity_layout_error` が
1 か所ずつ持つ。`chamber_to_bore_mm`（Phase A）と同じ形。

### 空洞は `min_wall` を守るのに、ボアの円柱は守らない

**同じ法則が片方にしか掛かっていなかった。** 空洞は `shell_limit` が
`ro − min_wall` に収めるのに、ボアは `_bore_solid` が素の円柱を引く。実測:

| ボア径（soprano、シャンク φ18.67） | 肉厚 | `params_error` | ビルド |
|---|---|---|---|
| φ14.80（帯の上端） | +1.94mm | None | ソリッド 1 個 / 11776mm3 |
| φ15.07 | **+1.80 ＝ `min_wall`** | None | ソリッド 1 個 / 11441mm3 |
| φ18.67 | **0.00 ＝ シャンクが消える** | None | ソリッド 1 個 / 6570mm3 |
| φ20.67 | −1.00 | None | ソリッド 1 個 / 4541mm3 |

**体積が 61% 落ちても「ソリッド 1 個」は 1 個のまま。** 掃引の段 3 は
「1 個か・体積 > 100mm3 か」しか見ないので、シャンクが丸ごと消えた形を
ok と言う ——**「ソリッドが 1 個できる」は壁の必要条件でしかない**の実例が
これで 2 つ目（1 つ目は Phase A の「通った」と「効いた」）。

線引きは 3 段にした:

| 肉厚 | どうする | どこ |
|---|---|---|
| ≤ 0 | 弾く（越えさせない） | `outer_layout_error` |
| 0 〜 `min_wall` | **注意カード**（形は指定どおり出るが刷れない） | `shank_warnings` |
| ≥ `min_wall` | 何も言わない | — |

**`min_wall` の側を壁にしなかった**のは、`min_wall` 自身がスライダだから ——
テンプレート値で `hard_max` を作ると、利用者が `min_wall` を下げても
スライダが古い値で止まる（黙ったクランプの作り方そのもの）。
注意は `618fc9e` の右パネルのカードに出る。

**ソプラノは帯の上端が既に危ない**: φ14.8 で肉厚 1.94mm ＝ `min_wall` 1.8 まで
0.14mm しかない。帯の中にいても、シャンク径を少し細くすれば注意が出る。

### 掃引器の目が壁に見えていた（B-0 の型の 2 回目）

`bore_length` の上で掃引器が止まった 58 / 78 / 95mm は、**モデルの成立条件では
なく `MIN_STATIONS`（20 枚）**。モデル自身が弾くのは 65.2 / 85.5 / 101.1mm で、
**6.5mm 外**にある。B-0 では「見る軸が足りない」で誤判定していたが、今度は
「退化の検出器を壁と読んだ」——**道具の眼鏡は測定値ではない**。

そして `bore_length ≤ 0`（ボアが部品の外から始まる）は逆に、**段 1〜2 が
−21mm まで素通りした**。ステーションは平然と返り、円柱が 1 ビットも削らない
ので体積は**増える**。−1.5 を割ると `Solid.make_cylinder` が
`Null TopoDS_Shape` を返してビルドが素の `ValueError` で落ちる ——
**割り算が潰れる型の 6 つ目**（今度は割り算ではなく高さ 0 の押し出し）。
成立条件を `cavity_layout_error` に書いたので、いまは `params_error` と
`cavity_stations` の両方が同じ理由を返す。

### 広げた先で下流が 1 つ壊れた —— NaN は JSON に乗らない

`bore_length` の壁を 1.0mm まで広げてブラウザで動かしたら、**`PUT` が 500** で
落ちた。原因は `tier1.in_tune_mm` が **NaN** になること:

- ボアがほとんど無いとコーク線が空洞の終端でクランプされ、**1mm 押しても音程が
  0.00 セントしか動かない**（実用域そのものが 3〜4mm に潰れる）
- 傾き 0 なので零点が出せず、`tuning_position` は `float("nan")` を返していた
- 実用域の両端でも目標音を挟まないので厳密解の側でも埋まらない
- NaN は `round()` を素通りし、FastAPI の JSON 化で
  `ValueError: Out of range float values are not JSON compliant` になる

**数字が無いことを NaN で表していた**のが誤り。いまは `None`
（`tuning_method` は `"unsolved"`）を返し、UI は「— 合う位置が無い」、
仕様書は「**無し**（1mm 押しても音程が動かない）」と書く。

Phase A の「広げると壊れる下流が 4 つあった」と**同じ型の 5 つ目**だが、
壊れ方が違う —— あちらは帯を代理変数として消費している場所、こちらは
**帯の外の値でしか踏まない経路**。掃引も OCCT ビルドも通っていて、
**壊れたのは API の境界**だった。だから回帰テストは 1 本ずつではなく
「**壁を持つ全パラメータ × 3 サイズで `simulate()` が
`json.dumps(allow_nan=False)` を通ること**」で押さえた。

### ついでに直した文面の腐り

`_MIN_WINDOW_SPAN_MM` の但し書きが「`window_end_z` は既に
`bore_start_z − 4.0` で頭打ち」のままだった。**その 4.0 は Phase A で
`chamber_to_bore_mm` になっている** —— 9/06 に警告文で直したのと同じ型が、
定数のコメントにもう 1 つ残っていた。

| `body_dia` | 18–34（3 サイズ共通の絶対レンジ） | **ボア径 −10.9 – 54.0**（2.9–54 / 4.9–54 / 6.1–54） | 下は**シャンク径そのもの**（関係）。上は 3 サイズとも 54.0mm でソリッド 1 個を確認 ＝ その先は未測定 |
| `shank_dia` | 14–28（同上） | **ボア径 −10.9 – 54.0**（同上） | 下は**ボア径**、上は**最大径**。両端とも関係 |
| `shank_length` | 0–30 | **0 – 46.5 / 59.5 / 70.0** | 上は踵が床に当たって形が凍る点の 1 目盛り内側。下の 0 は定義（負は形の意味を持たない） |
| `shoulder_ratio` | 0.02–0.45 | **0.02 – 2.030 / 1.905 / 1.785** | 同じ踵の床。下は広げない（負は段 3 でソリッドが割れ、−1 で 0 除算） |

### 壁が「数字」ではなく「関係」だった —— 5 本中 3 本

B-3 に続いて、外形でも壁の正体は関係だった。成立条件は
`profiles.outer_layout_error`（径 2 本）と `cavity_layout_error`（全長）が
1 か所ずつ持ち、`hard_*` は**安い掛け金**でしかない:

    ボア径 < シャンク径 ≤ 最大径          （径 2 本）
    全長 ≥ ボア長 + 6.5                    （全長。B-3 が測った関係の裏返し）

総当たりで測った「通る範囲」は 3 サイズとも端がぴったり相手の値になる ——
`body_dia` は 18.7 / 23.2 / 23.0 から（＝ シャンク径そのもの）、`shank_dia` は
ボア径 +0.1 から最大径まで。相手を動かすと壁も同じだけ動く。

### 帯の端が壁の外へはみ出していた（12 端のうち 6 端）

径 2 本の帯は 3 サイズ共通の**絶対レンジ**なので、既定の相手のままだと端に
立てない:

| | 帯 | 既定で通る範囲 | 死んでいる幅 |
|---|---|---|---|
| `body_dia` soprano | 18–34 | 18.7–（上限なし） | 下 0.7 |
| `body_dia` alto | 18–34 | 23.2– | **下 5.2**（帯の 32%） |
| `body_dia` tenor | 18–34 | 23.0– | **下 5.0** |
| `shank_dia` soprano | 14–28 | 13.9–25.0 | 上 3.0 |
| `shank_dia` alto | 14–28 | 15.9–29.1 | 下 1.9 |
| `shank_dia` tenor | 14–28 | 17.1–30.8 | **下 3.1** |

**これは帯の数字が下手なのではない。相手で動く壁を静的な帯で表せない**という
ことで、相手を一緒に動かせばどの端も届く。だから帯は動かさず、`hard_*` を
入れて「黙って丸める」のをやめた —— 端に置いた値はクランプされず、通らない
ときは相手の名前を挙げて 400 で断る。

ただし**下限の数字そのものは出所が消えていた**。18.0 / 14.0 は `f1e79e8`
（2026-08-11）で 20.0 / 16.0 から下げたもので、理由は
「ソプラノ実測 全長 71.4 / シャンク径 15.3 / シャンク長 6.4 が入る位置」。
**その 15.3 はもう存在しない** —— 旧軸スケール 0.664 の導出値で、
`soprano.json` の note 自身が「径を 0.664 で縮めるとシャンクの肉厚が 0.74mm に
なって `min_wall` を割る」と否定している（現行 18.67 はボア比 0.8118 の導出値）。
**理由の消えた追従**（`cad/windycity/README.md` の「band_width 15.3 への追従は
理由が消えたので戻した」と同じ型）で、`src` から落とした。

### 黙ったクランプ 8 例目 —— 踵の床

`heel_z` は `max(heel_raw, 0.30·全長)` で床を持っていた。掃引は
`shank_length` を **110mm まで**、`shoulder_ratio` を **2.45 まで**素通りさせ、
段 1〜3 が全部 ok を返す。ところが床に当たった先では:

| | 床に当たる点（soprano / alto / tenor） | 床から先で起きること |
|---|---|---|
| `shank_length` | 47.0 / 60.4 / 70.8mm | 踵も肩の長さも凍る ＝ **外形が 1 ビットも動かない**（掃引の応答 0%） |
| `shoulder_ratio` | 2.036 / 1.911 / 1.791 | 踵は凍るが肩の長さ（比 × 踵）は伸び続けるので**母線は変わる** |

**2 本で凍り方が違うのが厄介だった。** `shank_length` は掃引の死に帯検出に
そのまま引っかかる（応答 0%）が、`shoulder_ratio` は 22〜54% の応答を返し続ける
ので**検出器には見えない**。それでも踵が式どおり動かなくなった時点で
「最大径位置に対する比」という**この量の意味が成り立たない**（寸法図と仕様書は
与えた数字を印字し続けるので、図と形が食い違う）。だから壁はそこに置いた ——
**死に帯の規則ではなく、量の定義が壊れる点で決めた**のはこのスライスが初めて。

**この 2 本の壁も互いに関係**だった（ブラウザで踏んだ）。床は 2 本の組で
決まるので、`hard_max` は「相手がテンプレート値のとき」の値でしかなく、
**両方を壁へ置くと 400 で断られる** —— 径 2 本とまったく同じ形。掛け金が
静的な数字である以上こうなるので、断るときに理由が出ることだけを担保する。

床そのものは `profiles.HEEL_FLOOR_RATIO` に名前を付け、
`shank_length_at_heel_floor` / `shoulder_ratio_at_heel_floor` が当たる点を返す。
`hard_max` はその 1 目盛り内側（浮動小数の丸めで `outer_layout_error` と
食い違わないように。`chamber_to_bore_mm` の下限 0.5 と同じ寄せ方）。
**0.30 を書き写さない**のが肝で、写すと片方だけ直る代理変数になる。

### 割り算が潰れる型の 7 つ目 —— 肩比 −1

`shoulder_ratio` を下へ歩くと、−0.99 では段 1〜2 が素通りして**段 3 で
ソリッドが 2〜3 個**に割れ、**−1 ちょうどで素の `ZeroDivisionError`** が出た
（踵 `(全長 − シャンク長)/(1 + 肩比)` の分母）。帯の下限 0.02 があるので UI
からは届かないが、出所の分からない例外が上がるのがいちばん悪いので
`heel_raw` が `-inf` を返し `outer_layout_error` が理由を言う形にした。
**下限は広げない** ——負の肩比は形の意味を持たない。

### 掃引器の目が壁に見えていた（B-3 §3 と同じ、また 6.5mm）

`overall_length` の下は 51.5 / 61.5 / 70.5mm で止まるが、これは
`sweep_limits.MIN_STATIONS`（20 枚）＝ 退化の検出器であって成立条件ではない。
モデル自身の床は **44.6 / 54.6 / 64.0mm** で、**6.5〜6.9mm 外**にある。
B-3 で `bore_length` の上について測った差と**同じ 6.5mm** で、これは偶然では
なく同じ関係（窓が 2.0mm 残ること）を別の変数から見ているため ——
B-3 の「ボア長 ≤ 全長 − 6.5」の裏返しが「全長 ≥ ボア長 + 6.5」。

### 掃引器に足したもの 3 つ（測る前に塞いだ）

1. **注意の数え方**。`_build_around` が `pf.cavity_warnings` を直に数えていて、
   B-3 で増えた `shank_warnings` を落としていた。`comp.warnings` に変更 ——
   **注意の集約点は部品側 1 か所**（`registry.Component.warnings`）。
   `shank_dia` を下げる掃引でまさに出る注意なので、直さずに測ると嘘になった。
2. **「効いていない」と「壁がある」の取り違え**。`_walk` が形の動かないまま
   終わると、初版は理由（`why`）を捨てて「この向きでは効いていない」と書いた。
   `body_dia` を下へ掃くと 1 段目で「最大径がシャンク径より細い」が返るのに、
   **ログに壁が 1 文字も残らなかった**。起点のままかどうかで 2 つに分けた。
3. **帯の端そのものを試す**。`_walk` は端を起点に外へ歩くだけなので、端が
   既に弾かれていても「1 段外で壁」としか言えない。上の 6 端がこれ。

3 つとも**道具が測った理由を捨てていた**型で、B-0（軸が足りない）とは違う。

### 上の壁は 2 本とも「打ち切り」

`body_dia` は段 1〜2 なら 400mm まで、`overall_length` は 300mm まで通る。
段 3（OCCT）で確認したのは `body_dia` 54.0mm と `overall_length` の 149 /
174.5 / 194.5mm で、`hard_max` はそこに合わせた ＝ **壁を測ったのではなく、
確認した範囲を書いている**。`overall_length` は 3 サイズとも実測が届いている
1.8 倍を採った。

上向きの `overall_length` は**軸によって食い違う**（空洞 3 軸 0〜1% に対し
`beak_y` 95〜141%）。これは物差しの側 ——`_grids` が既定のボア始まりまでしか
無く、全長を伸ばすと空洞がグリッドの外へ出る。**効いていないのではない。**

### このスライスで一番大きいこと —— 掃引器の 3 段が 3 本とも素通りした

### 主張は 1 つ「母線は単調」、でも壊れ方は 4 通りで、どの目も何かを見落とす

胴は最大径に向かって太る一方、肩はシャンクへ細る一方 ——`ligature_seat_range`
と `outer_radius_nominal` がこれに乗っている。だが 1 つの主張が破れる**見え方**が
4 つあり、**目を 1 つ作っただけでは足りなかった**:

| 目（`profiles`） | 何を見る | 捕まる | 見落とす |
|---|---|---|---|
| `outer_apex` | 最大半径の z | `body_waist` 上 | 他の 3 つ |
| `body_dip` | 胴が太るのをやめる点 | `body_waist` **両側** | 肩の 2 つ |
| `shoulder_dip` | 肩の最小半径 | `shoulder_fullness` 下 | 他の 3 つ |
| `shoulder_bulge` | 肩が細るのをやめる点 | `shoulder_fullness` **両側** | 胴の 2 つ |

**肩比 +1.85〜+1.88 で 4 行とも何も鳴らなかった**（肩は膨らむが最大径は超えず、
シャンク径も割らない）。単調性そのものを見る 2 つ（`body_dip` /
`shoulder_bulge`）が主で、他の 2 つはその**症状**でしかない。

### 道具が「式」を測っていて「形」を測っていなかった（同じ日に 2 か所）

B-4a で出た「道具が測った理由を捨てる」型とは別。**測る対象を取り違えている**:

1. **`sweep_outer.py` の主張 (1)** が `pf.heel_z` を比べていた。`heel_z` は
   (全長 − シャンク長)/(1 + 肩比) という**軸方向の式**なので、`body_waist` /
   `shoulder_fullness` では定義上動かない ——いちばん頂点を壊す 2 本に対して
   構造的に無力で、`body_waist=max` を毎回通していた。`outer_apex` へ差し替え、
   `body_dip` / `shoulder_bulge` / `shoulder_dip` も足した。
2. **その主張の輪が `params_error` に弾かれた組も回していた。** `_cases` は
   わざと成立しない組（`body_dia=min` など）も踏むので、そこで「頂点が動いた」と
   言っても当たり前。ビルド側は既に `continue` していたのに、主張側は全件を
   回していた ——**旧 `heel_z` の目ではそれらが動かなかったので露見しなかった。**
3. **`sweep_limits.py` の `beak_y` 軸**が `pf.beak_y`（解析式の稜線）を測って
   いた。稜線が胴の外へ出ても線形に伸び続けるので、`beak_height` を既定の
   4 倍まで上げても「100% 生きている」と報告する。部品の上面は
   `min(稜線, 外半径)` なので `min` を掛けた。応答が **100% → 41〜48%** に。

3 は指紋を変えるので、**過去の掃引と比較できるかを確かめてから**入れた ——
既定では稜線が胴の内側にあるので頭打ちは効かないはずで、`beak_y` が本命だった
`tip_opening` を回し直したら上向きの行が `b0-remeasure.txt` と**バイト一致**した。

### 帯が壁を跨いでいた 2 本 —— 今度は帯の欠陥

B-4a でも「帯の端が壁の外へはみ出す」が出たが、あちらは**相手で動く壁**が原因で
帯の欠陥ではなかった。B-4b の 2 本は**相手がいない**（形の正規化量、または
テンプレート値だけで決まる）ので、静的な帯で正しく表せる ＝ **表していないのは
端的に欠陥**。だから帯を詰めた:

- `shoulder_fullness` の下端 **−1.0**。肩の中ほど（s≈0.73）がシャンク径を
  0.26〜0.34mm 下回る「えぐれ」で、しかも**えぐれは必ずボアの上に来る** ——
  `shank_warnings` が言う肉厚（シャンク径 − ボア径）が最薄でなくなり、
  **注意の数字そのものが甘くなる**。旧 `src` の「パラメータの定義域そのもの」は
  **両側とも定義域ではなかった**。
- `beak_height` の上端 **0.75·`body_dia`**（下記）。

どちらも内側に置ける目印が無い（`shoulder_fullness` の負側に「+1 ＝ 円錐」に
当たる landmark は無い）ので、**帯の端を壁と同じにした。margin を発明しない。**

### `beak_height` の「胴の全高 0.9·`body_dia`」は外れていた

旧コメントは「胴の全高 0.9·body_dia を超える値が形状として意味を持たない
（ビーク面が本体の外に出る）」と書いていた。実測すると:

| | バイトポイントでの胴の全高 | `body_dia` 比 | 旧レンジ上端 0.75·`body_dia` |
|---|---|---|---|
| soprano | 18.07mm | 0.723 | 18.8 ＝ **壁の外** |
| alto | 21.37mm | 0.734 | 21.8 ＝ **壁の外** |
| tenor | 22.97mm | 0.746 | 23.1 ＝ **壁の外** |

**比は一定ですらない** ——バイトポイントは全長の 1/4 で、そこの胴の太さは
踵までの比で決まるため。だから 0.9 でも 0.75 でも、**単一の数字では書けない**。
いまは `profiles.beak_height_at_body_top` が引く。

そしてこの壁は**また「関係」**（B-3・B-4a で 5 本出たのと同じ型で、通算 8 本目）
——`body_dia`・全長・テーブル角・ティップ開き・ティップレール厚で動く
（`body_dia` を +6mm すると上の壁が +3.5mm 動く）。だから `hard_*` は
テンプレート値での**掛け金**で、成立条件は `outer_layout_error` の条件 (6) が
1 か所で持つ。B-4b の 3 本のうち、**相手のいない純粋な数字の壁は
`body_waist` と `shoulder_fullness` だけ**だった。

下端も同じ形で、`beak_height_flat`（稜線が前下がりになる点。4.26 / 5.23 / 5.86）の
1 段上。**掃引器の「−21.2mm まで通る」を割れる点と読むと嘘になる** ——あれは
段 1〜2 の打ち切りで、段 3 をそこでしか回していないだけ。0.5mm 刻みで挟むと
実際は 0.5mm だった（B-3 の「打ち切りは壁ではない」が、今度は**壁ではなく
「壊れる点」の側で**出た）。**どちらも「壊れる点」ではない** ——OCCT が割れるのは
3 サイズとも `beak_height` = 0.5mm（直前の 1.0mm はまだ 1 個） で、壁のずっと外。決めているのは**量の定義が壊れる**ことで、
B-4a の `shoulder_ratio`（死に帯ではなく定義が壊れる点で壁を決めた）に続く 2 例目。

### 壁の値はどこにも書いていない

`body_waist` / `shoulder_fullness` の限界は `r/r_max` に正規化した形の性質なので
**3 サイズ共通・他のパラメータに依らない**。`profiles.body_waist_limits()` /
`shoulder_fullness_limits()` が `_BODY_PROFILE` / `_SHOULDER_PROFILE` から
**閉じた式で解く**（母線の微分の符号で上下に割れる）ので、実測表を差し替えたら
壁も一緒に動く。`beak_height` も同じくテンプレートから引く。

止める場所は 2 段構え ——**B-4a の踵の床と同じ組み方**:

- `ParamSpec.hard_*` が**スライダの刻みへ丸めた**値で止める（`mouthpiece._inside`）
- `profiles.outer_layout_error` の条件 (4)(5) が**真の交差**で断る

刻みに乗らない経路（プロジェクトファイル、直に組んだ dict、掃引器）は前者を
すり抜けるので後者が要る。どちらも数字を持たず同じ `*_limits()` を呼ぶので、
置き場所が 2 つでもずれない。

### 代理変数の 6 例目 —— 「可動域」と言いながら帯を読んでいた

`cad/inspection/inspection_values.py` の「ビーク高さの下限」探索が
`sb.min, sb.max` を可動域として二分していた。`beak_height` に壁が付いた今は
下側を 4.3〜5.9mm 取りこぼす。`sb.bounds()` へ。Phase A で 4 か所直したのと
同じ型で、**壁を足すたびに増える**（`min`/`max` を可動域の代理として読む）。
