# 壁と帯 — 設計許容範囲をどう決めているか

Phase 4-E。**「勧める帯」と「越えられない壁」を分けて、壁の出所を書く。**

## なぜ

印刷品を吹いた利用者の見立て:

> 世の中にある素晴らしいマウスピースの設計は理論だけでは説明がつかない可能性が
> 高い。ある程度の理論に基づき設計・試作・試奏し、奏者の感覚的な評価から最終
> 設計が決定される。……そのベースの上でユーザーのアイデアによる想定（理論）外の
> 変更箇所が音質や音程によい影響を及ぼすこともあるのではないか。

理論が出したベース形状の上で「想定外の値」を試せるべき、という話。
ところが着手前の可動域には 3 つ問題があった。

1. **黙っている。** `ParamSpec.validate` は範囲外を無言でクランプし、
   フロントは差分を拾って値を戻すだけだった。利用者にはスライダが勝手に
   戻ったようにしか見えない（この repo で数えて **8 例目**の黙ったクランプ）。
2. **出所が書かれていない。** 実測由来の壁（`body_dia` の下限＝ソプラノ実測）と、
   誰も測っていない暫定値（`beak_height` の既定は自認で「幾何的な暫定値」）と、
   幾何の定義域（`shoulder_fullness` の ±1）が、コード上まったく同じ顔をしていた。
3. **本当の壁の位置を誰も測っていなかった。** これが一番大きい ——
   下の「掃引で分かったこと」がその証拠。

## 仕組み

`ParamSpec`（`saxsketch/core/schema.py`）に 4 つ増やした。

| フィールド | 意味 |
|---|---|
| `min` / `max` | **勧める帯**。UI ではトラックの網掛け。越えられる |
| `hard_min` / `hard_max` | **越えられない壁**。`None` なら帯がそのまま壁 |
| `limit_kind` | `geometry` / `manufacturing` / `convention` / `unclassified` |
| `source` | 帯の出所。**空なら「出所の記載なし」と表示する** |

規則は 2 行:

- **クランプ先は `hard_*`。無ければ `min`/`max`。**
  `hard_*` を 1 つも入れなければ**現行と完全に同じ**挙動になる。
- **`limit_kind` は説明のラベルで、硬さは決めない。** 1 本のパラメータでも
  下限が幾何・上限が慣習ということがある（`shank_length` の 0 と 30.0）ので、
  緩めるのは片側ずつ `hard_min` / `hard_max` で行う。

丸めたときは `ParamSet.adjustments` に**値・単位・壁の種別・出所**を積み、
`PUT /api/project/params` の `adjustments` で画面まで届く:

> ⚠ 最小肉厚 0.2 → 1.2 mm に丸めました（製造の制約の下限、出所: 3D プリントの
> 強度下限（レジン 2mm 以上推奨））

## 掃引器

`cad/windycity/sweep_limits.py`。帯の端から外へ 1 段ずつ歩き、3 段で判定する:

1. `comp.params_error(p)` が `None`
2. `profiles.cavity_stations(p)` が例外を出さず、枚数と先端高さが退化しない
3. **OCCT ビルドがソリッド 1 個**（`is_valid` は当てにしない。体積も見る）

1〜2 は速いので端から端まで、3 は境界の周りだけ（1 点 4.5〜7 秒）。

**「通った」と「効いた」は別物。** 各点で形の指紋（ステーション枚数・先端高さ・
最大高さ・窓の後端・ボアの始まり）を取り、**動いていなければそう言う**。
これが無いと死に帯を「壁が無い」と読み違える —— 実際 `chamber_to_bore_mm` は
既定の `window_length` では**負にしても何も起きない**（`min()` の反対側が勝つ）
ので、最初の掃引は「−18mm まで通る」という嘘の結論を出していた。

## 掃引で分かったこと（Phase A・2026-09-05）

### 広げた 4 本

「入れた壁」は `hard_min`/`hard_max` に実際に書いた値で、**測った位置そのもの
とは限らない** —— 落ちる点ちょうどではなくスライダの 1 段手前で止めたり
（`chamber_to_bore_mm` の下は落ちる点が 0 で、入れたのは 0.5）、応答が死ぬ手前で
止めたり（`baffle_height`）する。差がある行は「何が壁か」に書いてある。

| パラメータ | 帯 | 入れた壁 | 何が壁か |
|---|---|---|---|
| `tip_opening` | 1.0–3.2mm | **0.05 – 5.2** | 下は 0 でちょうど落ちる（`ZeroDivisionError`）。上は 5.2 まで確認して打ち切り＝**それより外は未測定**。応答は tenor 101% / alto 82% で一定、**soprano だけ 7%** ＝ 死に帯の線引き 5% のすぐ上（膝が無いので広げたが、ぎりぎり） |
| `baffle_height` | 0.0–5.0mm | **−2.3 – （広げない）** | 上は **5.0 から先が死に帯**（天井が外殻で頭打ち）。負は天井を基準より上げる向き。ソリッドは −4.0 でも通るが **alto はそこで応答 4%**（soprano 23% / tenor 37%）。効くのは −2.3 までなので、縛るサイズに合わせた |
| `window_length` | 24.0–44.0mm | **4.0 – （広げない）** | 上は soprano / alto が **44 から先が死に帯**（tenor だけ 46 手前まで生きる）。頭打ちの相手は `chamber_to_bore_mm` |
| `chamber_to_bore_mm`（新設） | 2.0–10.0mm | **0.5 – 30.0** | 下は **3 サイズともぴったり 0**。上は 30.0 まで確認、その先は `cavity_layout_error` |

「広げない」と書いた 2 つは**壁が無いのに広げなかった**のではない ——
**壁ではなく死に帯**だったので、広げても嘘のつまみが増えるだけ。

### 「ソリッドが通る」だけでは決められなかった

`baffle_height` は当初 **−4.0** で入れた（3 サイズともソリッド 1 個）。
その後**固定グリッド**（ステーション数に依らない σ 等分）で空洞の平均高さの
応答を測ったら、**alto はそこで帯の端の 4%** しか動いていなかった。
効くのは **−2.3mm まで**。soprano 23% / tenor 37% はまだ生きているが、
**縛るサイズに合わせて −2.3 にした**。

線引きは「帯の端での傾きの 5% を割ったら死に帯」。この基準で 4 本すべてを
測り直した結果:

| | 帯の端の傾きに対する、壁での傾き | 判定 |
|---|---|---|
| `tip_opening` 上 | tenor 101% ／ alto 82% ／ soprano **7%** | 生きている（**ぎりぎり**。膝は無い） |
| `window_length` 下 | soprano 139% ／ alto 114% ／ tenor 110% | 生きている |
| `chamber_to_bore_mm` 上 | soprano 140% ／ alto 108% ／ tenor 101% | 生きている |
| `baffle_height` 下 | soprano 23% ／ tenor 37% ／ **alto 4%** | **死に帯 → −2.3 で止めた** |

（`chamber_to_bore_mm` の下側はこの表に入れていない。窓を上限まで伸ばして
拘束を効かせても **tenor では最初から効かない**ので、3 サイズを並べた比較に
ならない ——`zb` が大きいぶん窓の長さのほうが先に頭打ちになる。）

**「ソリッドが 1 個できる」は壁の条件であって、つまみが効く条件ではない。**
掃引器の形の指紋はステーション数が変わると跳ねるので、この判定には固定
グリッドを使う。判定と「効くのはどこまでか」の探索は掃引器に入れてあるので、
Phase B では同じ 1 コマンドで出る。

判定を足したら**もう 1 つ穴が見つかった**: `tip_opening` を 0 に寄せると天井と
床がどちらも発散して傾きが 1e18 になるのに、**`cavity_stations` は通る** ——
段 1〜2 を抜けたからといって量が測れているとは限らない。掃引器の側で
非有限と桁外れを弾くようにした（`MAX_SANE_SLOPE`）。

### `zb − 4.0` は幾何の壁ではなく、バグを覆う蓋だった

`window_end_z` の直値 4.0 は「チェンバー→ボアの遷移を残す」慣習に見えていたが、
**すぐ裏に退化が 2 つ並んでいた**。

1 つ目は `5fb0bf4` で直した `cavity_floor_y` の振幅アフィン（`a = target/(D(1) −
D(s_we))` が s_we → 1 で発散。`docs/print-inspection.md` §11.11）。

2 つ目は `_floor_limit`。制御点を `(0,0) (s_we,0) (min(s_we+0.06,1),1) (1,1)` と
組んでいたので、**`s_we ≥ 0.94` で第 3・第 4 節点が x=1.0 で衝突**して
`_pchip_table` が `ZeroDivisionError`。閾値は `gap ≤ 0.06·zb` ＝ サイズで変わる:

| | zb | 落ちる gap | 当時の壁 4.0mm からの余裕 |
|---|---|---|---|
| soprano | 33.10 | ≤ 1.99mm | 2.01mm |
| alto | 43.40 | ≤ 2.60mm | 1.40mm |
| tenor | 50.00 | ≤ 3.00mm | **1.00mm** |

**アルトの既定 `s_we` は 0.9078 ＝ 落ちるまで 0.033。** 直しは 2 つ ——
ランプが必ず収まるよう `s_we` を頭打ちにし、ランプの終わりが 1.0 に達したら
末尾の節点を置かない。既定 3 サイズの `s_we` は 0.8408 / 0.9078 / 0.8380 なので
頭打ちは効かず、**3 サイズとも形状・音響がビット一致**（`h[0]` / `hmax` /
ステーション数 / 実効容積 / `in_tune_mm` / Tier2 まで）。

### 蓋を外したら 3 つ目が出た

`chamber_to_bore_mm` を 0 まで下げると、今度は `_chamber_weight` の制御点が
x=1.0 で重なる（`s_we = s_th = 1` ＝ チェンバーの長さが 0）。**同じ型の 3 つ目。**

そこで `_pchip_table` に**重複 x を名指しで弾くガード**を入れた。
`profiles.py` には `s_we` / `s_th` / `s_ch` から動的に組む表が **6 か所**あり、
どれも設計値の組み合わせ次第で退化しうる。`ZeroDivisionError` がリスト内包の
奥から出るのではなく、どの表のどの点が重なったかを言う:

```
ValueError: PCHIP の制御点 x が単調増加ではありません:
pts[1]=(1.0, 0.0) と pts[2]=(1.0, 1.0) で x が 1.0 → 1.0（幅 0.0）。表全体: [...]
```

**このガードが 3 つ目を見つけた。** 併せて `cavity_layout_error` にも
「遷移は長さを持たなければならない」を書いて、例外ではなく理由で弾くようにした。

## 広げると壊れる下流が 4 つあった

`min`/`max` は**スキーマ以外の 4 か所でも消費されていた**。どれも「帯 ＝ 越え
られない値」を前提にしていたので、壁を広げた時点で意味が変わる。

| 場所 | 帯のままだと | どうしたか |
|---|---|---|
| 断面タブのハンドル（`baffle_handles`） | スライダは壁まで動くのにハンドルは帯で止まる ＝ **同じパラメータが 2 つの UI で違うところまでしか動かない** | スキーマの可動域を渡すようにした。`baffle_handles` は 0.0/5.0 などを直に書いていて、`_handle_ranges` のコメント自身が警告していた二重化 |
| 感度表（`brightness.sensitivity`） | 帯の外にいる利用者では 1 段が「+0.05」ではなく「−0.8」になり、**感度の符号ごと壊れる** | 止める先を `ParamSpec.bounds()` に |
| ゴールシーク（`goalseek`） | 利用者が帯の外に置いた値を**黙って帯の中へ引き戻す** | 探索は帯の中のまま（理論側の提案が慣習の外へ出るのは筋が違う）。ただし**現在値が外にあるならそこを含める** |
| 採寸フォーム（`survey_targets`） | 実物の実測が帯の外だと**測った値が別物にすり替わる**（`body_dia` の下限を下げた経緯そのもの） | 壁で受ける |

### Tier2 は広げない。ただし黙らせない

音色レーダー（`brightness.tone_metrics`）の正規化域は帯とほぼ同じ数値だが、
**意味が違う** —— こちらは回帰を当てた範囲で、外挿する根拠が無い。だから
広げず、**指標は帯の端で頭打ちになる**。

問題は「スライダを動かしてもレーダーが動かない」がこの repo で何度も踏んで
いる型（効いていないのに気づけない）だということ。そこで有効範囲を
`_MODEL_RANGE` として括り出し、**外に出ている入力を `note` に並べる**:

> …**ティップ開き 4mm（有効範囲 1〜3.2mm） がモデルの有効範囲の外にあります。**
> この指標はそこで頭打ちになっていて、動かしても変わりません（回帰を当てた
> 範囲の外なので外挿していません）。形そのものは変わっているので、断面タブと
> 寸法を見てください。

## 分類の結果（マウスピース 33 個）

| 種別 | 数 | 例 |
|---|---|---|
| `convention` | 28 | ほとんど。市販品や実測品がその辺りにあるというだけ |
| `geometry` | 3 | `tip_chamfer`（0 ＝ 面取りなし）、`baffle_curvature` / `shoulder_fullness`（±1 が定義域） |
| `manufacturing` | 2 | `min_wall`、`material` |
| `unclassified` | 0 | 残していない |

**分類したのはマウスピースだけ。** リード・リガチャー・ネック・管体は
`unclassified` のままで、挙動も現行どおり（`hard_*` が無いので帯がそのまま壁）。

**出所が空のものが 10 個ある**（`tip_opening` / `facing_length` / `facing_curve` /
`tip_rail_width` / `tip_rail_thickness` / `side_rail_width` / `baffle_type` /
`rollover_radius` / `chamber_shape` / `material`）。UI には「出所の記載なし」と
出る。**空欄を埋めるために出所を発明しない** —— 記載が無いことも情報。

## この次（Phase B）

同じ掃引器で**残り 25 本の数値パラメータ全部**に `hard_*` を埋める。
OCCT ビルドが 1 点 5〜7 秒なので、カテゴリ単位で 4 スライスに割る:

| スライス | 対象 | 本数 |
|---|---|---|
| B-1 | フェイシング（`facing_length` / `tip_rail_width` / `tip_rail_thickness` / `tip_chamfer` / `side_rail_width` / `table_angle`） | 6 |
| B-2 | バッフル ＋ チェンバー（`baffle_plateau` / `baffle_step_rise` / `baffle_curvature` / `rollover_radius` / `throat_ratio` / `chamber_ratio`） | 6 |
| B-3 | ボア ＋ ウィンドウ（`bore_dia` / `bore_length` / `cork_depth` / `reed_width`） | 4 |
| B-4 | 外形 ＋ 製造（`beak_height` / `body_dia` / `shank_dia` / `shank_length` / `shoulder_ratio` / `body_waist` / `shoulder_fullness` / `overall_length` / `min_wall`） | 9 |

完了条件は毎回同じ ——**掃引の生ログを残し、`hard_*` の根拠を「掃引でここまで
通った」という測定として書く**。新しい退化が出たら（Phase A で 2 つ出た）
そこで直す。`min_wall` は印刷の壁なので、掃引で決めるのは**幾何の壁だけ**。
